# Поведение

Вторая половина системы. Она управляет компонентами, суть которых — взаимодействие: слайдер,
таблица, датапикер, автокомплит, оверлей, виртуальный скролл, — там, где визуальной спеке
нечего сказать. Это не исключения из системы: они подчиняются этой главе вместо
[axes.md](axes.md).

## Три слоя

```
математика / машина состояний    чистые функции над значениями, без DOM
        ↓
control-композабл                DOM, события, ARIA — возвращает бэги атрибутов
        ↓
презентация                      компонент (или разметка потребителя) с v-bind
```

Эталон:
[`composables/slider/useSliderControl.ts`](../../../src/runtime/composables/slider/useSliderControl.ts)
стоит между `createSlider.ts` (чистая математика значений) и
[`components/ui/slider/index.vue`](../../../src/runtime/components/ui/slider/index.vue),
который потерял ~120 строк DOM-логики и теперь консьюмит те же бэги, что и любая сторонняя
разметка.

## Контракт escape hatch

> Сотри тег компонента, оставь `v-bind` плюс хук — поведение цело.

Это публичное обещание кита, поэтому оно должно быть истинно по построению, а не за счёт
дублирования. Один кодовый путь: поставляемый компонент — **потребитель** композабла, а не
привилегированный клиент. Если компонент знает что-то, чего бэги не отдают, демка может
соврать — и рано или поздно соврёт.

### Именование

| Форма | Когда |
|---|---|
| `rootAttrs`, `trackAttrs`, `rangeAttrs` | По одному бэгу на структурную часть, раздаётся через `v-bind`. |
| `getThumbAttrs(index)` | Геттер, когда часть повторяется. |
| `UseXControlReturn` | Публичный тип возврата объявляется явно. Выведенные типы валят `mkdist` с TS7056 — это ограничение сборки, а не стилевое предпочтение. |

### Композабл не отдаёт ни классов, ни `data-*`

Презентация целиком принадлежит потребителю. Композабл, из которого утекает имя класса или
`data-*`-атрибут, уже решил, как выглядит разметка, — то есть сделал ровно то, чего escape
hatch обещает не делать. Это проверяемо и проверяется: у каждого control-композабла есть
спека, которая монтирует его бэги на анонимную разметку и утверждает, что ни `class`, ни
ключа на `data-` в выхлопе нет.

Композабл владеет **связями** — `for` / `id`, `aria-describedby`, `aria-controls`, — потому
что это поведение, а не оформление. Компонент владеет всеми классами, включая модификаторы
состояний, и выражает их **BEM-модификаторами, а не `data-*`**: `data-*`-атрибут читается как
поверхность API, и потребители начнут по нему селектиться.

> `useSliderControl` раньше отдавал `data-orientation` / `data-state` / `data-disabled` /
> `data-readonly` — тот случай, против которого правило и написано. Они удалены (sweep run 2,
> W5-А): бэги несут только роли, `aria-*`, обработчики и геометрию; корневой бэг диапазона —
> `role="group"`.

Геометрия, нужная CSS, едет тем же путём — кастомными свойствами внутри бэга
(`--m-slider-percent`, `--m-slider-progress`). Это единственное санкционированное применение
рантайм-кастом-свойств: они несут **живые измерения**, а не значения темы. Цвет и состояния
компонента остаются билд-тайм-Sass — см. [architecture.md](../../architecture.md).

## Правила

- **Позиционирование принадлежит части, а не вызывающему.** `left: N%` плюс
  `transform: translate(-50%, -50%)` лучше, чем `left: calc(N% - 24rem)`: второе запекает
  размер части в арифметику родителя.
- **Никакого `onMounted` для начальных данных.** `useFetch` / `useAsyncData`. `onMounted` —
  только для браузерных Web API.
- **Каждый слушатель и таймер снимается.** Предпочитай `useEventListener` из VueUse, иначе —
  `onBeforeUnmount`.
- **Кэшируй измерения, инвалидируй по scroll и resize, троттли через rAF.** Обработчик
  указателя, зовущий `getBoundingClientRect` на каждое движение, — баг, ждущий длинного
  списка.
- **SSR — часть контракта.** Серверный HTML обязан уже нести `role`, `tabindex`, `aria-*` и
  позицию покоя; callback-рефы не должны утекать в разметку. Это тестируется.
- **Один контроллер на паттерн взаимодействия.** Два независимых клавиатурных контроллера на
  один паттерн (`useSliderControl` и `createRangeKeyboardController`) — известное
  сознательное дублирование; третий молча не добавляем.

## Доступность — тоже ось поведения

Роли ARIA и клавиатурные карты решаются в композабле, один раз, и наследуются каждым его
потребителем. Базовая клавиатура для range-подобного контрола: стрелки, Page, Home, End и
Shift для шага ×10.

Где работу может сделать нативный элемент — её делает он. `<MOtpInput>` рисует N ячеек над
**одним** настоящим `<input maxlength=N autocomplete="one-time-code">`: вставка,
автоподстановка из SMS, backspace через границу ячейки и озвучка скринридером достаются
бесплатно, тогда как N отдельных инпутов означали бы войну с браузером за каждое из этого.

Форма получает значения, а не заголовки. `<MDropdown>` и `<MAutocomplete>` отправляют по одному
`<input type="hidden">` на выбранное значение под `name` (целый элемент — его `id`), как
`<select multiple>`; видимый инпут с заголовком не отправляет ничего. Пикеры даты и времени так же
отправляют `YYYY-MM-DD` и `HH:mm`. Разделители во вставленном одноразовом коде не попадают в
`invalid`: «123-456» из SMS — не ошибка.

## Оверлеи и обратная связь

- **Фокус встаёт на поверхность, а не на первый контрол.** Модальное окно (`<MDialog>`,
  `<MSheet>`, `<MOverlay>` с ловушкой) при открытии фокусирует себя; контент, которому нужен
  фокус, говорит об этом `autofocus`. При закрытии фокус возвращается туда, где был.
- **Меню — это меню.** `<MMenu>` всегда открывается у якоря (`placement`, логические `start` /
  `end`, в RTL зеркалятся). Стрелки по кругу, Home / End — в концы, буква — typeahead, Escape
  закрывает и возвращает фокус; Tab закрывает и уходит дальше от триггера, как будто меню стоит
  в DOM сразу за ним. Отключённый пункт остаётся в порядке стрелок как `aria-disabled`. Не-меню
  (listbox, цветовой пикер) живёт в приватной всплывающей панели без роли меню. Пункты —
  `<MMenuItem>` и `<MMenuGroup>`; своя разметка пункта берёт `getItemAttrs()` из `useMenuControl`.
- **Модальное окно отвечает.** Слоты `<MDialog>` / `<MSheet>` получают `{ confirm, cancel, close }`;
  `confirm(payload)` эмитит `confirm`, `cancel()` и закрытие пользователем (scrim, Escape, свайп) —
  `cancel(reason)`, а `close()` и `v-model` родителя ответа не дают. `useModal().open()`
  резолвит `{ status: 'confirmed', value }` (falsy-payload сохраняется) или `{ status: 'cancelled',
  reason }` (`cancel`, `outside`, `escape`, `swipe`, `programmatic`, `parent-closed`).
  `$material.modal.confirm()` / `.alert()` строят `alertdialog` из подписей вызывающего.
- **Объявления — через постоянный регион.** Регион, смонтированный вместе с текстом, озвучивается
  ненадёжно. Хост оверлеев и каждое открытое модальное окно держат пару `role="status"` /
  `role="alert"`; `<MSnackbar>`, `<MAlert>` и `<MBanner>` пишут сообщение в пару своего слоя (у
  слоя без неё — в свою) и сами live-регионами не являются. `announce="off"` — для контента,
  который уже в серверном HTML.
- **Тултип описывает с самого начала.** Его поверхность в документе с монтирования; триггер берёт
  `aria-describedby` из `props` слота по умолчанию (или, если их не взяли, на первый фокусируемый
  элемент). Показ — на наведение и на фокус с клавиатуры, не на клик; на таче — долгое нажатие.
- **Закрытый блок не роняет фокус.** Закрытие `<MAlert>` / `<MBanner>` изнутри переводит фокус на
  то, что идёт после блока, иначе на ближайший заголовок перед ним (`return-focus="false"`
  оставляет это вызывающему).
- **`<MBanner layout="auto">` следует ширине окна, а не контейнера.** Баннер — поверхность уровня
  страницы; в узкой колонке ставьте `inline` или `stacked`.
