# Цвет и состояния

## Цвет — это роль, а не оттенок

`MColor` — это `primary | secondary | tertiary | error`. Компонент просит **роль**, а тема
решает, какими будут пиксели. В компоненте нет места, где цвет выбирается потому, что он
хорошо смотрится.

### Таблица ролей

Выведена из семейства полей и обязательна для всего, что имеет ту же форму смысла: ячейки,
чипы, элементы списка, шаги, сегменты.

| Ситуация | Роль |
|---|---|
| Пусто, содержимого нет | `outline-variant` |
| Содержимое есть | `outline` |
| Активно — то, с чем пользователь работает прямо сейчас | `primary` |
| Ошибка | `error` (плюс `error-container` там, где контейнер есть) |
| Выключено | то же свойство на пониженной непрозрачности, но никогда другой цвет |

**`primary` принадлежит одной лишь активности.** Наличие содержимого — не акцент, а наличие
содержимого. Именно поэтому у `<MOtpInput>` нет визуального состояния `complete`: если
`primary` помечает активную ячейку, то покраска готового кода в него сливает две роли — а к
моменту, когда код набран, активной ячейки уже нет. Подтверждение — работа приложения, а не
поля.

## Состояния

Любой интерактивный компонент обрабатывает пять: **обычное, hover, pressed, focused,
disabled**. Hover и pressed — это `color-mix` на непрозрачностях MD3, разрешаемый на этапе
сборки. Непрозрачности живут в одной карте (`$theme-state-link`: hover 8%, focus 10%,
pressed 12%, dragged 16%, disabled — контейнер 12% / контент 38%) и читаются через
`state-opacity()`, никогда не литералом:

```scss
@include can-hover {
  &:hover {
    background: color-mix(in srgb, #{$color} state-opacity(hover), transparent);
  }
}
```

Любое правило с `:hover` лежит внутри `@include can-hover` (`@media (hover: hover)`), чтобы
тап на тач-экране не оставлял состояние «залипшим». `:focus-visible` и прочие состояния —
снаружи. `npm run lint:scss` падает на «голом» `:hover`.

### Одно свойство на состояние

Состояние выражается свойством, которым вариант уже владеет. `outlined` показывает ошибку
через `border-color`, `filled` — тоном контейнера, `underline` — своей линией. Никто не
отращивает новое свойство ради состояния — см.
[principles.md](principles.md#в2-владеет-ли-компонент-свойством-которое-нужно-этому-состоянию).

### Состояние никогда не выражается одним цветом

Один только цвет подводит людей с нарушением цветовосприятия и низкоконтрастные экраны.
Дополняй: иконка, рамка, сообщение, позиция. Строка поддержки под полем держит
зарезервированную высоту именно для этого — раскладка не должна ехать, когда появляется
ошибка.

### Фокус — это цвет, а не движение

Во всём ките фокус — смена цвета: без кольца, без утолщения рамки и никогда не анимация.
Изменение ширины приходится отдавать обратно паддингом, и ни то ни другое не переходит
плавно — оба дёргаются, пока цвет едет. У `<MOtpInput>` нет мигающей каретки по той же причине: она
была бы единственным мигающим элементом кита, а кольцо активной ячейки уже закрывает
WCAG 2.4.7.

На рамке фокус старше ошибки: невалидное поле в фокусе берёт цвет фокуса, а ошибку
продолжают сообщать лейбл, текст и иконка — состоянию они нужны в любом случае. Read-only
поля показывают фокус как любые другие. Все остальные контролы (кнопки, чипы, пункты,
ползунки) используют общий `@include focus-ring`. В forced colors рамка ошибки пунктирная:
системный цвет для неё может пропасть на светлой контрастной теме, а стиль линии — нет.

Единственный случай, где каретка и кольцо действительно расходятся, — возврат к правке
целиком набранного кода: каретка стоит *после* символа, а кольцо подсвечивает ячейку. Случай
сочли слишком редким, чтобы покупать ради него новый механизм.

### Лейблы не двигаются

Плавающий лейбл сидит на верхней кромке контейнера и там остаётся. Его анимация делает
состояние покоя неоднозначным и ломает автозаполнение. `float` — это **позиция**, а не
переход.

### Тень — это уровень, а не значение

Тень — один из уровней MD3 0–5, читается через `elevation(n)` и никогда не пишется литералом
`box-shadow`. Уровни — `--sys-elevation-level0…5` на `:root`, окрашены ролью темы `shadow`.
Состояние, приподнимающее компонент, поднимает его ровно на один уровень (elevated-кнопка и
карточка 1 → 2 при hover, FAB 3 → 4); на любой другой ключ `elevation()` роняет сборку.

## Токены

Значения цвета и состояний берутся из собственной карты `$tokens` компонента через
`g($t, 'a.b.c')`.

**Используй точечный разделитель.** Легаси-форма через дефис не может адресовать ключ,
который сам содержит дефис (`active-outline`, `min-height`, `hover-color`) — она рвёт ключ и
молча резолвится в `null`. Именно так все четыре состояния ячейки `<MOtpInput>` уехали в
релиз, не рендерясь вообще. Трогаешь файл — переводи его целиком; смешение двух разделителей
в одном файле и есть тот механизм, которым баг возникает.

Ловит это `npm run lint:scss`. Запускай после любой правки `<style>` или карты токенов.
