# Решения

Закрытый вопрос остаётся закрытым, пока не появится что-то новое. Это реестр того, что
обсудили один раз, — и половина его о том, чего кит сознательно **не** имеет.

Открывай запись заново только с новой информацией: появился реальный заказчик, изменилось
поведение платформы, отпало ограничение. Заводи запись всякий раз, когда отвергаешь что-то по
причине, которую иначе придётся выводить заново.

## Удалено / отвергнуто

| Решение | Причина | Вернуть, когда |
|---|---|---|
| `variant="ghost"` убран из семейства полей | Потребителей в ките не было — только тесты и лаб-страницы. Ломающее изменение API; ближайшая замена — `outlined`. | Появится названный заказчик: редактируемая ячейка таблицы / inline-правка. |
| Форма поля `terminal` отброшена | Нишевая. | Появится продуктовая потребность. |
| `underline` отвергнут для `<MTextarea>` | Одиночная линия под многострочным блоком читается как незакрытая коробка. | — |
| Размещение лейбла `inline` (две колонки) не поставляется на одиночных полях | Его ценность в том, что колонка лейблов одинаковой ширины у всех строк; одному полю не с чем выравниваться, и подобранная под него колонка просто съедает ширину. | Появится `MFieldGroup` — оно принадлежит туда. |
| Мигающая каретка в `<MOtpInput>` | Во всём ките фокус выражается цветом; это был бы единственный мигающий элемент. Кольцо активной ячейки уже закрывает WCAG 2.4.7. | — |
| Визуальное состояние `complete` в `<MOtpInput>` | `primary` означает **активность**; покраска готового кода в него сливает две роли, а к моменту завершения активной ячейки нет. Подтверждение — работа приложения. **Событие** `complete` остаётся. | — |
| `hideLabel: boolean` | Перечисление из одного, притворившееся флагом. Стало `labelPlacement`. | — |
| `MFieldGroup` (форма `row` из спеки) | Отложено, а не отвергнуто. | Возьмётся отдельной задачей; вместе с ним вернётся размещение `inline`. |
| `underline` для семейства выбора (`<MDropdown>`, `<MAutocomplete>`) | Это единственная форма поля без контейнера, а эти два кладут чипы, крестик очистки и якорь меню **внутрь** коробки; ряд чипов на голой линии ничем не удержан. Плюс это «standard»-поле из Material 2, которое M3 убрал. | Для этих двух — никогда. Если пересматривать сам `underline`, это вопрос ко всему семейству полей. |
| Массивы примитивов в `items` (`['Москва', 'Питер']`) | `id` у элемента обязателен, значит голая строка элементом быть не может. Один `.map(v => ({ id: v, label: v }))` на месте вызова покупает резолверы без единой ветки по `typeof`. | — |
| Анимированная смена формы (S3) и пружины M3 Expressive (S4) в компонентах не делаются | Механизм морфа грузит бандл ради эффекта, который веб-интерфейс передаёт цветом и слоем состояния. Форма состояния статична (выбранный toggle квадратный без перехода), переходы — на токенах `--sys-motion-*`. **Исключения** (решения владельца 2026-10-07): FAB `<MFabMenu>` превращается в кнопку закрытия на пружинах `M3_SPRING` (размер и углы — spatial, цвет — effects); toggle-кнопки (`selected` у `<MButton>` / `<MButtonIcon>`, кнопки `<MButtonGroup>`) приходят к форме выбора на пружине (форма — fast spatial, цвет — effects), как `ToggleButton` в Compose. Обычная кнопка и нажатие форму не меняют. Пружины переводятся в CSS `linear()` (`springToCss`), так что в бандл не попадает покадровый цикл. JS-пружины `MShape` и индикатора загрузки остаются как были. | Появится заказчик морфа в другом компоненте — по тому же рецепту `springToCss`, а не новым механизмом. |
| Сегментированный стиль списка, перестановка строк, свайп по строке, раскрывающаяся строка (M3 Expressive) | Заказчика в ките нет; группы секций уже собираются из `MListSubheader`, а раскрытие — из `MExpansionPanel`. | Появится экран настроек из сегментированных групп, сортируемый список или жест на строке. |
| Карточка-кнопка (`MCard` как `<button>`) и «растянутая ссылка» с действиями поверх | Кликабельная карточка — переход: `tag="link"` делает ссылкой всю карточку. Действие без перехода — `MButton` в `#actions`. | Появится заказчик карточки, которая что-то делает на месте и при этом несёт свои действия. |
| Тоны статуса у `MTimelineItem` (`success | warning | info`) | У них нет ролей M3 (`MColor`), и соответствие «тон → роль» было бы придуманным. Смысл несут скрытое слово `status` и `icon`, роль — `color`. | В системе появятся роли успеха и предупреждения. |
| Одиночный выбор строк `MTable` (ось `selection`) | Заказчика нет. Открыть запись — событие `row-click`, клавиатурный путь — контрол в ячейке. | Появится экран «список → деталь» на таблице. |
| `column.maxWidth` у `MTable` | Браузеры не применяют `max-width` к ячейкам. Длинное значение ограничивают `width` и перенос (`overflow-wrap: anywhere`). | — |
| Счётчик символов у `MTextField` | Длинный ввод — `MTextarea`, счётчик в строке поддержки. | Появится однострочное поле с жёстким лимитом. |
| Docked-пикер даты (`MDateField`) | Рецепт — поле → `MDialogDate`. | Понадобятся плотные фильтры и таблицы. |
| Range-пикер даты | Заказчика нет; обещание снято из документации. | Появится заказчик. |
| `MDialogTime` | Рецепт — `MDialog` + `MTimePicker` + `validate()`. | Появится первый заказчик. |
| Rich-цвета и ScrollField у time picker | API Material3 ещё меняется. | API стабилизируется. |
| `MConfirmEdit` как компонент | Правка с подтверждением — композабл `useConfirmEditTransaction` и рецепт. | Два продукта соберут одинаковую разметку. |
| Английская подпись `aria-label="Loading"` по умолчанию у `MLoading` | Кит не поставляет текст, который не может быть на языке приложения. Хозяин индикатора (кнопка, таблица, OTP) объявляет занятость сам через `aria-busy` и прячет индикатор; отдельно стоящему индикатору имя даёт потребитель, без имени — предупреждение в dev. | — |
| Английские фразы по умолчанию у `<MDropdown>` / `<MAutocomplete>` («Clear», «No results», «Loading…»; ключи `MESSAGES.dropdown*`) | Причина `MLoading`, применённая к семейству выбора: один проп `messages` (`clear`, `toggle`, `loading`, `empty`, `noResults`) без дефолтов — та же форма, что уже у `MFileUpload`; слоты `#empty`, `#no-results` и `#loading` важнее фразы; кнопка без имени даёт предупреждение в dev. Без фразы и без слота состояние остаётся пустым, а живой регион молчит — лучше, чем английский текст в русском приложении. M3-polish, 2026-10-18. | У кита появится источник фраз на уровне приложения. |
| Алиасы и dev-предупреждения «снято» для снятых значений и пропов (`useRetiredValueWarning`, «работает ещё релиз») | Кит в версии 0.x, стабильной нет: снятое значение удаляется сразу, а его потребители внутри кита переводятся в том же изменении; алиас только удваивает API, которое читателю приходится учить. Решение владельца 2026-10-18. | Кит выпустит стабильную мажорную версию. |

## Архитектурные размены

| Решение | Причина |
|---|---|
| Плотность — это **выбор**, а не производная от доступного места | Поле шириной 320px — это цель для пальца в онбординге и цель для мыши в сайдбаре настроек, при одинаковой ширине. |
| Container queries по высоте не используются | Им нужен `container-type: size`; бокс с `contain: size` схлопывается в ноль, когда его высота `auto`, — а колонка формы почти всегда `auto`. Безопасен только `inline-size`, а ширина — плохой прокси. |
| Плотность реализована чистым Sass, а не тремя CSS-переменными | Вариант с кастом-свойствами был бы вдвое короче в исходнике, но zero-runtime сознательно покупает отсутствие рантайма размером собранного CSS. `@each` по трём ступеням держит **исходник** компактным; растёт только выхлоп — это и есть предполагаемый размен. |
| `compact` ограничен снизу минимумом цели 24px по WCAG 2.5.8 | Порог доступности, а не вкус. |
| Плавающий лейбл никогда не анимируется | Движущийся лейбл делает состояние покоя неоднозначным и ломает автозаполнение. Спека запрещает именно движение, а не позицию. |
| Дефолты полей: `float` у text-field и number-input, `top` у textarea | Выбраны так, что введение оси ничего не изменило визуально, — и потому что для каждого поля это верный вид покоя. |
| `<MOtpInput>` — один нативный инпут под N нарисованными ячейками | Вставка, автоподстановка из SMS, backspace через границу ячейки и озвучка скринридером работают бесплатно; N инпутов означают войну с браузером за каждое. |
| `sanitize()` сохраняет нормализацию NFKC и перевод арабо-индийских цифр в ASCII | Код, вставленный из арабской SMS, обязан работать. |
| Точечный разделитель `g()` канонический, дефисный — легаси и предупреждает | Дефисный путь не может адресовать ключ, содержащий дефис, и молча резолвился в `null` на ~99 вызовах. |
| `createRangeKeyboardController` оставлен вторым клавиатурным контроллером | Известное дублирование с `useSliderControl`, сознательно не тронуто. Третий не заводим. |
| Выбор в семействе дропдауна идёт **от модели**, а не от реестра | Поле держит значение раньше, чем держит опции: форма грузит `countryId`, а список приезжает через два тика. Выбор, существующий только как зарегистрированный тикет, теряет это значение в момент регистрации первой опции — и, хуже того, отдаёт укороченный массив обратно в модель. Значения без совпавшего элемента остаются в модели и рисуются из запасной строки. |
| Порядок для клавиатуры берётся из данных, а не из реестра | `createRegistry.register` кладёт тикет в конец, поэтому элемент, вставленный в середину уже смонтированного списка, оказывается последним в реестре, стоя третьим в DOM. Строки и так рисуются `v-for` по массиву; этот массив и есть порядок. Своё состояние дети по-прежнему отдают через контекст. |
| Идентичность элемента — его `id`, и дефолтный компаратор им и пользуется | Две выборки одной записи — это два объекта, поэтому `===` теряет выбор на каждом рефетче. `id` — единственное, что элемент обязан объявить. |
| Строки, заблокированные `max`, выпадают из обхода стрелками, а не только помечаются | APG допускает оба варианта. На достигнутом лимите единственное законное действие — снять выбор, а заход на строки, которые нельзя выбрать, предлагает ходы, ничего не делающие. `aria-disabled` и приглушённый вид у них остаются. |
| `maxHeight` панели едет кастом-свойством | Живая геометрия, заданная в рантайме, — единственный случай, разрешённый zero-runtime-правилом. Токен работает фолбэком, так что сотня опций ограничена и без пропа. |
| Кламп панели по реально доступному месту — работа `<MMenu>`, а не дропдауна | Сегодня не клампится ни один из двух путей позиционирования меню, и та же дыра касается tooltip и popover через `usePopover`. Починка внутри дропдауна закрыла бы одну треть. |
| `<MButtonFab>` и `<MButtonExtendedFab>` сохраняют `disabled` | M3 советует прятать FAB, а не выключать. Кит оставляет `disabled` как расширение: формы «отправить» выключают главное действие до валидности, а снятие пропа — ломающее изменение без выигрыша. |
| Подпись секции внутри `ul` — обычный `li` без роли | axe (правило `list`) не принимает у `ul` прямого ребёнка с явной ролью, кроме `listitem`, поэтому `li role="presentation"` невозможен. Цена: скринридер считает подпись элементом списка; текст читается по порядку, `<h3>` в слоте даёт навигацию по заголовкам. Вложенные группы (`MListGroup`) отвергнуты ранее. |
| `MList` — `ul` без `role="list"` | С явной ролью axe переключается на `aria-required-children` и отвергает заголовок в подписи. Цена: Safari VoiceOver может не объявить список при `list-style: none`. |
| Свёрнутое содержимое `MExpansionPanel` — `inert` | Поля в закрытой панели выпадают из обхода и дерева доступности (A11-11). Цена: поиск по странице не находит текст в закрытых панелях — для этого есть предложение `hidden="until-found"`. |
| Концы рейки `MTimeline` — `:first-child`/`:last-child`, а не реестр | Реестр знает «последний» только после регистрации всех элементов, и сервер отдавал каждый элемент последним. Структурный селектор верен уже в SSR. |
| Колонка времени `MTimeline` определяется CSS `:has()`, а не JS | Это решение уровня ленты, которое сервер должен отдать верно. Без `:has()` колонок остаётся три. |
| Слой состояния строки `MTable` рисуется на каждой ячейке | У `tr` нет надёжного блока для `::before`. |
| Строка панели dropdown равна высоте поля (44 / 56 / 64), а не 48 из M3 | Панель продолжает поле. |
| У `MOtpInput` нет оси `density` | Ячейка 48 — цель касания для кода. |
| Модель времени — всегда 24-часовая строка `HH:mm` | `hourCycle` меняет только вид, по умолчанию `h23`. |
| Выбор строк `MTable` живёт в модели и переживает смену страницы; «выбрать все» относится к текущей странице; исчезнувшие из данных строки таблица из выбора не убирает | При серверной пагинации таблица не может отличить строку другой страницы от удалённой, а «выбрать все» по всем страницам требует знать все данные. Удалённые записи из `v-model` убирает приложение. Решение владельца 2026-10-08. |
| Системный ключ `disabled-container-subtle: 4%` в `$theme-state-link` — единственное исключение из правила «новые значения выводить `calc()` из существующих» | Заливка отключённого filled-поля в M3 — `on-surface` 4% (Compose `DisabledContainerOpacity = 0.04`), из имеющихся непрозрачностей она не выводится. Решение владельца 2026-10-08; следующее исключение — снова только с его решения. |
| Вспомогательный текст отключённого поля — 38%, как в M3, хотя axe видит в нём нарушение контраста | WCAG 1.4.3 освобождает неактивные компоненты, но axe узнаёт это только для текста внутри `disabled` / `aria-disabled`. `expectNoAxeViolations` пропускает `color-contrast` внутри корня с модификатором `--disabled`. Решение владельца 2026-10-08. |
| `spacing()` принимает у потребителя любой шаг (`spacing(96)` → `96rem`); шкала 4-юнитной сетки обязательна только для кода кита | Модуль подмешивает абстракции кита в стили приложения, и внутренняя дисциплина кита становилась запретом для пользователя, которому может понадобиться любой отступ. Строгость — флаг `$spacing-strict`, его включает только `lint:scss` для `src/runtime`. Решение владельца 2026-10-08. |
| Круглая форма, которая морфится или встречается с меньшими углами, — конечный радиус, половина высоты своей ступени плотности (`calc(высота / 2)` в карте), а не `full` (`999rem`): toggle `MButton` / `MButtonIcon`, кнопки `MButtonGroup`, половины split-кнопки, открытый FAB menu. Обычные кнопки остаются `full` | Браузер рисует не больше половины высоты, поэтому пружина от `999` к `12` почти всё время проводит выше этой границы и видна только в самом конце — снапом; рядом с углом `999` маленькие внутренние углы split и группы сплющиваются в ноль. «Full» в Compose — 50% меньшей стороны, а не бесконечность. Обычная кнопка остаётся `full`, чтобы с переносом подписи она оставалась пилюлей. M3-polish, 2026-10-18. |
| Во всей семье кнопок (`MButton`, `MButtonIcon`, FAB, extended FAB, segmented, пункты FAB menu) нажатие — только рипл; hover и focus — слой `::before` (8 / 10) | Готовый смешанный фон нажатия — это подмена фона (craft.md §1), а заливка 12% с риплом поверх — нажатие, показанное дважды. Одна механика на семью и примерно вдвое меньше выходного CSS этих компонентов. M3-polish, 2026-10-18. |
| Сегменты segmented-кнопок — равной ширины, место под галочку есть в каждом сегменте | Галочка добавляла выбранному сегменту 26rem, и соседи вместе со всей группой прыгали при каждом выборе — раскладка не должна ехать от состояния. Так же делает M3 (material-web `grid-auto-columns: 1fr`, Compose `weight(1f)`). Цена: короткие сегменты шире. M3-polish, 2026-10-18. |
| Отключённая ссылка во всём ките (`MButton`, `MCard`, `MListItem`) — `<a>` без `href`, `role="link"` и `aria-disabled="true"`; один хелпер — `utils/link` | С оставленным `href` и `tabindex="-1"` средняя кнопка мыши, «открыть в новой вкладке» и перетаскивание всё равно уводили по ссылке. Без `href` не уводит ничто, и якорь сам выходит из обхода Tab; он теряет и роль — её возвращает `role="link"`, чтобы `aria-disabled` был объявлен. Адрес, переданный потребителем атрибутом, тоже снимается. M3-polish, 2026-10-18. |
| `MDatePicker` / `MDialogDate` отдают модель в том типе, в котором её получили: строку — как `YYYY-MM-DD`, число — как миллисекунды, `Date` — как `Date` | Формы хранят ISO-день, и каждый живой потребитель конвертировал `Date` обратно руками. Тип, который держит приложение, уже сказан входом; проп `valueFormat` стал бы третьим словом для того же факта. M3-polish, 2026-10-18. |
| Поднятый лейбл поля `filled` / `inset` выводится из токенов: он стоит на строке значения, одна формула на все плотности | Раньше это были три подобранных числа, и лейбл почти касался верхней кромки. Выведенная позиция переживает смену токена (craft.md §1). Изменило вид всех полей `filled` / `inset` кита — дропдаун, автокомплит, выбор файла, ввод цвета, поле даты. M3-polish, 2026-10-18. |
| Строка поддержки стоит на 4 ниже коробки поля, а не на 8 | M3 и концепт дают 4; лишние 4 добавлял отступ поверх зазора. Каждая форма становится на 4 короче на поле. M3-polish, 2026-10-18. |
| Поле резервирует строку поддержки, только если ей есть что показать: `helperText`, путь валидации `path`, `required`, слот `#helper` / `#error` или `error` / `errorMessage`, переданные родителем, — даже пустыми (привязан, но пока сказать нечего). Без этого ни строка, ни её live-регион не рендерятся. Композит передаёт пропы ошибки полю, только если их передал его собственный потребитель, путь адаптера может дать ошибку или у композита есть своя ошибка, которую надо показать (отклонённый файл, нечитаемый цвет, отклонённая дата) | Заменяет «строка всегда зарезервирована» (2026-10-06): поле, которое никогда не покажет ошибку, оставляло пустые 16 под собой в каждой форме и пикере. Там, где ошибка может прийти, строка есть заранее — ничего не едет, первая ошибка по-прежнему объявляется. Проверка читает привязанные пропы родителя при рендере, поэтому первый кадр сервера верный. Решение владельца 2026-10-19. |
| Read-only поле отвечает на наведение, как редактируемое, во всём семействе полей | `readOnly` в Compose не меняет цветов, а композиты (дропдаун, выбор файла) — это текстовое поле с `readonly` внутри, и наведение им нужно. Одно правило вместо разницы между text-field, textarea и number-input. M3-polish, 2026-10-18. |
| Строка `MTable` показывает слой наведения, только когда она интерактивна: таблица `selectable` или подписан слушатель `row-click` | Слой состояния — ответ на взаимодействие; на строках, которые ничего не делают по клику, это ложная подсказка — как была у статичной карточки. Подсветка всех строк «для чтения» из data table M2 не сохраняется. M3-polish, 2026-10-18. |
| `modeToggle` у `MTimePicker` (клавиатура ↔ циферблат) по умолчанию выключен; его подписи — пропы без дефолтов с предупреждением в dev | Кнопке, показанной по умолчанию, нужны подписи по умолчанию, а кит не добавляет новых английских строк — это правило важнее паритета с `MDatePicker`. M3-polish, 2026-10-18. |
| `useReducedMotion` хранит состояние на уровне модуля — единственное исключение из правила «нет изменяемого модульного состояния» | Один слушатель `matchMedia` обслуживает всех потребителей вместо одного на компонент. Пишется он только на клиенте после монтирования, сервер его не читает и не пишет, поэтому между запросами ничего не утекает. Альтернатива (`useState` и клиентский плагин) — больше кода ради того же поведения. M3-polish, 2026-10-18. |

## Решено, миграция ждёт

Решено принципиально, код ещё не переехал. Каждое — ломающее изменение публичного API и
получает собственную задачу. Не применяй наполовину: до миграции следуй существующей
локальной конвенции.

| Решение | Причина | Миграция |
|---|---|---|
| `density` — единственное слово кита для масштаба | `size` (`sm \| md \| lg`), `MLoadingSize` (`small \| medium \| large`) и `MFieldDensity` (`compact \| default \| comfortable`) были тремя написаниями одной идеи. Слово определено, набор ступеней — нет, см. [axes.md](axes.md#ов-1-набор-ступеней-для-density). | `avatar` переехал (2026-10-07). Осталось переименовать `size` → `density` в `loading`, `progress`; убрать `MSize`. Значения ждут ОВ-1. |
| `plain` входит в канонический `MVariant` | `MSurfaceVariant` уже добавил его самостоятельным членом. Это законная пятая обработка поверхности, а не причуда компонента. | Добавить в `MVariant`; `MSurfaceVariant` становится `Extract<MVariant, …>`. |
| Член `surface` в `MBannerVariant` — ошибка наименования | `surface` называет компонент, а не обработку. Значение, которое имелось в виду, уже есть в каноническом юнионе. | Переименовать в канонический член и сузить через `Extract<>`. |
| Тонкая обводка — `max(1px, 1rem)` во всех outlined-компонентах | Корень кита масштабируется от ширины окна (`1rem` — пиксель макета), и на узком экране `1rem` становится тоньше аппаратного пикселя: линия бледнеет или пропадает. `max()` держит хотя бы один пиксель, на широком экране ничего не меняется. Решение владельца 2026-10-08; выражается в картах компонентов, без системного токена. | `divider`, `avatar`, `table`, семейство полей, `card` и семья кнопок уже переехали (последние две — в M3-polish, 2026-10-18/19). Пройти по остальным картам с обводкой в `1rem` (чипы, …) отдельной задачей. |
