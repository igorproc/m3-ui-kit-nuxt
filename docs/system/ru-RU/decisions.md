# Решения

Закрытый вопрос остаётся закрытым, пока не появится что-то новое. Это реестр того, что
обсудили один раз, — и половина его о том, чего кит сознательно **не** имеет.

Открывай запись заново только с новой информацией: появился реальный заказчик, изменилось
поведение платформы, отпало ограничение. Заводи запись всякий раз, когда отвергаешь что-то по
причине, которую иначе придётся выводить заново.

## Удалено / отвергнуто

| Решение | Причина | Вернуть, когда |
|---|---|---|
| `variant="ghost"` убран из семейства полей | Потребителей в ките не было — только тесты и лаб-страницы. Ломающее изменение API; ближайшая замена — `outlined`. | Появится названный заказчик: редактируемая ячейка таблицы / inline-правка. |
| Форма поля `terminal` отброшена | Нишевая. | Появится продуктовая потребность. |
| `underline` отвергнут для `<MTextarea>` | Одиночная линия под многострочным блоком читается как незакрытая коробка. | — |
| Размещение лейбла `inline` (две колонки) не поставляется на одиночных полях | Его ценность в том, что колонка лейблов одинаковой ширины у всех строк; одному полю не с чем выравниваться, и подобранная под него колонка просто съедает ширину. | Появится `MFieldGroup` — оно принадлежит туда. |
| Мигающая каретка в `<MOtpInput>` | Во всём ките фокус выражается цветом; это был бы единственный мигающий элемент. Кольцо активной ячейки уже закрывает WCAG 2.4.7. | — |
| Визуальное состояние `complete` в `<MOtpInput>` | `primary` означает **активность**; покраска готового кода в него сливает две роли, а к моменту завершения активной ячейки нет. Подтверждение — работа приложения. **Событие** `complete` остаётся. | — |
| `hideLabel: boolean` | Перечисление из одного, притворившееся флагом. Стало `labelPlacement`. | — |
| `MFieldGroup` (форма `row` из спеки) | Отложено, а не отвергнуто. | Возьмётся отдельной задачей; вместе с ним вернётся размещение `inline`. |
| `underline` для семейства выбора (`<MDropdown>`, `<MAutocomplete>`) | Это единственная форма поля без контейнера, а эти два кладут чипы, крестик очистки и якорь меню **внутрь** коробки; ряд чипов на голой линии ничем не удержан. Плюс это «standard»-поле из Material 2, которое M3 убрал. | Для этих двух — никогда. Если пересматривать сам `underline`, это вопрос ко всему семейству полей. |
| Массивы примитивов в `items` (`['Москва', 'Питер']`) | `id` у элемента обязателен, значит голая строка элементом быть не может. Один `.map(v => ({ id: v, label: v }))` на месте вызова покупает резолверы без единой ветки по `typeof`. | — |

## Архитектурные размены

| Решение | Причина |
|---|---|
| Плотность — это **выбор**, а не производная от доступного места | Поле шириной 320px — это цель для пальца в онбординге и цель для мыши в сайдбаре настроек, при одинаковой ширине. |
| Container queries по высоте не используются | Им нужен `container-type: size`; бокс с `contain: size` схлопывается в ноль, когда его высота `auto`, — а колонка формы почти всегда `auto`. Безопасен только `inline-size`, а ширина — плохой прокси. |
| Плотность реализована чистым Sass, а не тремя CSS-переменными | Вариант с кастом-свойствами был бы вдвое короче в исходнике, но zero-runtime сознательно покупает отсутствие рантайма размером собранного CSS. `@each` по трём ступеням держит **исходник** компактным; растёт только выхлоп — это и есть предполагаемый размен. |
| `compact` ограничен снизу минимумом цели 24px по WCAG 2.5.8 | Порог доступности, а не вкус. |
| Плавающий лейбл никогда не анимируется | Движущийся лейбл делает состояние покоя неоднозначным и ломает автозаполнение. Спека запрещает именно движение, а не позицию. |
| Дефолты полей: `float` у text-field и number-input, `top` у textarea | Выбраны так, что введение оси ничего не изменило визуально, — и потому что для каждого поля это верный вид покоя. |
| `<MOtpInput>` — один нативный инпут под N нарисованными ячейками | Вставка, автоподстановка из SMS, backspace через границу ячейки и озвучка скринридером работают бесплатно; N инпутов означают войну с браузером за каждое. |
| `sanitize()` сохраняет нормализацию NFKC и перевод арабо-индийских цифр в ASCII | Код, вставленный из арабской SMS, обязан работать. |
| Точечный разделитель `g()` канонический, дефисный — легаси и предупреждает | Дефисный путь не может адресовать ключ, содержащий дефис, и молча резолвился в `null` на ~99 вызовах. |
| `createRangeKeyboardController` оставлен вторым клавиатурным контроллером | Известное дублирование с `useSliderControl`, сознательно не тронуто. Третий не заводим. |
| Выбор в семействе дропдауна идёт **от модели**, а не от реестра | Поле держит значение раньше, чем держит опции: форма грузит `countryId`, а список приезжает через два тика. Выбор, существующий только как зарегистрированный тикет, теряет это значение в момент регистрации первой опции — и, хуже того, отдаёт укороченный массив обратно в модель. Значения без совпавшего элемента остаются в модели и рисуются из запасной строки. |
| Порядок для клавиатуры берётся из данных, а не из реестра | `createRegistry.register` кладёт тикет в конец, поэтому элемент, вставленный в середину уже смонтированного списка, оказывается последним в реестре, стоя третьим в DOM. Строки и так рисуются `v-for` по массиву; этот массив и есть порядок. Своё состояние дети по-прежнему отдают через контекст. |
| Идентичность элемента — его `id`, и дефолтный компаратор им и пользуется | Две выборки одной записи — это два объекта, поэтому `===` теряет выбор на каждом рефетче. `id` — единственное, что элемент обязан объявить. |
| Строки, заблокированные `max`, выпадают из обхода стрелками, а не только помечаются | APG допускает оба варианта. На достигнутом лимите единственное законное действие — снять выбор, а заход на строки, которые нельзя выбрать, предлагает ходы, ничего не делающие. `aria-disabled` и приглушённый вид у них остаются. |
| `maxHeight` панели едет кастом-свойством | Живая геометрия, заданная в рантайме, — единственный случай, разрешённый zero-runtime-правилом. Токен работает фолбэком, так что сотня опций ограничена и без пропа. |
| Кламп панели по реально доступному месту — работа `<MMenu>`, а не дропдауна | Сегодня не клампится ни один из двух путей позиционирования меню, и та же дыра касается tooltip и popover через `usePopover`. Починка внутри дропдауна закрыла бы одну треть. |

## Решено, миграция ждёт

Решено принципиально, код ещё не переехал. Каждое — ломающее изменение публичного API и
получает собственную задачу. Не применяй наполовину: до миграции следуй существующей
локальной конвенции.

| Решение | Причина | Миграция |
|---|---|---|
| `density` — единственное слово кита для масштаба | `size` (`sm \| md \| lg`), `MLoadingSize` (`small \| medium \| large`) и `MFieldDensity` (`compact \| default \| comfortable`) были тремя написаниями одной идеи. Слово определено, набор ступеней — нет, см. [axes.md](axes.md#ов-1-набор-ступеней-для-density). | Переименовать `size` → `density` в `avatar`, `loading`, `progress`; убрать `MSize`. Значения ждут ОВ-1. |
| `plain` входит в канонический `MVariant` | `MSurfaceVariant` уже добавил его самостоятельным членом. Это законная пятая обработка поверхности, а не причуда компонента. | Добавить в `MVariant`; `MSurfaceVariant` становится `Extract<MVariant, …>`. |
| Член `surface` в `MBannerVariant` — ошибка наименования | `surface` называет компонент, а не обработку. Значение, которое имелось в виду, уже есть в каноническом юнионе. | Переименовать в канонический член и сузить через `Extract<>`. |

## Закрыто

| Решение | Чем закончилось |
|---|---|
| `<MDropdown>` пока сохраняет собственный `variant` | Закрыто переработкой дропдауна: он спредит `mFieldProps` + `fieldDensityProp`, а `variant` сужает до `Extract<MTextFieldVariant, 'filled' \| 'outlined'>`. `<MAutocomplete>` — тот же компонент плюс фильтр, поэтому берёт те же пропы из `mDropdownProps`. |
