# Чек-лист

## До того, как что-то написать

1. **Отвечает ли система на это уже сейчас?** В какое семейство входит компонент и какие его
   оси применяются без изменений? Вывод лучше изобретения — если ты рисуешь, а не выводишь,
   сначала найди недостающее правило.
2. **Какие оси ему нужны?** Бери их из [axes.md](axes.md). Новая ось — это изменение системы:
   назови её, обоснуй и будь готов отвечать за неё больше чем в одном компоненте.
3. **Нет ли пропа, который на деле свёрнутое перечисление?** Разворачивай сейчас, а не после
   релиза.
4. **Кто заказчик каждого варианта?** Нет заказчика — нет варианта.
5. **Какие внешние ограничения здесь действуют?** Минимумы доступности, поведение нативного
   элемента, пределы платформы. Назови хотя бы одно — иначе ты в зоне вкуса: остановись и
   спроси.
6. **Не решали ли это уже?** Загляни в [decisions.md](decisions.md).

## Пока делаешь

- Сначала нативный элемент; рисуй поверх него, а не переписывай его.
- Поведение — в control-композабл, презентацию — в компонент ([behavior.md](behavior.md)).
  Шаблоны остаются тонкими.
- Цвет — только по ролям из таблицы в [color-and-state.md](color-and-state.md).
- Все пять состояний, `color-mix` на 8% / 12%, одно свойство на состояние, никогда не только
  цвет.
- Токены через `g($t, 'точечный.путь')` — точечная форма, весь файл, без исключений.
- Никаких захардкоженных значений, никаких локальных `$colour`-переменных, никаких
  рантайм-кастом-свойств для цвета и состояний. Живая геометрия — единственное исключение.
- Компоненты, принимающие контент, отдают `<slot />`.
- Внутри библиотеки другие UI-компоненты импортируй **явно**; автоимпорт — только для
  композаблов, утилит и API реактивности.
- Новый стор Pinia требует явного одобрения человеком. Предпочитай `useState()` и
  `provide`/`inject`.

## Прежде чем назвать готовым

```bash
npm run lint && npm run lint:style && npm run lint:scss && npm run test
```

- `lint:scss` — единственное, что компилирует Sass из SFC: иначе неверная арность миксина или
  мёртвый путь токена доедут до дев-сервера потребителя. Он падает и на депрекациях.
- Проверь, что в собранном CSS действительно есть правила для добавленных модификаторов
  состояний. Тесты смотрят на DOM и классы; они не увидят, что путь токена дал `null`.
- Перегенерируй манифесты доков (`docs:sync`), чтобы новые оси появились в таблицах пропов.
- Напиши summary в `.cursor/summary/<краткое-описание>_<таймстемп>.md`.

## Definition of Done

Скажи прямо: что изменилось (список файлов), как это проверить, какие допущения сделаны и где
они могут оказаться неверными, что осталось и какие есть риски.

Явно отмечай, если правка в основном про CSS и **не была** посмотрена глазами в браузере:
тесты читают DOM и классы, поэтому визуальная регрессия проходит их незамеченной. Дев-серверы
запускает человек — спроси.
