# Textarea: standalone-переписка по PrimeTime Fields Spec

**Дата:** 2026-09-03
**Репозитории:** `kit` (компонент + два композабла + токены + тесты), `docs` (демо-страница)
**Источник дизайна:** Claude Design → проект `df4c2553-40a5-4ad6-bfef-813244279864`,
файл `PrimeTime Fields Spec.dc.html`, фрейм 06 (`text-area`) + фреймы 02–05, 08.

## Зачем

`<MTextarea>` оставался единственным полем на legacy-фрагменте `FieldRoot`, тогда как
`MTextField` уже уехал на standalone-разметку (ef87c74). Из этого росли все жалобы:

- **outlined-лейбл посередине.** В `FieldRoot` лейбл — `top: 50%; translateY(-50%)`
  относительно `.ui-field__control`, а textarea переопределял его на `align-items: stretch;
  min-height: 96rem`. 50% от высокой коробки и есть центр. У filled поднятое состояние
  задавалось абсолютным `filled.active.label.top`, поэтому там совпало случайно.
- **underline рисовался как outlined.** В SCSS `FieldRoot` существовали только ветки
  `--filled` и `--outlined`; `underline`/`ghost` не были реализованы вообще, класс получал
  базовые `border-width` + `border-style: solid` без цвета — рамку со всех сторон.
- **Два механизма авторазмера дрались.** SCSS ставил `field-sizing: content` безусловно,
  а JS писал inline `style.height`. В Chrome выигрывал JS, в Firefox/Safari — только JS,
  при этом `rows`/`maxRows` при живом `field-sizing` игнорировались.
- **`useWindowEventListener('resize')`** — глобальный слушатель на `window` на каждый
  инстанс ради пересчёта высоты при смене ширины.
- **`code`-режим был клавиатурной ловушкой** (перехват `Tab` без выхода) — WCAG 2.1.2.

## Что сделано в `kit`

### Новый слой `composables/textarea/`

`useTextareaResize.ts` — высота: авторост, grip, CSS-переменные. Один механизм на браузер:
`field-sizing: content` там, где поддерживается, иначе одно измерение `scrollHeight` на
изменение значения; границы приходят из уже посчитанных браузером `min-height`/`max-height`.
Ширина отслеживается `ResizeObserver` на самом элементе — подписки на `window` больше нет.
Grip тянется указателем и управляется с клавиатуры (↑/↓ — строка, PageUp/PageDown — пять,
Home/End — границы, Escape — сброс к авто). Ручная высота выигрывает у автороста до сброса.

`useTextareaControl.ts` — поведение: `useTextField` (валидация/фокус) + `useTextareaResize`,
плюс идентификаторы, счётчик и весь ARIA. Отдаёт `inputAttrs` / `labelAttrs` / `supportAttrs`
/ `counterAttrs` / `gripAttrs` и флаги состояния. **Классов и `data-*` не производит** —
презентация целиком на потребителе (в тестах это зафиксировано отдельным кейсом).

### Компонент

`components/ui/textarea/index.vue` — standalone-разметка без `FieldRoot`, состояния несут
BEM-модификаторы (`ui-textarea--focused|error|disabled|readonly|auto-grow|capped|resizable|
resizing|composer|hide-label`), не `data-*`.

`components/ui/textarea/footer.vue` → `<MTextareaFooter>` (автоимя из `pathPrefix: true,
prefix: 'm'`): toolbar-строка, которую контейнер поглощает; слоты `#start`/`#end`.

### Что взято из спеки

- **Лейбл всегда сверху и не анимируется** (anti-rule «No animated float»). Для многострочного
  поля свободной первой строки не существует — плавающий лейбл там или наезжает на значение,
  или уезжает в центр коробки, что и было багом.
- **Счётчик живёт в label-баре**, а не под полем — support-строка остаётся свободной под ошибку.
- **Support-строка с зарезервированной высотой** (`min-height: 18rem`): переход valid⇄invalid
  не двигает форму.
- **Одно свойство на состояние**: hover меняет тон рамки, focus добавляет кольцо
  (1px рамка + 3rem ring @14%, ширина рамки не меняется), validity меняет оттенок рамки и
  добавляет глиф ▲, disabled меняет поверхность, readonly снимает контейнер.
- **Состояние никогда не только цветом** — у ошибки есть глиф.
- **Motion — только обратная связь**: цвет 90ms linear, высота 120ms ease-out; ничего не
  меняет положение.

### Публичный API

Убрано: `code`, `resize`, вариант `ghost`.
Добавлено: `resizable`, `resizeLabel`, `hideLabel`.
Подключён унаследованный `rounded` — раньше приходил из `mFieldProps` и молча игнорировался.
`rows` сохраняет нативную семантику и работает как минимум высоты.

### A11y

`<label for>` + нативный `<textarea>`, без выдуманных ролей. `aria-required` (не было),
`aria-invalid`, `aria-describedby` = support + counter. `role="alert"` только на ошибке;
у helper-строки live-региона нет. Счётчик становится `aria-live="polite"` только у порога
лимита (остаток ≤ max(10, 10% лимита)) — иначе скринридер читал бы каждый символ. Grip —
паттерн window splitter: `role="separator"`, `tabindex`, `aria-orientation`,
`aria-valuenow/min/max` в строках; нативный `resize` этот путь не закрывает (WCAG 2.1.1).
Клавиатурная ловушка ушла вместе с `code`.

## Тесты

`components/ui/textarea/tests/{variants,interaction,a11y}.spec.ts` — 70 кейсов, разбивка как
у `autocomplete`. `composables/textarea/useTextareaControl.spec.ts` — 10 кейсов на голом
харнессе без единого класса кита (escape-hatch не может «врать»).
Старый `components/ui/textarea/index.spec.ts` удалён — он ассертил `.ui-field__control--*`.

Полный прогон: 92 файла / 788 тестов зелёные, `lint` и `lint:style` — 0 ошибок.

## Расхождения со спекой (осознанные)

- **Density (sm/md/lg) не реализована** — это ось всего семейства полей, а не textarea;
  вводить её только здесь значит развести поля.
- **Warning-состояние (△) не реализовано** — у кита нет `caution`-роли в теме.
- **Шейпы `row` и `terminal` не реализованы**, `code`-вариант textarea выброшен по решению.
- **Дефолтный вариант остался `filled`**, хотя спека называет дефолтом outlined — менять
  дефолт значит молча изменить вид существующих потребителей.
- **Фокус-кольцо разошлось с `MTextField`**: тут 1px рамка + ring по спеке, там 2px рамка.
  Унификация — вместе с будущим объединением field-слоя.

## Что осталось

- `FieldRoot` теперь используется только `number-input`. Либо мигрировать его тем же
  способом, либо удалить фрагмент вместе с ним.
- Демо-страница `docs/app/pages/components/textarea.vue` написана, но в браузере не
  проверялась (dev-сервер не запускался).
- `prepend`/`append` переехали внутрь поля (append прилипает к последней строке) — под них
  ещё нет реального потребителя в ките.

## Ревизия по ревью (2026-09-03, вторая итерация)

Правки после разбора первой версии — часть из них откатывает решения спеки в пользу
внутренней консистентности кита:

- **Фокус — только цвет рамки.** Спека требовала «1px рамка + 3px ring @14%», сначала это
  заменили на утолщение рамки как у `MTextField` (2rem + компенсация `padding-inline` до
  15rem). Оба варианта отвергнуты: ширина и паддинг не перечислены в `transition` и потому
  щёлкают мгновенно на фоне плавно едущего цвета, а компенсация паддинга — костыль.
  Итог: `border-color → primary`, ширина 1rem неизменна, паддинг не двигается.
  `border-style` остаётся единственным исключением — ghost обязан затвердеть из пунктира.
  **Расхождение с `MTextField`**, который пока продолжает утолщать рамку.
- **Счётчик вернулся вниз**, в строку поддержки справа от сообщения (спека клала его в
  строку лейбла). `__bar` исчез, появились `__support` (обёртка-строка) и `__message`
  (сам параграф с id и `role="alert"`).
- **`underline` заменён на `ghost`** — под многострочным блоком одиночная линия не читается.
  Ghost повторяет реализацию из `MTextField`: пунктир в покое, сплошная рамка на hover/focus.
- **`readonly` больше не снимает контейнер** (тоже требование спеки, откачено): коробка
  выглядит как обычно, уходит только интерактивность — hover, фокус-хром, grip, footer.
- **`disabled`/`readonly` доходят до footer.** `<MTextarea>` провайдит `textareaFieldStateKey`,
  `<MTextareaFooter>` его инжектит и ставит себе `inert` — нативно снимает и клики, и фокус,
  и таб-порядок, чего не сделал бы `pointer-events: none`.
- **`rounded` доведён до паритета с `MTextField`**: тиры из shape-scale, filled держит
  плоский низ, `pill` у filled капается на `large`.
- **Grip получил видимый фокус** (`:focus-visible` → outline 2rem + offset). Без него
  Tab уводил каретку на 10-пиксельную метку, и это читалось как «Tab не работает».

### Композаблы: props вместо геттеров

`useTextareaControl(model, focused, props)` и `useTextareaResize(element, props)` теперь
принимают реактивный объект пропсов целиком. Каждое чтение живёт внутри computed, поэтому
реактивность сохраняется, а из компонента ушли ~25 строк обёрток вида `rows: () => props.rows`.
Для потребителя без компонента подходит любой `reactive({...})`.

### Прочее

- `focusFromBox` свёлся к `event.target !== event.currentTarget` — клик по самому паддингу
  фокусит поле, всё, у чего есть собственная цель (textarea, grip, кнопка в адорнменте),
  обрабатывает себя само.
- Интерполяция `#{&}` в SCSS убрана: составные модификаторы пишутся явными именами
  (`&--filled .ui-textarea__control` / `&.ui-textarea--focused`).
- Глиф ошибки ▲ был удалён из компонента вне этой сессии; тесты приведены к текущей
  разметке. Ошибка теперь различима только цветом рамки и текстом — см. риск ниже.

### Риск

Без глифа состояние ошибки отличается от нормального только цветом (рамка + текст), что
нарушает WCAG 1.4.1 «Use of Color». Текст сообщения спасает частично: он есть не всегда
(`error` без `errorMessage`). Стоит вернуть глиф или иной нецветовой признак.

## Ревизия по MD3-ревью (2026-09-03, третья итерация)

Тот же разбор, что прошёл number-input: поле читалось как форм-тулкит, а не как Material.
Причина везде одна — **волосяная линия внутри контрола**, чего Material не рисует никогда,
и **отсутствие state layer**.

### Футер отделён тоном, а не линией

`border-top` под футером убран. Вместе с ним ушёл `footer.border.color`, а поверхность
сменилась с `surface-container-low` (ступень **вниз** от контейнера — внутри одной рамки
встречались две далёкие поверхности) на `surface-container-high`, то есть ступень вверх.
У `filled` контейнер уже лежит на `surface-container-highest`, ступеньки выше нет, поэтому
там футер получает state layer 8% — то же решение, что у зон степперов в number-input.
Базовый тон живёт в `footer.vue`, вариантная ветка — в `index.vue`, потому что о форме знает
только он (специфичность `.ui-textarea--filled .ui-textarea__footer` выигрывает в любом
порядке подключения).

### Grip стал drag handle

Уголок из двух бордеров — это нативный ОС-ный маркер ресайза, у Material аналога нет.
Заменён на полоску по центру нижней кромки: 44×5rem, полный радиус, тот же грабер, что у
bottom sheet. Цель — `::before` 72×16rem вокруг неё, то есть в разы больше прежних 10rem;
именно микроскопичность старого уголка читалась как «Tab не работает».

`:focus-visible` больше не рисует кольцо — фокус выражается цветом, как во всём семействе.
На полоске такой ширины цвета хватает, а кольцо было костылём под невидимый уголок.
Токены `grip.size`/`grip.focus.width`/`grip.focus.offset` удалены, появились
`grip.width/height/band/hit`.

### Один state layer вместо пре-смешанных ховеров

`filled.hover.surface` и `ghost.hover.surface` удалены. Вместо двух заранее смешанных цветов
у `.ui-textarea__control` появился `::before` с `z-index: -1` — слой в собственных чернилах
поля, поверх поверхности и под значением. Работает и на прозрачном контейнере, где
смешанный цвет не работал в принципе. Контейнер получил `isolation: isolate`, чтобы
отрицательный z-index не провалился за фон предка.

### Ошибка снова различима без цвета

Возвращён нецветовой признак — `<MIcon name="round-error">` в строке сообщения,
`aria-hidden` (смысл несёт текст). Показывается и когда `error` выставлен без `errorMessage`,
то есть в единственном случае, когда раньше не было вообще ничего, кроме оттенка.
Слот `#error` его подавляет — там индикатор на совести потребителя.
Захардкоженный `gap: 6rem` заменён токеном `support.icon.gap` (он под этот глиф и был).
Закрывает риск WCAG 1.4.1, отмеченный в первой итерации. Пять новых кейсов в `a11y.spec.ts`.

### `MTextField` приведён к семейству

Фокус там утолщал рамку до 2rem с компенсацией `padding-inline` до 15rem — а ни ширина, ни
паддинг не перечислены в `transition`, поэтому оба щёлкали мгновенно на фоне плавно едущего
цвета. Убрано в четырёх ветках (`filled`, `outlined`, `underline`, `ghost`): остаётся
`border-color`. Теперь все три поля семейства говорят на одном языке фокуса.

Токены `filled.focused.border.width`, `outlined.focused.border.width` и
`outlined.focused.padding.inline` **не удалены** — на них ещё ссылается осиротевший
`fragments/field/root.vue`. Уйдут вместе с ним.
