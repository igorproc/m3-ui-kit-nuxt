# Number-input: standalone-переписка по PrimeTime Fields Spec

**Дата:** 2026-09-03
**Репозитории:** `kit` (компонент + три композабла + токены + тесты), `docs_v2` (lab-страница, манифесты)
**Источник дизайна:** Claude Design → проект `df4c2553-40a5-4ad6-bfef-813244279864`,
файл `PrimeTime Fields Spec.dc.html`, фрейм 07 (`number-input · six ways to change a number`).

## Зачем

`<MNumberInput>` оставался последним компонентом на legacy-фрагменте `FieldRoot`.
Оттуда росли все шесть пунктов ревью:

- **`ghost` не работал, `underline` рисовался как `outlined`.** В SCSS `FieldRoot`
  существовали ровно две ветки — `.ui-field__control--filled` и `--outlined`. Остальные
  варианты получали базовое правило с безусловными `border-width` + `border-style: solid`
  и без цвета, то есть рамку со всех сторон. Тот же баг, что был у textarea.
- **«Иконки по центру, а сам input нет».** У filled инпуту выдавался асимметричный паддинг
  под поднятый лейбл (`filled.input.padding.top/bottom`), а `.ui-field__icon` центрировался
  по всей высоте контрола без этого паддинга. Рядом с маленькой иконкой незаметно, рядом с
  цифрой и «+»/«−» — бросается в глаза.
- **«Супер громоздкий».** Высота набиралась из трёх независимых источников: `container.height`,
  паддинги под лейбл и собственный `min-height` у `MButtonIcon` в той же строке.
- **«stacked + split небрежно».** Оба собирались из полноразмерных `MButtonIcon`, у stacked
  они просто ставились в колонку с `gap: 0`.

## Что сделано в `kit`

### Новый слой `composables/number-input/`

`useNumberValue.ts` — цикл draft ⇄ модель, и больше ничего: парсинг, форматирование, шаг,
клампинг. Два правила определяют устройство: **черновик не равен значению** (`"-"`, `"1."`,
`""` — законные промежуточные состояния) и **никогда не клампить на нажатие клавиши** —
поле, переписывающее `1` в минимум `10`, пока пользователь идёт к `100`, сломано.
Клампинг живёт в `commit()` (blur / Enter) и в шаге.

`useNumberScrub.ts` — горизонтальный drag поверх существующего `useDrag`. Жест
**абсолютный, а не инкрементальный**: значение снимается на `pointerdown`, каждое движение
считает `base + steps × step`. Поэтому возврат мышью в исходную точку возвращает исходное
значение, а модификатор, нажатый на середине, перешкаливает весь жест, не оставляя шва.
Shift ×10, Alt ×0.1, 4px на шаг, порог 3px (иначе клик по лейблу перестал бы быть кликом).

`useNumberInputControl.ts` — `useField` (валидация) + два верхних + id и ARIA →
`inputAttrs` / `labelAttrs` / `supportAttrs` / `incrementAttrs` / `decrementAttrs`.
**Классов и `data-*` не производит** — на это есть отдельный кейс в спеке композабла.

### Компонент

`components/ui/number-input/index.vue` — standalone-разметка без `FieldRoot`, состояния
несут BEM-модификаторы (`ui-number-input--focused|populated|error|disabled|readonly|
interactive|split|stacked|scrub|scrubbing|unit`), не `data-*`.

**Ключевое структурное решение — сквозные зоны.** `.ui-number-input__control` получил
`align-items: stretch` и `overflow: hidden`, паддинг переехал с контейнера на
`__body`/`__input`. Степперы теперь растягиваются на всю высоту коробки и прижаты к её
краю с разделителем: split — две зоны по 44rem, stacked — колонка 26rem с ▲/▼. У зоны,
занимающей всю высоту, нет средней линии, о которой можно разойтись с текстом, и она не
добавляет высоты, как добавлял `MButtonIcon` со своим `min-height`. Это лечит первый и
шестой пункты ревью одним приёмом.

Кнопки — нативные `<button>` (без `MButtonIcon`), но под слотами `#increment`/`#decrement`,
так что заменяются целиком. `unit` вынесен в такую же зону с ведущей границей.

### Что взято из спеки

- **Anti-rule «Never clamp on keystroke»** — реализовано и закреплено тестом; пул-бэк на
  blur отдаётся наружу как `invalid(draft, 'out-of-range')`, чтобы потребитель мог
  объяснить его в support-строке. Своей английской копирайт-строки кит не выдумывает.
- **Rule «numerals are tabular»** — `font-variant-numeric: tabular-nums` на значении.
- **Split — «the only touch-safe stepper»** (44rem), **stacked — desktop only** (26rem).
- **Scrub** — «ghost shape; the label itself is a horizontal drag target», и обязательное
  «never the only way to set the value»: инпут остаётся печатаемым и остаётся spinbutton'ом.
- **Unit — часть контейнера, а не отдельный контрол**: одна рамка фокуса, один лейбл.

### Публичный API

Убрано: `slider` (+ `.ui-number-input__slider`), вариант `underline`.
Добавлено: `scrub`, `incrementLabel`, `decrementLabel`.
Починен `ghost`. Подключён унаследованный `rounded` — раньше приходил из `mFieldProps`
и молча игнорировался (та же дыра, что была у textarea).
`unit` оставлен строковым суффиксом — см. «Отложено».

### A11y

`<label for>` + нативный `<input>` c `role="spinbutton"`, `aria-valuenow/min/max/valuetext`
(озвучивается форматированное `12,345`, а не голое число). `aria-required` (не было),
`aria-invalid`, `aria-describedby` на support-строку; `role="alert"` только на ошибке.

`type="text"` + `inputmode` вместо `type="number"`: сохраняется локальный черновик с
разделителями, который умеет парсить кодек, и уходит поведение «колесо мыши съело значение».

Степперы — `tabindex="-1"` по паттерну WAI-ARIA spinbutton: инпут уже даёт весь клавиатурный
доступ, а фокусируемые кнопки добавляли бы две табостановки на поле, не открывая ничего
нового. Ручка scrub — это `<label for>`, то есть не табостановка: клик по ней фокусирует
поле, а клавиатурный эквивалент жеста — стрелки самого спинбаттона. `ArrowLeft/Right`
намеренно **не** заняты: это отняло бы у пользователя движение каретки.

Home/End перехватываются только когда есть соответствующая граница — иначе остаются
привычными шорткатами каретки в текстовом поле.

## Найденный баг (не мой, но починен)

**Escape никогда не откатывал значение.** `restore()` перечитывал значение из модели, а
`onInput` уже писал в модель каждое нажатие — к моменту Escape там лежало ровно то, что
пользователь напечатал. Так было и в старой реализации. Добавлен снимок `committed`
(обновляется на focus, commit и шаге) и отдельный `revert()`; `restore()` остался тем, чем
был — перерисовкой черновика из модели для вотчера кодека.

## Ревизия по ревью (вторая итерация)

### `controls` — одна ось вместо флагов

`scrub` был отдельным булевым пропом, хотя split / stacked / scrub не могут существовать
одновременно. Теперь это одно перечисление: `controls: 'split' | 'stacked' | 'scrub' | false`.
Проп `scrub` удалён. Каноничный тип живёт в `props.ts` (оттуда его читает генератор доков
`docs_v2`), а `NumberScrubProps` в композабле повторяет литералы явно — композабл не может
импортировать из компонента, а разворачивать алиас через границу слоя генератор не умеет.

### Unit стал меню

`<MNumberInputUnit>` (`components/ui/number-input/unit.vue`) — зона суффикса. Без `units`
это статическая строка, как было; со списком — триггер, открывающий `<MMenu>`.

- **`unit` теперь модель** (`v-model:unit`), а не проп: единица измерения — самостоятельное
  значение, а не украшение числа. Два модели, никакой связи между ними.
- **Выбор только переименовывает.** 512 MiB не превращается в 0.5 GiB: для конвертации нужна
  шкала, которой у поля нет, а молча пересчитать напечатанное пользователем число хуже, чем
  не пересчитывать. Закреплено тестом.
- `units` принимает `string[]` или `{ value, label }[]`.
- ARIA: триггер — `aria-haspopup="menu"` + `aria-expanded`, пункты — `role="menuitemradio"`
  с `aria-checked`. Роль radio, а не обычный menuitem, потому что единица одна из набора.
  Хардкод `role="menu"` на поверхности `MMenu` при этом не трогается.
- Меню закрывается само, если поле уходит в disabled/readonly — иначе над мёртвым полем
  осталась бы висеть живая поверхность.

`tests/unit.spec.ts` — 15 кейсов (статический суффикс, меню, ARIA), с поднятием
`#ui-overlay-host`, как в тестах autocomplete.

**Побочный эффект:** модели нигде не попадают в генерируемый API (`modelValue` и `focused`
тоже там отсутствуют у всех компонентов кита), поэтому `unit` исчез из таблицы пропов
`docs_v2`. Это общее поведение генератора, не регрессия этой задачи.

Итог: 96 файлов / 904 теста зелёные, из них 115 по number-input.

### Тональные зоны вместо разделителей

Поле читалось как бутстраповский `input-group`, и причина была буквальная: внутри одного
контрола стояли три волосяные линии (`−` │ значение │ unit │ `+`). Material не разделяет
части контрола линией никогда — он разделяет **тоном и формой**.

- Все `border-left`/`border-right` у степперов и у колонки stacked убраны.
- Зона стала объектом внутри коробки: своя поверхность, свой радиус, отступ от края.
  На прозрачных контейнерах (`outlined`, `ghost`) это `surface-container-high`; у `filled`
  контейнер уже лежит на `surface-container-highest` — ступеньке вверх идти некуда, поэтому
  там зона рисуется state-layer'ом поверх.
- Появился настоящий **state layer**: `::after` в собственных чернилах элемента с opacity
  8% / 12%, а не подмена `background-color`. Тон под ним продолжает просвечивать.
- Подключён `v-ripple` из `directives/ripple.ts` — на всех четырёх кнопках и на триггере
  единиц.
- Колонка stacked разделена **зазором**, а не правилом: в шов видно поверхность контейнера.
- Unit перестал быть тинтованной коробкой с рамкой — это обычный текст `on-surface-variant`;
  форму и state layer получает только триггер, потому что он единственный тут контрол.

**Радиус зоны едет по существующему `rounded`, на тир круглее контейнера.** Поэтому
`rounded="pill"` превращает зоны в таблетки и даёт вид «MD3 Expressive» без второй
реализации и без новой оси пропов; `rounded="small"` остаётся плотным видом для форм.

Отдельно: зоны сдвинуты вниз на `(filled.input.padding.top − filled.input.padding.bottom) / 2`.
Значение в filled-поле лежит ниже центра коробки, потому что верх занят поднятым лейблом —
зона едет за цифрами, а не за коробкой. Это ровно та жалоба «иконки по центру, а сам input
нет», выраженная выводимой величиной, а не подобранной константой.

**Не проверено глазами.** Вся эта правка чисто визуальная, а тесты проверяют DOM и классы,
не CSS. Смотреть на `docs_v2/app/pages/lab/number-input.vue` — там теперь есть переключатель
`rounded`, чтобы сравнить плотный вид с pill.

## Отложено (помечено, не сделано)

- **Segmented digits** из спеки не делается: это `<MOtpInput>`, он уже есть.
- **Slider-bound** выброшен по решению — сборка range + числа остаётся за потребителем.

## Расхождения (осознанные)

- **Фокус — только цвет рамки** (`border-color → primary`, ширина 1rem неизменна), как у
  переписанного `MTextarea`. `MTextField` пока продолжает утолщать рамку до 2rem с
  компенсацией паддинга — расхождение внутри семейства, снимается вместе с будущим
  объединением field-слоя.
- **Значение в split выровнено по левому краю**, а не по центру, как нарисовано в спеке:
  под плавающим лейблом центрировать нечего. Правило спеки про табличные цифры это
  разрешает («left-aligned when it sits alone»).
- **Support-строка рендерится по `v-if`**, а не резервирует высоту (как у textarea) —
  паритет с `MTextField`; в плотной таблице настроек постоянная строка под каждым полем
  дороже, чем редкий reflow.
- **Density (sm/md/lg) не реализована** — это ось всего семейства полей.

## Что осталось

- `FieldRoot` (`components/fragments/field/root.vue`) теперь **не импортируется никем**.
  Не удалён: решение об объединении field-слоя за тобой.
- Поднятый лейбл у `outlined` наполовину выходит за верхнюю границу контейнера, а у корня
  нет `padding-top`. Ровно так же ведёт себя standalone `MTextField` — расхождения нет, но
  в браузере это стоит посмотреть на обоих сразу.
- Демо-страница `docs_v2/app/pages/lab/number-input.vue` переписана (варианты
  filled/outlined/ghost, флаги unit/scrub/helper/disabled/readonly/error, карточка
  «Slider-bound» заменена на «Scrub»), но в браузере не проверялась — dev-сервер не запускался.
- В `docs_v2` четыре падающих теста (`basic-playground`, `component-catalog` locale parity,
  `components-drawer`, `home-content`) — те же, что были до этой задачи, к number-input
  отношения не имеют.
