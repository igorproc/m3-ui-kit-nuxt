# M3-polish · группа «Поля» (w3) — MTextField, MTextarea, MNumberInput

Аудит: `.cursor/handoff/m3-polish/audit/fields.md`. Решения по развилкам — оркестратор по рекомендации (2026-10-18).

## Решения
- Q-1 (оси на приватных `--ui-*`) и Q-12 (`MNumberInputUnit` публичный) — **СТОП, к владельцу**; ничего не менялось.
- Q-2 → read-only отвечает на hover во всей семье (Compose: `readOnly` не меняет цвета); фокус показывает и лейблом.
- Q-3 → поднятый лейбл (filled float, inset, underline) выводится из токенов: центр = верх значения − 9
  (половина строки body-large × 0.75); 15 / 9 / 19 для default / compact / comfortable.
- Q-4 → строка поддержки в 4 от коробки (было 8: gap 4 + margin 4).
- Q-5 → контракт «лейбл рядом с prepend начинается там, где значение» во всей семье (text-field 52,
  textarea inset + 28, number-input inset + 32).
- Q-6 → поднятый лейбл textarea 12 (body-large × 0.75), как у семьи.
- Q-7 → переход высоты textarea убран: одна мгновенная механика.
- Q-8 → скраб логический: к концу строки — больше (в RTL влево), как клавиши слайдера кита.
- Q-9 → ручка textarea в покое `outline` (≥ 3:1).
- Q-10 → ряд чипов зарезервирован: хук — наличие слота `#leading-content`; `__leading` держит высоту чипа (32).
- Q-11 → `defineExpose({ control, input })` у всех трёх (`MFieldParts<Input>` стал generic).
- Q-13 → выбранная единица остаётся `secondary-container`.
- Q-14 → `ui-textarea--populated`, `--composer` удалены.
- Q-15 → общая строка поддержки — SCSS-миксины, не компонент.
- Q-16 → одна логика ошибки: внутренний `utils/text-field/useFieldValidation` для трёх control-композаблов;
  `useTextField` удалён из автоимпорта.
- Q-17 → зоны filled остаются на индикаторе; описание в карте исправлено (история в craft §1 — у оркестратора).

## Что сделано
**MTextField** (`components/ui/text-field/{index.vue,props.ts}`, `composables/text-field/useTextFieldControl.ts`,
`assets/stylesheet/components/text-field/{_index,_label,_states,_parts,_family}.scss`)
- Слоты читаются в рендере (`hasPrepend/hasAppend/hasLeading/hasRow`, `rootClasses`) — первый чип в пустом
  multiple-dropdown появляется (был «замороженный» `computed` по `useSlots()`).
- Коробка — цель нажатия: `utils/text-field/boxPress.ts` (`pointerdown` → фокус контрола, `click` → проброс на
  контрол; кнопки, ссылки, `label`, `[tabindex]` в слотах не трогаются). Та же механика у textarea и number-input.
- Hairline `max(1px, 1rem)`; паддинги ряда через `calc()` — поле с prefix/suffix/чипами больше не выше голого.
- Лейбл: центр на значении (Q-3), комнаты по `--prepend/--append` (`label.room.*`), underline + prepend от начала
  значения; на notch лейбл у начала контента без translateX-сдвига (ушли `--ui-text-field-label-notch-shift`,
  `--ui-text-field-label-raised-*`, `--ui-text-field-start`); вырез открыт не шире комнаты лейбла.
- Ряд с `#leading-content`: `contain: inline-size` (чипы не расширяют поле), `__leading` высотой чипа, пустой — без отступа.
- `text-overflow: ellipsis` у значения; поддержка в 4; `margin: 0` строки поддержки (у `<p>` был UA-отступ 12 снизу).
- Правила индикатора filled и underline — один набор (`:is(--filled, --underline)`), hover — один `can-hover`.
- `defineSlots` (`MTextFieldSlots`, `MFieldMessageSlotProps`); сняты `rounded`, `MTextFieldRounded`,
  `RETIRED_ROUNDED_TO_SHAPE`, `useFieldShape`, `populated`, `type="number"`, `loading` (в `mFieldProps` только `disabled`).

**MTextarea** (`components/ui/textarea/{index.vue,props.ts}`, `composables/textarea/{useTextareaControl,useTextareaResize}.ts`,
`assets/stylesheet/components/textarea/{_index,_label,_parts,_states}.scss`)
- Без перехода высоты; ручка: `outline`, hover/нажатие/перетаскивание (слой 8/12/16) только у интерактивной,
  фокус-цвет после hover; метрики строки снимаются один раз на жест.
- Read-only отвечает на hover; поднятый лейбл 12 на значении (центр 15, значение с 24); prepend/append-комнаты.
- Hairline для рамки и `frame` — filled и outlined одной высоты на 360/1280; поддержка в 4.
- `defineSlots` (`MTextareaSlots`), `defineExpose({ control, input })`; удалены мёртвые токены
  (`label.gap`, `input.rows`, `grip.band`, `state.grow`), мёртвая `line-height`, классы `--populated/--composer`.

**MNumberInput** (`components/ui/number-input/{index.vue,props.ts}`, `composables/number-input/{useNumberInputControl,useNumberScrub}.ts`,
`assets/stylesheet/components/number-input/{_index,_label,_parts,_states}.scss`)
- Смещение «зон за значением» — только у split-зон: половинки stacked больше не сжаты до 7.5rem.
- Единица едет за значением (`margin-top` = дисбаланс паддингов) — на строке цифр.
- Read-only: фокус лейблом и hover; скраб логический в RTL; prepend-лейбл от начала значения; на notch лейбл у
  начала контента, вырез по видимой ширине; `:autofill` общей механикой (литералы `600000s` ушли).
- Hairline (шов stacked ≥ 1px); поддержка в 4; мёртвые токены (`container.height`, `label.left`, `label.active`,
  `stepper.split.width/height`, `stepper.stacked.height`, `scrub.gap`) и класс `--interactive` удалены.
- `defineSlots` (`MNumberInputSlots`, `MNumberInputStepperSlotProps`), `defineExpose({ control, input })`.

**Семья** — `text-field/_family.scss`: `shape-axis`, `autofill`, `notch`, `support-line`, `support-glyph`;
`utils/text-field/{boxPress,useFieldValidation}.ts`; масштаб лейбла в RTL — одна механика (`:dir(rtl)`).

## Ломающие изменения и миграция
- `rounded` → `shape` (`sharp→none`, `small→extra-small`, `pill→full`); `useFieldShape` удалён — `props.shape`.
- `populated` удалён (ничего не делал). `type="number"` у `MTextField` — `<MNumberInput>`.
- `loading` больше не в `mFieldProps` (поля его не читали); dropdown объявляет свой.
- `useTextField` (автоимпорт) удалён; поведение — через `useTextFieldControl` / `useTextareaControl` /
  `useNumberInputControl`.
- `MNumberInput` expose `{ element }` → `{ control, input }`; `MTextarea` теперь отдаёт `{ control, input }`.
- Классы: `ui-text-field__support--helper/--error` → модификатор корня `--error`; `ui-textarea--populated`,
  `--composer`, `ui-number-input--interactive` удалены.
- Вид: лейбл filled/inset ниже (центр 15), поддержка ближе на 4, у `MTextField` пропал случайный нижний отступ 12
  строки поддержки — формы из полей станут плотнее; underline: значение опущено под лейбл (как filled).

## Открытые вопросы
- Q-1 (оси на `--ui-*` против `decisions.md`) и Q-12 (`MNumberInputUnit`) — владелец.
- Лейбл стоит от внешнего края коробки, значение — внутри рамки: расхождение в один hairline (1–1.5rem), было и раньше.
- Смена темы (FAM-3): переходы цвета догоняют страницу ≈165 мс — общекитовое, контроллер темы.

## Риски и долги
- `contain: inline-size` на ряду с чипами: в auto-контекстах (таблица, flex без basis) поле с чипами просит ширину
  минимума input (60rem) — уже, чем было; ширину задаёт контейнер.
- `:empty` у пустого `__leading` полагается на то, что пустые якоря фрагментов Vue не считаются содержимым (Chromium).
- Словарь ролей карт (`filled.indicator.*` против `filled.border.*`) не сведён — миксины его не требуют.

## Дополнение 2026-10-19 — строка поддержки только когда ей есть что сказать (решение владельца)
- Правило: строка (и её `role="alert"`) рендерится, только если есть `helperText`, `path`, `required`, слот
  `#helper`/`#error` или родитель передал `error`/`errorMessage` (даже пустыми). Хелпер
  `utils/text-field/supportLine.ts`: `useBoundProp()` (ключ в `vnode.props`, camel/kebab, читается в рендере —
  первый кадр SSR верный, поздняя привязка тоже видна) и `useSupportLine(props, slots)`. Поля: MTextField,
  MNumberInput (`v-if` на строке), MTextarea (`v-if` на ряду; ряд остаётся и ради счётчика).
- Композиты — только проброс пропов ошибки (`fieldError()`): dropdown, autocomplete — если потребитель привязал
  `error`/`errorMessage` или задан `path`; file-input — то же или есть отказ файла; color-input — привязано или
  введённый цвет нечитаем; date-picker/input — `invalid` или отклонённая дата. form-renderer передаёт `path` —
  резерв по пути, правка не нужна. MColorPicker `Edit.vue:13-14` по-прежнему привязывает `error`/`errorMessage`
  всегда — его поле значения сохраняет резерв (файл не из разрешённого списка).
- Тесты: unit — без всего строки нет; резерв для helper/path/required/пустого `errorMessage`/`error=false`/слотов;
  при привязке ошибка встаёт в ту же строку; MDropdown без пропов — без строки, с привязанным — со строкой; спеки
  number-input/textarea переписаны под правило; file-input — строка уходит вместе с отказом. e2e обновлены (свои:
  высота строки по `helper-*`, alert-тест number-input, геометрия, ink disabled-композера), **не прогонялись** —
  дирижёр остановлен, пойдут в финальном прогоне.
- docs/system: `decisions.md` (новая запись) и `color-and-state.md` — обе локали.
- Гейты: eslint 0, stylelint 0, lint:scss 154/0 deprecations, typecheck — ошибки только `playground/render/**`,
  vitest семья + композиты + color-picker — 22 файла, 499 passed.
- Владелец подтвердил: у композитов с собственной проверкой строка появляется вместе с ошибкой. MColorPicker
  `fragments/color-picker/Edit.vue` — поле значения передаёт `error`/`errorMessage` (`fieldError()`) только при
  нечитаемом значении: пустая строка под полем ушла. Спека `ui/color-picker/index.spec.ts` — после Escape строки
  нет; комментарий в `color-picker.e2e.ts` поправлен. Гейты: eslint 0, typecheck (только `playground/render/**`),
  vitest color-picker + color-input 31 passed.
