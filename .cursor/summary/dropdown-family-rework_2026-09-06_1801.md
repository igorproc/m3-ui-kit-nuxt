# Семейство выбора: `MDropdown` — родитель, `MAutocomplete` — он же плюс фильтр

**Дата:** 2026-09-06
**Репозитории:** `kit` (дропдаун, автокомплит, список, общий движок, доки системы), `docs_v2` (три места использования + манифесты)
**Основание:** `docs/system/decisions.md` → «`<MDropdown>` keeps its own `variant` for now… revisit when the dropdown rework begins». Эта задача и есть та переработка.

## Что решено

`MDropdown` — **базовое поле выбора**: коробка поля, панель-listbox, single/multiple,
чипы, очистка. `MAutocomplete` = он же **плюс запрос**: фильтр, черновик ввода, IME.
Два самостоятельных компонента поверх одного композабла — не обёртка над обёрткой и не
два движка.

| Ось | Решение |
|---|---|
| Семья | `mFieldProps` + `fieldDensityProp`; собственный `MDropdownVariant` удалён |
| `variant` | `Extract<MTextFieldVariant, 'filled' \| 'outlined'>` — сужение, не новый юнион |
| `items` | `TItem extends { id }`; `itemTitle`→`'label'`, `itemValue`→item целиком, `itemDisabled`→`'disabled'`; `itemKey` не существует |
| Идентичность | дефолтный `valueComparator` сравнивает объекты по `id` |
| Выбор | `multiple`, `mandatory`, `max`, `clearable` |
| Панель | `menuPlacement`, `maxHeight`, `loading`, слот-эскейп `#default` |
| Плотность | доезжает до строк: `MList`/`MListItem` получили свою `density` |

## Три развилки, которые стоит перечитать

### Выбор идёт от модели, а не от реестра

Планировалось взять `useSelectionGroup` — он уже умеет `multiple`, `max`, `mandatory`,
comparator и двусторонний мост с моделью. При чтении кода выяснилось, что для поля он
структурно не подходит:

```js
// useSelectionGroup.ts — обратный watch
watch(selected, (values) => {           // selected собран из тикетов
  if (!sameValues(current, values)) emitModel([...values])
})
```

Поле держит значение раньше, чем держит опции: форма грузит `countryId`, список приезжает
через два тика. Пока опции не зарегистрировались, `selected` короче модели — и этот watch
отдаёт укороченный массив обратно потребителю. Значение молча теряется.

Поэтому `useDropdownSelection` **model-first**: модель — истина, строки — её проекция.
Значение, которого нет в `items`, остаётся в модели и рисуется из запасной строки (её
title резолвится тем же резолвером, потому что по умолчанию value и есть item). Побочно
это чинит `[object Object]`, который автокомплит показывал для такого значения.

`useSelectionGroup` не тронут — он остаётся движком `MSelectionGroup`, где дети
монтируются вместе с данными и разрыва нет.

### Порядок — из данных

`createRegistry.register` кладёт тикет в конец (`index = registration.index ?? size`).
Элемент, вставленный в середину смонтированного списка, оказывается последним в реестре,
стоя третьим в DOM, — и стрелки идут не туда. Строки и так рисуются `v-for` по массиву,
поэтому порядок берётся из массива, а через контекст дети отдают только своё состояние.

### `max` выключает строки для клавиатуры

`entry.disabled = itemDisabled || blocked` — заблокированные лимитом строки выпадают из
обхода стрелками и получают `aria-disabled`. Выбранные при этом не блокируются: снять
выбор — единственное законное действие на лимите. APG допускает оба поведения, выбран
этот.

## Плотность в списке

`lines` — форма контента, `density` — масштаб. Матрица 3×3 генерится `@each`, числа
взяты дельтами семьи полей (−12 / +8 от дефолта), чтобы строка и поле совпадали:

```
compact      44 / 60 / 76      (44 = compact-поле)
default      56 / 72 / 88      (без изменений)
comfortable  64 / 80 / 96
```

Меняется только `min-height`: вертикальные паддинги оставлены как были, потому что высоту
и так держит `min-height`, а трогать их значило бы менять вид всех списков кита.
`MList` провайдит ось вниз, проп на строке перекрывает; `density` на самой строке —
`undefined` по умолчанию, и отсутствие здесь значит «наследую».

Оба файла списка заодно переведены на точечные пути `g()` (правило «конвертировать файл
целиком при касании»).

## Ломающее

- проп `options` удалён — но форма `{label, value}` больше не подходит и по другой причине: `id` обязателен;
- массивы примитивов в `items` больше не поддерживаются (было у автокомплита);
- `variant="underline"` невалиден у обоих компонентов;
- `menuOrigin` → `menuPlacement`;
- `itemKey` удалён (идентичность — всегда `id`);
- слоты дропдауна: `#default` теперь вся панель, `#item` — тело строки, `#selection` — весь блок чипов, `#chip` — один чип; у автокомплита `#selection` сменил смысл с «один чип» на «весь блок»;
- `role="combobox"` переехал с `div`-обёртки на реальный `<input>`;
- валидация (`path`) теперь связывает **выбор**, а не отображаемую строку: раньше адаптер получал `"Two"` там, где форма ждала `2`.

## Допущения и риски

- **Глазами не смотрел.** Правка тяжёлая по CSS, а тесты читают DOM и классы. Особенно
  стоит проверить: чипы в поле при `multiple` (высота коробки), `compact`-панель под
  `compact`-полем, и `outlined` + чипы.
- **`MListItem` используют меню, навигация и таблица.** Дефолтная ветка плотности даёт те
  же 56/72/88, но специфичность селектора выросла с одного класса до двух — если где-то
  высоту строки перебивали снаружи одним классом, это перестанет работать.
- **Порядок чипов** теперь порядок значений в модели (как и было), но `selectedEntries`
  строится по модели, а не по `items` — при `multiple` чипы идут в порядке выбора.
- Дефолт `itemValue` = item целиком: у потребителя, который ждал скаляр, в модели окажется
  объект. Это осознанное решение, но самое заметное на практике.

## Страница документации

Проверять компонент было негде, поэтому в `docs_v2` собрана полноценная страница
`/components/dropdown` (5 секций, 14 блоков) — и два **новых типа блока**, которых в
системе не было.

### `matrix` — две оси сразу

Рендерит один и тот же `*-interactive`-renderer в сетке «строка × колонка» с подписями
осей. Для дропдауна это `variant` × `density`: шесть живых полей, в которых видно ровно то,
что не видно на одиночной демке, — как `compact` садится под `outlined` и куда при этом
уезжает плавающий лейбл. Блок общий: любая пара пропов у любого компонента.

### `keyboard-map` — карта клавиатуры, которая отвечает

Слева живой компонент, справа список биндингов. Нажал клавишу в поле — подсветилась строка,
которая эту клавишу за собой числит, и её имя появилось в подсказке (состояние не держится
на одном цвете). Не подсветилась — значит карта врёт, и это видно сразу, без чтения кода.

Оба зарегистрированы честно: тип в `shared/types/docs.ts`, правила в **обоих** валидаторах
(`scripts/validate-docs.mjs` для сборки и `server/schemas/docs.ts` для рантайма), компонент
в `app/components/docs/block/`.

### Что ещё на странице

`anatomy` с выносками по живому DOM (панель телепортируется, поэтому названа без линии),
`interactive-demo` со всеми осями, `states`, `example-gallery` из четырёх сценариев
(одиночный, `max`, асинхронная загрузка с предустановленным значением, своя панель через
`#default`), `usage`-блоки про поведение и выбор компонента, `accessibility`, плейграунд с
кодогенерацией, `token-map` и API.

Новые файлы в `docs_v2`: 6 примеров (`dropdown`, `-interactive`, `-async`, `-limit`,
`-panel`, `-anatomy`), плейграунд, два блока, токен-манифест `server/content/tokens/dropdown.json`,
контент `en`/`ru` и `tests/dropdown-page.spec.ts` (9 тестов: схема, покрытие секций, рендер
всех блоков через реестр, матрица, клавиатурная подсветка, живой выбор в демке).

Заодно починены шесть примеров автокомплита, которые падали под новым контрактом `items`
(строки вместо объектов с `id`).

**Как посмотреть:** `npm run dev` в `docs_v2` → `/components/dropdown` (страница открывается

## Три бага, найденные на странице

Страница окупилась сразу: всё три нашлись глазами за первые минуты.

### Панель открывалась под helper-text

`MMenu` брал якорем `anchorRef.parentElement`, то есть **корень дропдауна**, а в его
коробку входит строка поддержки. Панель вставала под ней — с зазором ровно в высоту
подсказки.

Починено на уровне контракта, а не сдвигом: `MTextField` теперь отдаёт наружу
`defineExpose({ control, input })`, у `MMenu` появился необязательный проп `anchor`
(по умолчанию — прежний `parentElement`, так что остальные потребители не тронуты), а
дропдаун и автокомплит якорятся к **нарисованной коробке**, а не к корню.

### Backspace не снимал чип

Чип — настоящая `<button>`. Клик по нему (или Tab) уводил фокус с инпута, а обработчик
клавиатуры висел только на инпуте, поэтому после этого не работало вообще ничего.

Две правки: чипы больше не забирают фокус указателем (`@mousedown.prevent`), и на корне
поля появился запасной `@keydown`, который ловит нажатия, начавшиеся **не** на инпуте.
Событие с самого инпута он пропускает, иначе один Backspace снимал бы два чипа.

**Дополнено:** в одиночном режиме Backspace и Delete теперь очищают значение — у селекта
нет текста, который они могли бы стирать, поэтому клавиша уходит к самому значению.
`mandatory`, `disabled` и `readonly` её держат, а у автокомплита она по-прежнему правит
текст: очистка с клавиатуры включается только для нередактируемого поля.

### Лейбл наезжал на чипы, плейсхолдер не выключался

Асимметричный паддинг, который освобождает место плавающему лейблу, применялся только к
`.ui-text-field__input`. Чипы живут не в инпуте, а в строке `.ui-text-field__field` рядом
с ним, — и оставались по центру коробки, ровно под поднятым лейблом.

Правило переехало на ту строку, над которой лейбл на самом деле стоит: голый инпут
(`__control > __input`) **или** строка с чипами (`__field`).

Заодно: плейсхолдер теперь исчезает, как только что-то выбрано. Проверка `populated`
массив учитывала правильно — виноват был не `if`: под плавающим лейблом плейсхолдер
показывается по `data-populated`, то есть становился видимым именно тогда, когда сказать
ему уже нечего.

### Поле не показывало фокус

Клик мог прийтись на коробку, лейбл или стрелку — ни один из них не фокусируем, — поэтому
поле открывалось, значение выбиралось, а фокуса у комбобокса не было вовсе. Это не только
пропавшее кольцо: без DOM-фокуса `aria-activedescendant` указывает из ниоткуда, и для
скринридера навигации по списку просто нет.

Теперь при открытии панели фокус ставится на инпут; панель глотает `mousedown`, поэтому
после выбора мышью он там и остаётся.

### Крестик очистки всегда горел primary

`MButtonIcon` наследует `color: 'primary'` из `makeColorProps()`, и текстовый вариант красит
им контент. Но `primary` по [color-and-state.md](../../docs/system/ru-RU/color-and-state.md)
принадлежит **активности**, а лежащий крестик — это аффорданс, а не действие.

Токены `clear.color` / `clear.active-color`: в покое `on-surface-variant` (как стрелка
рядом), на hover и focus-visible — `on-surface` плюс собственный слой состояния кнопки. То
же у автокомплита, там ещё и кнопка-стрелка. Селектор повторяет `.ui-button` дважды, чтобы
перебить двухклассовое правило кнопки не полагаясь на порядок стилей.

**Тесты:** +10 в ките (клавиатура с чипа, отсутствие двойной обработки, выбор якоря,
плейсхолдер, очистка на Backspace/Delete, `mandatory`, пустое поле, фокус при открытии,
фокус после выбора мышью) — 1087 зелёных.

## Осталось

- **Кламп панели по вьюпорту** — отдельная задача по `MMenu`/`usePopover`: поле у нижнего
  края экрана всё ещё роняет часть панели за границу, `maxHeight` от этого не спасает.
  Правка общая для menu / tooltip / popover.
- `MList` по-прежнему красит `container-color` — для панели это лишний слой поверх
  поверхности меню; не трогал, потому что это касается всех списков.
- Строки-нон-опции в панели (заголовки групп, разделители) не поддержаны: сейчас панель
  либо своя целиком через `#default`, либо плоский список. Группировка ждёт своего
  заказчика.
- В `docs_v2` остаются три падавших до задачи теста (`basic-playground` — в нём не
  резолвится `m-card`, `home-content`, и `component-catalog`, который ловит `app-bar`:
  у него в секции reference нет блока `token-map`). Ни один к семейству выбора не относится.
