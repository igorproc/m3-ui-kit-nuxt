## Ключевые выводы

- Почти ничего из отложенного нет в M3. Из M3 только carousel (есть на сайте) и pull-to-refresh
  (есть в Compose). Остальное — авторские компоненты: их вид выведен из системы M3.
- **Stepper.** Роль завершённого шага по таблице ролей кита — `outline` + галочка, не
  `primary`, как в M2: `primary` закреплён за активным шагом (вопрос 1).
- **Treeview.** Строка — это `MListItem` из плана list. Выбор рисуется глифом чекбокса без
  вложенного `input`.
- **Window** — поведенческая основа. Предложено одно слово `mount` для политики монтирования,
  общее с панелями tabs.
- **Calendar** строится на сетке date-picker, а не дублирует её.
- **Parallax.** Прежний JS-фолбэк противоречит решению «без механизмов, растящих бандл». Вынесен
  в вопрос, рекомендация — только CSS scroll-driven или отказ.
- **Empty state.** Сначала общий фрагмент для слотов `#empty` (table, list, dropdown…), потом
  публичная обёртка.
- **Slide group** — примитив прокрутки (`useScrollOverflow`) без собственного выбора, чтобы не
  появился третий контракт выбора.
- **Графики.** Роли кита как одновременные ряды неразличимы (ΔE 5,2 при пороге 15), что
  подтверждает прежний отказ от нескольких рядов. Прежнее `type` нарушает ОВ-2, предложено `mark`.
- **Hover/focused.** VueUse `useElementHover` не годится: залипает на таче. Предложен общий
  помощник для `MTooltip` и `MLazy`.
