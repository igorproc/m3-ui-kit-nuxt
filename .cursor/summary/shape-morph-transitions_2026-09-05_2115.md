# Shape morph: transitions as mathematics

**Дата:** 2026-09-05
**Область:** `utils/motion/*` (новое), `utils/morph/*`, `useShapeMorph`, `MShape`, `MLoading`, `docs_v2/app/pages/lab/shape.vue`

## Зачем

Морф форм читался «спокойным». Разбор показал пять причин, из которых easing — только одна:

1. `easeM3Standard = 1 − (1−t)⁴` — скорость максимальна в нулевой момент и только падает. Нет фазы **нарастания** ускорения, а именно её глаз читает как рывок. У `cubic-bezier(0.2,0,0,1)` скорость нарастает до пика на ~12% времени.
2. `createPathInterpolator` глушил любой заброс: `if (t >= 1 − EPSILON) return toD`. Пружина пересекает 1 на середине полёта — отскок съедался целиком.
3. Площадь контура не сохранялась: круг → клевер визуально «сдувался» в середине.
4. `duration: 600` против `useTimer(1000)` в loading → 400 мс мёртвой зоны каждый цикл.
5. Вращение было отдельным CSS `linear infinite 4s`, не связанным с деформацией.

## Что сделано

### `utils/motion/` — движение как математика

```
shared/    types · spring (замкнутая форма) · define · resolve · reduced-motion
standard/  tokens (md.sys.motion, v34.0.21) · bezier (CSS-решатель) · transitions: calm, standard
expressive/ transitions: expressive, bouncy
```

Граница: `standard/` — буква спеки M3, `expressive/` — надстройка ради живости, `shared/` — общая математика.

**Пружина задаётся двумя числами, длительность выводится:**

| transition | ζ / k | duration | overshoot | rotate |
|---|---|---|---|---|
| `calm` | 1.0 / 1600 (M3 effects) | 231 мс | 0 | 0° |
| `standard` | 0.9 / 700 (M3 spatial) | 325 мс | 0.15% | 0° |
| `expressive` **(дефолт)** | 0.6 / 380 | 610 мс | 9.5% | 60° |
| `bouncy` | 0.45 / 600 | 637 мс | 20.5% | 90° |

Столбец `rotate` — пиковая амплитуда замаха, не накопительный угол.

Формулы: `ω₀ = √k`; недодемпфированный `x(t) = 1 − e^(−ζω₀t)(cos ω_d t + (ζω₀/ω_d) sin ω_d t)`; settle `T = ln(A/ε)/(ζω₀)`, `A = 1/√(1−ζ²)`; overshoot `e^(−πζ/√(1−ζ²))`.

**Свои переходы:** `defineTransition({ spring, rotate, preserveArea, hold })`, либо `{ easing: cubicBezier(...) }`, либо готовая функция. `MorphTransitionInput = имя | опции`.

**Tree-shaking:** `resolveTransition` не ссылается на `standard/bezier` — все именованные переходы пружинные. Проект на пружинах физически не тянет bezier-решатель. Замеры (esbuild min + gzip): spring 436 B, bezier 351 B.

### `utils/morph/`

- `area.ts` — формула шнурков (Green's theorem) + масштабирование кольца к целевой площади.
- `plan.ts`/`types.ts` — площади обоих концов считаются один раз при сборке плана.
- `interpolate.ts` — 4-й аргумент `preserveArea`: результат подгоняется к `lerp(areaA, areaB, t)`. На концах коррекция ровно 1 → каноническая геометрия не тронута.
- `index.ts` — опции `preserveArea` и `snapEnd`. `snapEnd: false` нужен для пружины: иначе пересечение цели на середине полёта замораживает морф.

**`align.ts` не тронут.** Доворот вынесен из ядра целиком: он применяется трансформом к элементу, не к геометрии пути, поэтому произвольный угол не мешает морфу приходить в канонический `d`.

### Доворот — замах, а не накопление

Первая версия копила угол (`rotateTo = rotateFrom + rotate`), и форма замирала под произвольным углом: после трёх морфов ghost стоял под 180°. Исправлено на **замах**: `shared/velocity.ts` численно дифференцирует кривую и нормирует пик к 1, угол = `амплитуда × скорость(t)`.

Почему по скорости, а не по прогрессу: пик приходится туда, где деформация самая резкая (у пружины — первые ~60 мс), поэтому крен читается **до** отскока; к затуханию скорость сама уходит в 0, и форма всегда приходит в покое ровно; у пружины скорость меняет знак на возврате, так что крен качается вместе с ней. Работает для любой пользовательской кривой, не только для пружины.

### Композабл и компоненты

- `useShapeMorph` — опция `transition` вместо `easing`; возвращает `rotate` (текущий угол крена, 0 в покое) и резолвнутый `transition`. `prefers-reduced-motion` → мгновенный снап без накопления угла.
- `MShape` — пропы `transition`, `duration` (override); угол применяется как `transform: rotate()`.
- `MLoading` — проп `transition`; интервал цикла = `duration + hold` (мёртвая зона убрана); CSS `linear-rotate` для `expressive` снят — вращение теперь несёт сам переход.

## Допущения и что осталось

- **Дефолт морфа сменился** на `expressive` (был quartic 600 мс). Любой `<m-shape>` теперь морфит пружиной и кренится с пиком 60°, возвращаясь в 0. Нужен визуальный прогон — числа подбирались по формулам и описанию гифки, не по глазу.
- `MLoading type="expressive"` больше не крутится равномерно через CSS. При `transition="calm"` (rotate = 0) вращения не будет вовсе.
- `easeM3Standard` оставлен экспортом с `@deprecated`, чтобы не ломать импорты.
- `docs_v2` подключает kit через `dist` (симлинк на пакет), поэтому после правок в `src` нужен `npm run build` в `kit`.
