# MSearch v2: полный M3-поиск (2026-10-20)

## Что и почему

MSearch был половиной M3-поиска: строка без вида результатов, фокус и слои не как у соседей, мимо осей кита.
Решения владельца 2026-10-19/20 (план `.cursor/plans/feature/components-should-update/inputs/search.md`, v2.1):
- полный M3-поиск: строка + вид результатов на движке MDropdown;
- docked-вид — строка остаётся и становится шапкой, под ней `MMenu`, одно поле ввода;
- результаты — публичные `MSearchList` / `MSearchListItem`; `items` остаётся сокращением;
- виды `docked` и `inline`; полноэкранный поиск кит не открывает — это решение приложения;
- аватар и навигация необязательны;
- открытые вопросы закрыты рекомендованными вариантами («давай сделаем поиск уже»): density = ступени полей,
  вид только с содержимым, `removable` + Delete без ↖, общий фильтр, выбор пишет заголовок в запрос,
  недавние хранит приложение.

## Ломающие изменения (без шимов)

- `clearLabel` → `messages.clear`.
- `v-model:focused` удалён.
- Строка переехала с корня в `.ui-search__bar`; корень держит строку и вид.

## Ключевые механики

- `useSearchControl`: модель — запрос; выбор строки пишет её заголовок в запрос и испускает `select(value)`;
  Enter без активной строки — `submit`; Esc: закрыть вид → очистить → отпустить; Delete удаляет активную
  `removable`-строку; IME не читается.
- Docked-панель рендерит строки только открытой; открытый вид, которому нечего показать, закрывается в том же
  такте (post-flush), до отрисовки.
- Inline-вид скрывается через `:has()` по наличию строк — верен с первого кадра SSR; без `:has()` — JS-модификатор
  под `@supports not`.
- Без вида строка — обычное поле поиска, не combobox.
- Кольцо фокуса — только с клавиатуры (указатель распознаётся по `pointerdown`).
- Слой hover гаснет над вложенной кнопкой (`:has()`, прогрессивное улучшение).
- Переопределение поверхности `MMenu` — составным селектором `.ui-search__menu.ui-menu .ui-menu__surface`.

## Риски и что не сделано

- Docked-панель при нехватке места снизу переворачивается вверх (поведение `MMenu`), а нижние углы строки всё
  равно квадратные — подтверждено рендером (высокая панель с группами у нижнего края). У строки в шапке места
  снизу хватает; решение — в `MMenu` (запрет переворота или кламп высоты для пристыкованной панели).
- `MMenu` оборачивает listbox в `role="menu"` (A11-06): axe `aria-required-children` на открытом виде. Тот же
  дефект у MDropdown и MAutocomplete, там просто не проверялся. Тест поиска помечен `test.fail()` со ссылкой.
- `MMenu` без `appear`: меню, созданное уже открытым (`v-model:open` = true с первого кадра), не входит в top layer
  и не видно, а строка при этом в открытом состоянии. Открытие взаимодействием работает.
- Рендер концепта v2 всё ещё рисует полноэкранный вид, снятый решением владельца.
- Группы в панели MDropdown — отдельная задача плана dropdown (вопрос 7).
