## Эталон unit-тестов (обязателен для каждого компонента твоей группы)

Образец — `src/runtime/components/ui/textarea/tests/` и `number-input/tests/` (а также `dropdown/tests/`,
`otp-input/tests/`). Устройство:

- Папка `components/ui/<имя>/tests/` рядом с компонентом. Минимум три файла:
  - `variants.spec.ts` — **матрица**: каждая ось (`variant`, `color`, `density`, `shape`, `type`, размещение,
    режимы) через `it.each` по всем значениям; значения по умолчанию; сочетания, где они меняют разметку;
    слоты; классы-модификаторы состояний.
  - `interaction.spec.ts` — **поведение**: события и `v-model`, клавиатура (свой файл `keyboard.spec.ts`,
    если тестов много), disabled/readonly/loading, фокус, таймеры, SSR-первый кадр через `renderToString`
    там, где он важен.
  - `a11y.spec.ts` — **доступность явными проверками**: роль (нативная предпочтительнее), имя (label/
    `aria-label`/`aria-labelledby`) и dev-предупреждение без имени, состояния (`aria-checked`/`-pressed`/
    `-expanded`/`-selected`/`-current`/`-disabled`/`-invalid`/`-busy`), связи (`aria-describedby`,
    `aria-controls` на существующий id), скрытие декора (`aria-hidden`), live-регионы, порядок фокуса.
    **axe в unit не используем** — он остаётся в e2e.
- Общий `mount()`-хелпер в начале файла с `afterEach(unmount)`, как в textarea; describe — `'m-<имя> · variants'`
  и вложенные describe по оси/аспекту.
- Подкомпоненты (`tab`, `item`, `group`…) — свои describe в тех же файлах или свой `tests/` у подпапки.
- Старый `index.spec.ts` разбирается по трём файлам целиком (ничего не теряем) и удаляется.
- Композаблы/утилиты компонента — их спеки остаются рядом с ними (`composables/<x>/*.spec.ts`).
- Каждый тест проверяет ожидаемое поведение. Если тест показывает баг: пункт из одобренного списка —
  чини; вне списка — `it.fails(...)` нельзя, оставь тест с `it.todo('…')` и опиши баг в отчёте.
