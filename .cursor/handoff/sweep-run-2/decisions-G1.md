# Sweep run 2 · G1 «Выбор и формы» — решения по рекомендации

Оркестратор переносит в `docs/system/{en-US,ru-RU}/decisions.md`. Пункт → решение → причина.

| # | Пункт | Решение | Причина |
|---|---|---|---|
| G1-1 | Q28-Б: куда ставить строку поддержки у MCheckbox / MSwitch / MRadio | Корень — `<div class="ui-<x>">`, внутри `<label class="ui-<x>__field">` (инпут, контрол, подпись) и после него строка `ui-<x>__support` | Внутри `<label>` текст строки вошёл бы в доступное имя контрола и клик по подсказке переключал бы флажок |
| G1-2 | Q28-Б: имена слотов строки | `#helper` и `#error` со scope `{ message }`, как у семейства полей; пропы `helperText` / `error` / `errorMessage`; резерв — `useSupportLine` (правило 2026-10-19) | Один словарь для всей формы; план флажка предлагал `#support` — отклонено ради единообразия с полями |
| G1-3 | Q28-Б для группы радио (РВ-2) | Поле — `MRadioGroup`: строка поддержки у группы, `invalid` в контексте красит все радио, `aria-describedby`/`aria-invalid` на `role=radiogroup`; у радио в группе своей строки нет | Одна ошибка на набор, а не по одной под каждым вариантом |
| G1-4 | `MRadioGroup` и fallthrough-атрибуты | `inheritAttrs: false`: `class`/`style` — на корень, всё остальное (`aria-labelledby` и пр.) — на `role=radiogroup` | Корень теперь обёртка над группой и строкой; `aria-labelledby` демо orders иначе ушёл бы на `div` без роли |
| G1-5 | `name` группы радио | `name ?? path ?? useId()`; у одиночной радио `name ?? path` (B6.1c, A11-08) | Нативная группировка и стрелки работают без явного `name` |
| G1-6 | B6.10g | form-renderer рендерит `MRadioGroup :path :name` вокруг радио, а не `:name` на каждой | Одна привязка `useField` на поле вместо N на один `path`; одна строка ошибки |
| G1-7 | Круглое кольцо фокуса у MRadio | Кольцо на контейнере 40 со скруглением `full` | План radio (шаг 3) и W7-А: кольцо вокруг слоя 40 |
| G1-8 | S8: контракт миксина мишени | `@include touch-target($axis: both \| block, $size: 48, $pseudo: after)` в `abstracts/_mixins.scss`, только под `@media (pointer: coarse)` | modern-web (Q40): мишень растёт на грубом указателе; на мыши соседи не перехватывают клик. `block` — для icon-only в MButtonGroup (G6) |
| G1-9 | Слой состояний чипа (план, шаг 2) | Один `::before` цветом контента: hover 8 / focus 10 / pressed 12; фон не подменяется; у `--blocked` чипа слоя нет (раньше не было только у `--disabled`) | Заблокированный `max` чип на нажатие не отвечает — слой обещал бы действие |
| G1-10 | B8.9d: куда уходит фокус с удалённого чипа | Следующий в DOM, иначе предыдущий (среди не заблокированных) | Как у удаления строки в списке; фокус не падает на `<body>` |
| G1-11 | B8.10c: `toggleAll` под `max` | Если достигнут лимит — `unselectAll`, иначе `selectAll` до лимита | Под `max` «выбраны все» недостижимо, и `toggleAll` никогда бы не снимал выбор |
| G1-12 | N.9: имя ручек range без `ariaLabelStart/End` | Обе ручки берут `label`, dev-warning; английских «start»/«end» нет | Кит не поставляет английский текст (Q32-А) |
| G1-13 | Касание трека слайдера | Прыжок значения — на `pointerup`; `pointercancel` (скролл) прыжок отменяет; нажатие без движения завершается на отпускании | modern-web §3.2; заодно чинится застревание `--dragging` после клика по ручке без движения |
| G1-14 | B8.5 rating | `ariaLabel` без дефолта + dev-warning после mount без `aria-label`/`aria-labelledby`; `aria-valuetext` только из нового пропа `valueText(value, length)` | Без текста скринридер читает число; «N of M» — английский |
| G1-15 | B6.10c: кнопка без `submitLabel` | Рендерится пустой + dev-warning; слот по-прежнему заменяет кнопку | Q32-А: без английского дефолта |
| G1-16 | B6.1f: родитель держит `indeterminate` | После клика свойство `input.indeterminate` возвращается на `nextTick`, если `v-model:indeterminate` не принял `false`; `aria-checked` снят (modern-web) | Нативный контрол и модификатор класса не расходятся |
| G1-17 | B6.1b: вид ошибки у switch | Рамка трека и слой состояний — `error`, как у флажка; текст — в строке поддержки | «as checkbox» из рекомендации |
| G1-18 | B5.9b/d RTL | Слайдер: позиция ручки и заливки — `inset-inline-start`, математика и стрелки зеркалятся по `direction` трека в момент события; switch: `inset-inline-start` + `:dir(rtl)` без фолбэка | modern-web: `:dir(rtl)` без `[dir]`-фолбэка |

## P3 (ответы W1–W30 — «всё по рекомендации»)

| # | Пункт | Решение | Причина |
|---|---|---|---|
| G1-19 | W3-А: hover у слайдера | Меняется только курсор; слоя и value indicator на hover нет. **Отход от «пяти состояний» — внести в `decisions.md`** | M3/Compose hover у ползунка не рисуют; value indicator на hover нарушал WCAG 1.4.13 |
| G1-20 | W17-Б: имя оси удаления чипа | `removal: 'none' \| 'button' \| 'whole'` + `removeLabel` (без дефолта, dev-warn) + событие `remove` | Существительное-ось; `whole` = весь чип — кнопка удаления (как `remove-only` material-web и нынешний MDropdown) |
| G1-21 | W2-А: имя оси centered | `origin: 'start' \| 'center'`; на `range` не действует | Как в вопросе; ось с местом для `end` |
| G1-22 | Inset-иконка слайдера (шаг 5) | Иконка не переносится: две копии в начале трека, каждая обрезана своим сегментом (on-primary / on-secondary-container); положение через `cqi` трека (`container-type: inline-size`) | «Конфликты с правилами»: без `ResizeObserver`; первый кадр SSR верен; иконка читается на любом цвете |
| G1-23 | Тики дискретного слайдера | Элементы `span` (по одному на шаг) вместо `radial-gradient`; крайние зажаты в угол трека; stop indicator при тиках не рисуется | Роли по стороне (активная/неактивная) без масок; последний тик и есть stop |
| G1-24 | Сдвиг ручки switch | Оставлен `transform` (+ `:dir(rtl)`), а не `inset-inline-start` от центров из плана | Правило владельца «анимировать только transform»; RTL работает так же |
| G1-25 | Root MRadioGroup / MChipGroup / MRating / MSlider | Корень — обёртка (подпись, ряд/контрол, строка поддержки); `class`/`style` на корне, ARIA и прочие атрибуты — на `radiogroup` / `group` / `slider` / ручках | W9, W21–W22, W25, W4: имя и строка поддержки вне управляемого элемента |
| G1-26 | MFormRenderer: событие успеха | `submitted(values)` и `invalid(errors)`, а не `submit` | `onSubmit` — проп, и `emit('submit')` вызвал бы его второй раз (Vue ищет обработчик в props vnode) |
| G1-27 | MFormRenderer `v-model` | Модель засевает поля один раз (поверх `default`) и получает каждое изменение; внешняя смена модели после mount поля не переписывает | У `FormBinding` адаптера нет `setValues`; реактивная схема отклонена (Q36-А) |
| G1-28 | MFormRenderer `select` (W30-А) | `MDropdown` над `options` (`{ id: value, label }`, `item-value="id"`), вид поля `enum` | Значение формы — `value` опции |
| G1-29 | W19-А (тултип обрезанной подписи чипа) | Не сделано, ждёт G2 | `MTooltip` переделывается G2 (Q19-В, W37–W39); обёртка каждого чипа в текущий тултип — +teleport на чип |
| G1-30 | Слайдер не потребляет `rangeAttrs` | Сегменты строятся из `activeRange` композабла и флагов среза; `rangeAttrs` остаётся для своей разметки | `rangeAttrs` задаёт `inset-inline-start`/`width` одного элемента, а трек Expressive — три сегмента с зазором |
| G1-31 | Пункты планов, не сделанные | radio: геттер `value` в регистрации (реестр индексирует по значению — `browse()`); checkbox: прорисовка галочки `stroke-dashoffset` (глиф — `MIcon`); chip: generic `TValue`; form-renderer: сводка ошибок (`MAlert` у G2, у адаптера нет карты ошибок) | Каждое — отдельная правка вне текущего API |
