# Sweep run 2 · G5 (containment, данные, foundation) — решения для decisions.md

Оркестратор переносит в `docs/system/{en-US,ru-RU}/decisions.md`.

| Пункт | Решение | Причина |
|---|---|---|
| N.3 + N.4 (корень) | `overflow-wrap: break-word` вместо `anywhere` на корнях `MCard` и `MListItem` | `anywhere` наследуется в слоты и сводит min-content каждого слова к одному глифу: равные колонки (сегменты, ряд чипов) рвали слова. `break-word` переносит длинную строку у края, но min-content слова оставляет целым. Правки `.ui-chip` / `.ui-segmented-button` внутри карточки и строки больше не нужны. |
| B9.1 (Q46-А) | Статичная выбранная строка `MListItem` — `aria-current="true"` (на `li` в списке, на `div` вне его); с `role` от потребителя — ничего | `aria-selected` у `listitem` недопустим; иначе выбор передан только цветом. Ссылка — `aria-current="page"`, кнопка — `aria-pressed`, как раньше. |
| Q47-А | Подвал `MTable` остаётся приватным компактным фрагментом, не `MPagination` | Решено при создании MPagination; потеря фокуса (B9.2a) чинится общим механизмом мягкого disabled. |
| B9.2a (класс) | `<select>` размера страницы в подвале `MTable` при `loading` — мягкий disabled: `aria-disabled="true"`, модификатор `ui-table__page-size-select--disabled`, нажатие и клавиши (кроме Tab/Escape) не открывают и не меняют его, `change` откатывается | Как Prev/Next (Q24-А): нативный `disabled` у сфокусированного контрола роняет фокус на `body` на каждом запросе страницы. |
| B9.2b | «Выбрать все» в шапке `MTable` показывает частичный выбор страницы как mixed (`MCheckbox :indeterminate`, нативный `input.indeterminate`); активация mixed дополняет страницу | APG Checkbox (mixed). Считается по текущей странице: строки других страниц mixed не делают. |
| B9.3 | `MTimelineItem` с `variant` ≠ `plain` — модификатор `ui-timeline-item--contained`: отступы 12 / 16, угол `medium` (через `MSurface shape`), у всех «контейнерных» вариантов зарезервирован волосок края `max(1px, 1rem)` (рисует его только `outlined`); точка, время и концы рейки — на центре первой строки с учётом отступа и края | Без отступа текст лежал на краю заливки/рамки. Резерв края одинаков у filled/elevated/outlined, поэтому первая строка на той же высоте при любом варианте. |
| B9.4 | Волосок `max(1px, 1rem)` в картах `surface` (outlined) и `hotkey` (рамка клавиши) — локальная `$hairline` | `decisions.md` «A hairline is max(1px, 1rem)»; e2e на 360 px проверяет ≥ 1 px. В Chromium e2e проходит и до правки — движок сам доводит дробную рамку до 1 px; правка — для Firefox/Safari и по правилу. |
| B13.2a (вторая половина) | `MSurfaceVariant = Extract<MVariant, 'plain' \| 'filled' \| 'elevated' \| 'outlined'>` | Одна ось вариантов кита; `plain` теперь в `MVariant` (G6). |
| Q48-А | `useHotkey` сопоставляет главную клавишу по `key` ИЛИ по физической (`code`) для букв и цифр (`KeyS` → `s`, `Digit1` → `1`); удержанные клавиши (`pressedKeys`) — так же | Русская раскладка, Option+буква, Shift+цифра. Цена: на раскладке, переставляющей буквы (AZERTY), физическая Q тоже отвечает на `a`. |
| Q49-А | Убраны `UseHotkeyOptions.scope`, `pushScope`/`popScope` и стек скоупов реестра | Без `pushScope` скоуп ничего не делал; слои закрывает `isOnTopLayer` (открытый модал). Без алиасов (до 1.0). |
| B1.7a | Внутренности hotkey — в `utils/hotkey/` (`format`, `registry`, `platform`, `presentation`, `labels`); в `composables/hotkey/` — только `useHotkey` и `provideHotkeyLabels` (файл `provideHotkeyLabels.ts`, бывший `useHotkeyLabels.ts`) | `composables/**` автоимпортируется потребителю: `registerHotkey`, `normalizeKey`, `detectPlatform`… засоряли его пространство имён. Прецедент — `utils/button/useButton` (0.6.0). Спек проверяет, что папка экспортирует ровно два имени. |
| B9.7e | `useConfirmEditTransaction().draft` — глубокий `ref` (черновик — всегда приватный клон); `committed` остаётся `shallowRef` | `v-model="tx.draft.value.name"` пишет поле, а `dirty` его не видел. |
| B9.7a | `MLazy :once="false"` без `v-model:active` освобождает содержимое — проверено unit-спеком и e2e (`release-unbound` без `minHeight`); правки кода не потребовалось | Гипотеза verify (схлопнутый плейсхолдер возвращается в `rootMargin`) не подтвердилась. |
| B13.3c | Решено по рекомендации: один медиазапрос `REDUCED_MOTION_QUERY` в `utils/motion/shared/reduced-motion.ts` для `prefersReducedMotion()` и `useReducedMotion`; `useVirtualScroll` читает предикат в момент прокрутки, а не ref | Ref `useReducedMotion` равен `false` до монтирования компонента, а `useVirtualScroll` может работать в голом effect scope — замена на ref сломала бы reduced motion вне компонента. Дубликат строки запроса снят. |
| e2e `virtual-scroll.e2e.ts:105` (RTL) | `isAtEnd` допускает один пиксель недолёта до геометрического конца, если порог `end` меньше пикселя | При дробной ширине вьюпорта Chromium отдаёт RTL `scrollLeft` −159682 при диапазоне 159682.8 (LTR — 159683): RTL-панель никогда не доходила до конца. Порог шире пикселя остаётся точным. |
| Аудит планов: заглушка картинки строки (CT-09) | Голые `img`/`video` в `#leading` у `MListItem` лежат на `surface-container-highest`, пока нет пикселей; `MAvatar` — со своим контейнером | Медленная или битая картинка оставляет видимый бокс, а не дыру в строке. |
