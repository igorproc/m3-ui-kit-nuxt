|---|---|---|---|
| F2-01 | checkbox Ш7 — прорисовка галочки | Глиф — свой SVG (`utils/choice/checkMark.ts`): галочка Compose в боксе 18 (точки 0.2/0.5 → 0.4/0.7 → 0.8/0.3), черта — средняя линия; `pathLength="1"`, `stroke-dashoffset` 1 → 0 на `medium-3` + `emphasized-decelerate`, снятие — `short-3` + `emphasized-accelerate`; масштаб 0.6 → 1 сохранён; прозрачность глифа — `short-1` + `linear` в обе стороны. Смена галочка ↔ черта — мгновенная (без морфа) | Таблица токенов плана (`checkbox.md:81`); морф отклонён (S3/S4, `decisions.md:24`). Reduced motion — системно: `medium-3` сжимается до `short-2` (`base/_animations.scss`), анимация укорачивается, а не выключается. `MIcon`/`ICONS.check|remove` в флажке больше не используются |
| F2-02 | radio Ш1б — реактивный `value` | Не геттер, а перерегистрация: смена `value` снимает тикет и регистрирует новый; выбранная радио остаётся выбранной, модель группы следует новому значению | Реестр индексирует тикеты по значению (`createRegistry.browse`), геттер в нём не работает. Как у нативной радио: отмеченная радио отправляет своё текущее `value`. `composables/radio/useRadioGroup.ts` не тронут — хватило `register`/`unregister`/`select` контекста |
| F2-03 | radio Ш4б — безымянная группа (FM-07) | Dev-предупреждение `[m-radio-group] the group has no name…` при отсутствии `label`, `#label`, `aria-label`, `aria-labelledby` | Образец `MChipGroup` (`chip-group/index.vue`); правило «нет имени — dev-warning» |
| F2-04 | switch Г1 — нажатая ручка 28 | `flex-shrink: 0` у `__thumb`: ручка 28 больше контейнера 24 и центрируется переполнением, не сжимается в овал | Корень дефекта — сжатие flex-элемента (аудит `switch.probe.ts › press`) |
| F2-05 | chip A — generic `TValue` | `<script setup generic="TValue = unknown">` + `defineProps(mChipProps as MChipPropsOptions<TValue>)`; тип `MChipPropsOptions` — в `chip/props.ts` | Тот же приём, что `MDropdownPropsOptions` (`dropdown/props.ts`); свой тип, чтобы не зависеть от файла dropdown, который правят параллельно |
| F2-06 | chip S8 — мишень 48 у `removal="button"` | Обёртка `<span class="ui-chip--multi">` мишени не несёт (`&:not(.ui-chip--multi) { touch-target }`); главное действие — `touch-target` на `::before` (оба направления; по инлайн-оси у чипа ≥ 48 прирост 0), кнопка удаления — `touch-target` на `::after` (квадрат 48 вокруг неё, поверх главного действия) | `common.md` S8: мишень у каждой кнопки. Цена: мишень удаления заходит на конец подписи на ≈ 7rem (48 − 18)/2 − 8 |
| F2-07 | chip-group Ш6 — фокус после удаления последнего чипа | `@focusout` ряда снимает `tabindex="-1"` только когда фокус теряет сам ряд (`event.target === row`) | Корень: Chromium шлёт `focusout` с удаляемого чипа, он всплывал к ряду и сбрасывал `orphanedFocus` до фокуса в `nextTick` — ряд оставался без `tabindex`, фокус падал на `body` |
| F2-08 | slider СЛ-2 — `origin` на `range` (W2-А) | Dev-предупреждение `[m-slider] \`origin\` applies to a single value…`; поведение прежнее (range заливает между ручками) | W2-А, `decisions.md` |
| F2-09 | slider Ш3п — `&--dragging * { transition: none !important }` | Заменено BEM: `ui-slider-track--dragging` гасит переходы `__segment`/`__tick`, `ui-slider-thumb--dragging` — `__handle`/`__value`; у фрагмента трека новый проп `isDragging`. Модификатор корня `ui-slider-root--dragging` оставлен (его читает спека, это хук для потребителя) | Правило кита: без универсального селектора и `!important`. Эффект тот же для всех частей, у которых есть переходы |
| F2-10 | selection-group N4 (а) — строки в scope `#default` | В режиме данных scope `#default` получает `rows` — VNode строк (`#item` на каждую запись или `#empty`); потребитель кладёт `<component :is="rows" />` внутрь своей обёртки с `groupAttrs`. Взял `rows` из scope (чтение свойства во время рендера слота) — группа не рисует строки после слота; не взял — рисует, как раньше. Свойство неперечислимое: `v-bind="scope"` его не забирает | N4 → (а) по брифу. Решение синхронно в рендере группы, поэтому SSR отдаёт строки один раз и сразу внутри обёртки. Отвергнуто «`pattern` + `#default` → строки только в scope»: у потребителя с шапкой в `#default` строки молча пропали бы. VNode, а не компонент: компонент без пропсов не перерисовывается вместе с группой и держал бы устаревшие слоты |
| F2-11 | selection-group ВГ-1 — `aria-disabled` группы | `groupPatternAttrs(pattern, multiple, disabled)` отдаёт `aria-disabled="true"` у отключённой группы | ВГ-1 (`selection-group.md:212`); `aria-disabled` допустим у `group`/`radiogroup`/`listbox` |
| F2-12 | form-renderer DT-09 — результат отправки | Проп `statusText`; постоянный `role="status"` в конце формы, визуально скрыт (`sr-only`), есть в серверном HTML | DT-09; образец — `ui-file-upload__status`. Слота нет: минимальный API, текст — строка |
| F2-13 | form-renderer FM-11 — сводка ошибок | Делается без смены контракта адаптера: `CreateFormConfig.onValidationError(errors)` уже отдаёт карту «поле → сообщение», адаптер vee-validate передаёт `ctx.errors`. Сводка — `MAlert color="error"` над полями (`fragments/form-renderer/summary`), `tabindex="-1"`, `announce="off"` (фокус переходит на неё, второе объявление не нужно), заголовок — проп `errorSummaryTitle` (без дефолта, dev-warning при показе без него). Строки в порядке конфигурации, ссылки `href="#<id контрола>"`, клик ставит фокус в контрол. Сводка исчезает после успешной отправки. Контролы ищутся через функциональные ref на корнях полей (`composables/form-renderer/useErrorSummary.ts`) — без нового реестра и без своих id. Строки сводки — через 16: ссылка одна в строке, и axe `target-size` (24 CSS px между центрами) иначе падал | План `form-renderer.md` (FM-11, шаг 4); запрет менять контракт адаптера (память: vee-validate-адаптер и `./validation` остаются) |
| F2-14 | form-renderer N5 (а) — степперы `number` | Dev-предупреждение рендерера на каждое поле `number` со степперами (`controls` `split` по умолчанию или `stacked`) без `props.incrementLabel` / `props.decrementLabel`; называет поле из конфигурации | N5 → (а) по брифу. `MNumberInput` предупреждает и сам, но не знает имени поля конфигурации |
