# Showcase: приложения

Порты (QA поднимает сервер сам): mail 3301 · store 3302 · tasks 3303 · finance 3304 · home 3305.
Для каждого: концепция, экраны, что обязательно нагрузить из кита, гипотезы о недостающих кирпичиках
(подтверди или опровергни в FINDINGS), объём. Тема/шрифт — на твой вкус через `materialKit`, но
выбор и трение с ним — тоже находка.

## mail — почтовый клиент «Inbox» (сложное)

Канонический M3-кейс. Объём: 5–6 экранов/состояний.

1. **Входящие**: папки (desktop — sticky aside с extended FAB «Compose» + список папок; tablet — rail;
   phone — top app bar + bottom bar + modal drawer), поиск в app bar, чипы-фильтры (Unread, Attachments,
   From me), список писем (`m-list`, аватар, жирность непрочитанного, бейджи), массовый выбор с панелью
   действий (archive/delete/mark read), undo-снекбар.
2. **Чтение**: list-detail на desktop (две колонки), отдельный экран на phone; тред из нескольких писем
   (`m-expansion-panels`), вложения, ответить/переслать, меню «ещё» (`m-menu`), tooltips на иконках.
3. **Написать**: на desktop — диалог (или нижнеправое окно), на phone — полноэкранный sheet; «Кому» —
   `m-autocomplete multiple` с чипами контактов; тема; тело — `m-textarea autoGrow`; вложения
   (`m-file-input`/`m-file-upload`); отправка → undo-снекбар; черновик при закрытии — подтверждение (`useModal`).
4. **Настройки**: плотность списка (`m-button-group`/radio), тема (definition + palette + contrast через
   `useMaterialTheme`), подпись, переключатели уведомлений.
5. **Ярлыки**: список ярлыков + создание/редактирование в диалоге (`m-color-input` для цвета).
6. Хоткеи: `c` написать, `/` поиск, `e` архив — с подсказками `m-hotkey`.

Гипотезы: нет панели результатов поиска, нет list-detail/pane-компонента, нет «toast queue», drawer только
модальный, rail/bar без ссылок.

## store — магазин + checkout «Atelier» (сложное)

Публичный «красивый» сайт (керамика/мебель), page scroll, sticky header, footer. Объём: 6 экранов.

1. **Главная**: hero (можно `m-shape` как декор), категории, подборка товаров, промо-баннер, подписка
   на рассылку (форма с валидацией).
2. **Каталог**: фильтры (`m-chip-group`, `m-slider range` по цене, `m-rating`, `m-checkbox` бренды,
   `m-dropdown` сортировка); на phone фильтры в `m-sheet`; сетка карточек (`m-card tag="link"`), пагинация.
3. **Товар**: галерея (carousel — вероятно своя), выбор варианта (цвет — `m-button-group`/swatches, размер —
   segmented), количество (`m-number-input`), «В корзину», отзывы (`m-rating`, распределение `m-progress`),
   хлебные крошки.
4. **Корзина**: drawer/sheet + страница корзины, изменение количества, промокод.
5. **Checkout**: шаги (stepper — вероятно свой), адрес (валидация), доставка — `m-dialog-date` + слот
   времени, оплата (фейковая форма, не реальные данные), подтверждение `m-otp-input`, итог заказа.
6. **Трекинг заказа**: `m-timeline`, статус-баннер.

Гипотезы: нет carousel/gallery, stepper, price/money, image с плейсхолдером/скелетоном, empty state,
footer-компонента; «маркетинговая» типографика и секции лендинга — слабое место кита.

## tasks — таск-менеджер «Planner» (сложное)

Объём: 5 экранов. Переключение видов — `m-tabs`, поиск, фильтр-чипы, FAB «New task» (`m-fab-menu`).

1. **Доска (канбан)**: колонки статусов, карточки (аватары, чипы-метки, дедлайн, прогресс чек-листа),
   перетаскивание (`useDrag` из кита или своё) + доступ с клавиатуры (меню «Move to…»).
2. **Список**: `m-table` (сортировка, выбор, пагинация, кастомные ячейки), массовые действия.
3. **Календарь**: месячная сетка с задачами (календаря-месяца в ките нет — своё; переиспользуй что можно
   из `m-date-picker`/`useDateGridControl`).
4. **Задача**: desktop — боковая панель (aside/end-zone), phone — sheet; название, описание (`m-textarea`),
   исполнитель (`m-autocomplete` с аватарами), срок (`m-dialog-date` + `m-time-picker`), приоритет
   (segmented), чек-лист (`m-checkbox` + `m-progress`), комментарии (`m-timeline`), вложения (`m-file-upload`).
5. **Проект/участники**: таблица участников, роль (`m-dropdown`), опасная зона (`useModal` подтверждение).

Гипотезы: нет канбана/DnD-списка, календаря, side sheet, avatar group, empty state; end-aside не виден на tablet.

## finance — дашборд личных финансов «Ledger» (средне-сложное, берёт освободившийся воркер)

Объём: 3 экрана. Desktop — rail, phone — bottom bar.

1. **Обзор**: KPI-плитки, график cashflow (своё SVG, без библиотек), бюджеты (`m-progress`), последние операции (`m-list`).
2. **Операции**: `m-table` + фильтры: период (range-пикера нет — два `m-date-picker`/`m-dialog-date`), категории
   (чипы), сумма (`m-number-input` с `units` валют), меню экспорта.
3. **Перевод/бюджет**: форма с `m-number-input`, `m-slider`, подтверждение (`m-dialog`), `m-alert`/`m-banner` успеха.

Гипотезы: нет charts, KPI/stat tile, date range, money/currency формата.

## home — «Умный дом» (простое, берёт освободившийся воркер)

Цель — понять масштаб «быстро и красиво»: **1–2 экрана**, минимум своего CSS. Засеки (в FINDINGS):
сколько строк своего SCSS и сколько своих компонентов понадобилось.

1. **Дом**: комнаты (`m-tabs` или `m-button-segmented`), карточки устройств: свет (`m-switch` + яркость
   `m-slider`), термостат (`m-number-input`/`m-slider`), сцены (`m-button-group`), камера (`m-card` +
   `m-responsive` 16/9 плейсхолдер), энергия (`m-progress` expressive), переключатель темы.
2. (опц.) **Комната**: детали устройства в `m-sheet` на phone / `m-dialog` на desktop.
