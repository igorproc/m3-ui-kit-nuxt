# Workflow: Перевод UI Компонента на Zero-Runtime SCSS Мапы

Этот документ описывает стандартный алгоритм (flow), который я (Antigravity/AI) должен использовать каждый раз при старте задачи по рефакторингу или созданию нового компонента в PrimeTime UI Kit.

При получении задачи на перевод компонента, я должен самостоятельно пройти по этим шагам, не ожидая подробных инструкций от пользователя.

## 1. Скан контекста и файлов (Discovery)

Перед тем как писать код, мне нужно проанализировать текущее состояние:
1. **SCSS Токены**: Прочитать текущий файл `app/assets/stylesheet/components/[component-name]/_index.scss` (если он есть).
2. **Vue Компонент**: Прочитать `app/components/ui/[component-name]/index.vue` (пропсы, слоты, классы).
3. **Референсы**: При необходимости вспомнить или прочитать эталонные реализации (например, `list/item/_index.scss` или `button/_index.scss`), чтобы вспомнить структуру мап.
4. **Спецификация M3**: Найти HTML-снапшоты с токенами в `.cursor/temp/snapshots/[component].htm` (если пользователь их выгрузил) или запросить у пользователя ссылки на Figma/Material Design.

## 2. На что обратить внимание (Checklist)

При написании кода строго соблюдать следующие архитектурные правила:

*   **Иерархические Мапы**: В `_index.scss` мапа `$tokens` должна быть строго вложенной (hierarchical), например: `standard: ( container: ( color: ... ) )`. Функция `material-map` автоматически сделает ее плоской (например, `standard-container-color`).
*   **Zero-Runtime**: В `.vue` файле доступ к токенам осуществляется ТОЛЬКО через функцию `g($t, 'твой-путь-к-токену')`.
*   **Elevation (Тени)**: Не использовать жестко зашитые `rgba()`. Использовать объектную структуру `(umbra, penumbra, ambient)` и `color-mix` с системной переменной `var(--color-shadow)` для поддержки светлой/темной тем.
*   **Цвета и Скругления**: Обращаться к дизайн-системе через `map.get($theme-color-link, ...)` и `map.get($theme-shape-link, ...)`.
*   **Пиксели в Rem**: Никаких `px`. Все значения конвертируются в `rem` (1 к 1), например `64px` -> `64rem`.
*   **Typography**: Использовать миксины: `@include typescale('title-medium');`.
*   **Документация (docs)**:
    *   Обязательно наличие/создание API данных: `server/data/en/[component-name].json` и `server/data/ru/[component-name].json` (чтобы не было 404).
    *   Создание интерактивного демо-стенда: `docs/app/components/docs/component/[component-name]/Playground.vue` (с пресетами и вкладками).
    *   При необходимости создание/обновление корневой страницы доки `docs/app/pages/components/[component-name].vue`.

## 3. Шаблон стартового промта (Для копирования)

Когда нужно начать работу с новым компонентом, достаточно отправить мне этот промт:

```text
Начинаем перевод компонента [Имя Компонента] на Zero-Runtime SCSS мапы.

1. Прочитай текущий код компонента: @[d:\dev\primetime\ui\kit\app\components\ui\[имя-компонента]\index.vue] и его SCSS @[d:\dev\primetime\ui\kit\app\assets\stylesheet\components\[имя-компонента]\_index.scss] (если существует).
2. Снапшоты токенов M3 лежат здесь: @[d:\dev\primetime\ui\kit\.cursor\temp\snapshots\[имя-компонента].htm].
3. Действуй строго по правилам описанным в @[d:\dev\primetime\ui\kit\.cursor\flow\ui.md].
4. Сформируй вложенную SCSS-мапу, обнови Vue-компонент, сделай playground и добавь JSON-данные для документации.
```
