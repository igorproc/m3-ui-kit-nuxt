## Вердикт

`авторский`. Вид и смысл остаются: постоянный блок в потоке документа, не тост, без таймера,
очереди и телепорта. Это подтверждено владельцем при создании.

Системные правки:
- тяжесть сейчас различается только цветом: иконки по умолчанию нет (TH-05);
- длинный токен вылезает за край;
- живой регион монтируется вместе с текстом;
- в forced colors tonal-блок теряет границу;
- фокус с кнопки закрытия падает на `body` (вопрос 1).

## Поведение и доступность

- Иконка тяжести декоративна (`aria-hidden`): тип объявляет роль и текст. Для зрячих с
  нарушением цветовосприятия иконка и есть нецветовой признак.
- **A11-02.** В пропсах слота `close` ключ `ariaLabel` выводится в SSR как `arialabel`. Отдавать
  `'aria-label'`.
- **A11-04.** Имя закрытия по умолчанию строится как «`closeLabel`: `title`» (шаблон, а не
  английская строка).
- Escape не закрывает inline-alert: решение прежнего плана остаётся.

## Открытые вопросы

**1. Куда уходит фокус после закрытия?** При создании решено: компонент не угадывает, фокус
возвращает потребитель в `@close`. Аудит считает потерю фокуса дефектом P1 (A11-09).
1. Оставить решение и добавить рецепт в документацию. Ничего не угадываем, но по умолчанию фокус
   падает на `body`.
2. По умолчанию переводить фокус на следующий фокусируемый элемент после блока, а если его нет —
   на ближайший заголовок области. Проп `returnFocus: false` отключает. Нет потери позиции, но
   компонент решает за потребителя.

Рекомендация: 2. Потеря фокуса на `body` — нарушение WCAG 2.4.3, и чаще всего это и есть
правильная цель.

**2. Как держать живой регион смонтированным, если блок появляется по `v-if`?**
1. Общий постоянный регион в `#ui-overlay-host` (как у [snackbar](snackbar.md)),
   alert только дублирует туда текст при появлении. Надёжно, но текст звучит отдельно от места.
2. Оставить роль на блоке и рекомендовать `v-show` вместо `v-if` для динамических alert. Без
   нового механизма, но правило легко нарушить.

Рекомендация: 1, общий механизм со snackbar.
