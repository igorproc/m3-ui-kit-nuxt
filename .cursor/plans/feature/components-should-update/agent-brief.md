Общий контекст для каждого агента волны. Твой личный промт называет компонент, план и поправки
к нему. Всё остальное — здесь. Читай целиком.

- Git: не коммить, не создавай веток, не делай `checkout`/`switch`/`stash`/`reset`/`restore`.

## 4. Жёсткие правила кода

### Стили
- Каждое значение — из карты `$tokens` компонента (`assets/stylesheet/components/<name>/_index.scss`)
  через `g($t, 'точечный.путь')`, где `$t: material-map(t.$tokens, 'md-<name>')`.
  Разделитель пути — **только точка**. Трогаешь файл с дефисными путями — переводишь весь файл.
  Ключ с дефисом (`min-height`) допустим как имя ключа.
- Никаких литералов ms, cubic-bezier, %, rgb/hex, px. Инструменты (в scope без `@use`):
  `spacing(0|2|4|8|12|16|20|24|32|40|48|64)`, `state-opacity(hover|focus|pressed|dragged|disabled-container|disabled-content)`,
  `elevation(0..5)`, `z(...)`, `map.get($theme-color-link, '<роль>')`,
  `map.get($theme-shape-link, '<ступень>')`, `var(--sys-motion-duration-*)`, `var(--sys-motion-easing-*)`.
  Миксины: `can-hover`, `focus-ring` / `focus-ring(inset)`, `forced-colors`, `sr-only`,
  `typescale('<стиль>')`, `use-scrollbar`.
- Только `rem` (корень = vw, 1rem ≈ 1 дизайн-пиксель — это фича). Исключение: `1px` внутри
  `@include forced-colors`.
- Новых системных токенов (`--sys-*`, ключей `$theme-*`, ступеней шкал) не заводить. Значение вне
  шкалы выводится `calc()` из существующих ступеней **внутри карты токенов компонента**.
  Арифметика — в карте, не в `.vue`. В карте лежат атомарные значения, шорткат (`padding: a b`)
  собирается в SCSS.
- Повторяющиеся наборы (варианты, плотности, состояния) генерирует `@each` по карте.
- `:hover` — только внутри `@include can-hover { … }`.
- Фокус: контролы — `@include focus-ring`; поля — только смена цвета, без кольца и утолщения.
- BEM `ui-<block>__<el>--<mod>`. Без селекторов по тегам (`> span`), без `[data-*]` для
  состояний, минимальная специфичность. Не стилизуй чужие блоки (`.ui-icon` и т. п.) — размер
  иконки задаётся `font-size` контейнера, иконка наследует `1em`.
- Пять состояний у интерактивного: обычное, hover, pressed, focused, disabled. Одно свойство на
  состояние. Роли: пусто → `outline-variant`, есть содержимое → `outline`, активно → `primary`,
  ошибка → `error`, выключено → то же свойство на пониженной непрозрачности.
- Состояние никогда не выражается только цветом. Forced colors: всё, что нарисовано фоном или
  тенью, повторить системными цветами.
- `prefers-reduced-motion`: укоротить, а не выключить.
- Новый код — на логических свойствах (`inline/block`, `inset-inline-start`), стрелки
  направления зеркалятся в RTL.
- Z-index внутри компонента — литерал 1–3 при `isolation: isolate`; слой страницы — `z()`.
- Раскладка не «едет» от состояния: ширина, высота строки, место под ошибку зарезервированы.
  Слоты по ширине не ограничиваются.
- Runtime custom properties — только для живой геометрии, которую знает лишь рантайм.

### API и оси
- Пропы в `props.ts` через `propsFactory` (`#kit/shared/utils/props/propsFactory`), фабрики
  `makeColorProps/makeVariantProps/makeStateProps` из `#kit/shared/utils/props`. В SFC:
  `defineProps(mXProps)`, `defineModel`, `defineSlots`, типизированные emits из `props.ts`.
  Публичные типы живут в `props.ts`/`types.ts`, не в `.vue`.
- Оси: `color: MColor`, `variant: MVariant`, `density` (`compact | default | comfortable`,
  тип `MFieldDensity`), `shape: MShape` (шкала скруглений), `tag`, `mode`, `<x>Placement`.
  **Нельзя**: `size`, `sm/md/lg`, XS–XL, `type` на новом пропе. Подмножество оси — через
  `Extract<MVariant, …>`. Взаимоисключающие флаги — одна ось. Вариант без заказчика в ките не
  вводится. Дефолт — литералом на пропе, не в константе.
- Контент, который захотят заменить, — слотом. Обёртка над смысловым элементом:
  `defineOptions({ inheritAttrs: false })` + `useControlAttrs()`.
- Контекст детям — `createContext` из `#kit/shared/utils/context/createContext`. Тему на
  поддерево не провайдить.
- Кит не поставляет английский пользовательский текст по умолчанию. Нет имени — dev-warning
  (образец — `useButtonNameWarning`). Фразы — `shared/constants/messages.ts`, имена иконок —
  `ICONS` из `shared/constants/icons.ts`.
- Внутри кита UI-компоненты импортируются явно (`#kit/components/ui/...`). Любой `.vue` в
  `components/ui/` становится публичным `M*` — приватные части кладутся в
  `components/fragments/<name>/`.

### Поведение
- Три слоя: чистая логика (без Vue и DOM, своя `.spec.ts`) → control-композабл в
  `composables/<name>/` (DOM, события, ARIA → бэги атрибутов) → тонкий компонент.
- Композабл не отдаёт ни `class`, ни `data-*` — это проверяет его спека. Тип возврата объявлен
  явно (`UseXControlReturn`), иначе `mkdist` падает с TS7056.
- SSR: `role`, `aria-*`, `tabindex` есть в серверном HTML, первый кадр правильный. `onMounted` —
  только для браузерных API. На сервере нет модульного изменяемого состояния (модульный `let`
  запрещён; client-only сущности на сервере не создаются).
- Каждый слушатель и таймер снимается. Используй свои композаблы кита (`useEventListener`,
  `useGlobalListener`, `useRaf`, `useTimer`). Новых импортов из `@vueuse/core` не добавляй.
- Окно и брейкпоинты — `useSSRWindowSize()` / `useBreakpoint()`. Измерения кэшируются,
  троттлятся через rAF.
- Живые регионы смонтированы всегда, меняется только текст. `aria-invalid` — только при видимой
  ошибке. Декоративная графика — `aria-hidden="true" focusable="false"`. Цель нажатия ≥ 24.
- Один клавиатурный контроллер на паттерн (`useSliderControl`, `createRangeKeyboardController`,
  roving — `ui/tabs`). Третий не заводить.

### Форма кода
- Файл не длиннее ~400 строк, иначе дроби на композаблы и partials.
- Порядок в `.vue`: `<template>` → `<script setup lang="ts">` → `<style lang="scss">`.
  ESLint stylistic: без точек с запятой; `a => f(a)` без скобок, блочное тело — `(a) => { … }`.
- **Новых комментариев не пишешь** (правило владельца репозитория). Исключение — однострочный
  JSDoc у пропов в `props.ts`: из него строится API в документации. Существующие комментарии не
  трогаешь, если не удаляешь сам код, к которому они относятся.
- Код, имена, строки ошибок и логов — по-английски.
- Минимальный правильный diff. Не рефактори попутно то, что не нужно для шага плана.
- Чини корень, а не симптом. Нашёл баг класса, который есть и в других компонентах, — не чини
  их, перечисли в отчёте.

## 5. Стоп-правила

Не делаешь сам, а пишешь в отчёт в «Вопросы владельцу»:
- новая зависимость, Pinia, новый системный токен или ступень шкалы;
- пружины и морф в компоненте, где их ещё нет;
- удаление публичного компонента;
- правка чужого компонента или общего файла сверх добавления ключа;
- развилка, где у правила два разумных толкования и код с `docs/system` её не решают.

Открытые вопросы плана решаешь сам: по умолчанию бери рекомендацию плана, если личный промт не
говорит иначе. Другой вариант — только с внешним основанием (доступность, платформа,
существующий токен, ограничение сборки). Каждое решение — в отчёт.

«Предложения по UX» из плана — не шаги. Делай только дешёвые (S), без зависимостей, если личный
промт их не отменяет. Каждое сделанное — в отчёт.

Ломающее изменение публичного API допустимо (кит 0.x, легаси-алиасов нет), но: перечисли в
отчёте, что сломано и как мигрировать; потребителей внутри кита не трогай — список их файлов и
нужной правки дай в отчёте.

## 6. Тесты и фикстуры

### Unit (рядом с кодом)
- Vitest, `mountSuspended` из `@nuxt/test-utils/runtime`, `attachTo: document.body` для фокуса,
  оверлеи ищи в `document.body`. Без реальных таймеров (`vi.useFakeTimers`) и пикселей.
- Покрыть: рендер и корневой класс; пропы → BEM-классы и атрибуты; v-model и emits; роли и aria;
  disabled гасит взаимодействие; fallthrough-атрибуты; бэги композабла без `class`/`data-*`;
  чистая логика — таблицей случаев.
- Падающий старый тест сначала проверь: не закреплял ли он баг. Тест под баг не подгоняется.

### Фикстуры и e2e
- `playground/fixtures/<name>/matrix.vue` — строки = состояния, колонки = варианты/плотности.
- `playground/fixtures/<name>/stress.vue` — длинный текст, длинное слово без пробелов, пусто,
  много элементов.
- `playground/fixtures/<name>/<name>.e2e.ts`.
- Фикстуры регистрируются сами (`playground/app/utils/fixtures.ts`), открываются как
  `/<name>/matrix`. В фикстуре импорт явный (`#kit/components/ui/...`), `data-test` — единственный
  разрешённый `data-*`.
- e2e через хелперы `playground/e2e/support.ts`: `openFixture(page, '<name>/matrix', { theme, dir })`,
  `expectNoAxeViolations`, `expectNoHorizontalOverflow`, `THEMES`, `DIRECTIONS`, `WIDTHS`.
  Проверить: axe на matrix по `THEMES × DIRECTIONS` и на stress; нет горизонтального переполнения
  на `WIDTHS`; обход Tab; клавиатурная модель; видимость фокуса (ширина outline ≥ 2); forced colors
  через `page.emulateMedia({ forcedColors: 'active' })` + `getComputedStyle`.
  Образец — `playground/fixtures/button/button.e2e.ts`.
- e2e ты **пишешь, но не запускаешь**.

### Проверки — один раз, в конце
Человек делегирует, чтобы отойти, а тесты (`vitest`, `playwright`, `npm run test:*`, `vue-tsc`)
у него каждый раз спрашивают разрешение. Поэтому:
- **пока пишешь код, тестов не запускаешь** — ни после каждой правки, ни «проверить одну
  строку». Читать файлы и историю (`ls`, `cat`, `grep`, `git log`, `git show`, `git diff`) можно
  свободно;
- **когда весь код, спеки и фикстуры написаны**, один раз запускаешь проверки по своим файлам —
  ровно этими командами, по одной, без `timeout`, пайпов, `2>&1`, `cd …&&`, `| tail`:
  ```
  npx vitest run <твои .spec.ts через пробел> --coverage.enabled=false
  npx eslint <твои файлы и папки>
  npx stylelint <твои .vue и .scss>
  npm run lint:scss
  ```
- упало — чинишь всё, что упало, и перезапускаешь **только упавшую** команду; не больше двух
  повторов на команду, дальше — в отчёт как «не прошло»;
- `lint:scss` компилирует все SFC: ошибки в чужих файлах игнорируй (их правят параллельно);
- `typecheck`, `build`, e2e, dev-сервер не запускаешь — их прогоняет основная сессия.

## 7. План компонента

Когда начал — `state="planned"` (если стоял `pending`), когда закончил — обнови
`<implementation-status>`: `state="done"` (или оставь `planned`, если шаги перенесены),
`updated="<сегодня>"` и одна строка о том, что сделано. Перенесённые шаги пометь в «План работ»
словом **перенесено** с причиной.
