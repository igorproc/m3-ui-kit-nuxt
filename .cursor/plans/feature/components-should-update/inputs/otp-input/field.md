## Вердикт

**Авторский.** Ячейка — картинка позиции, а не контрол: `aria-hidden`, без `tabindex` и обработчиков
клавиатуры; клик ставит каретку через `focusAt(i)`, а клик по прозрачному инпуту над сеткой
находит ячейку по геометрии (`cellAt(x)`). Расхождение с системой одно, и оно ролевое: пустая и
заполненная ячейки обе с кромкой `outline`, заполненная ещё и залита.

## Поведение и доступность

- Ячейка не объявляет себя: значение и позицию озвучивает единственный инпут.
- Один механизм попадания: инпут лежит поверх и ловит клик, ячейка под указателем определяется по
  геометрии; `onClick` в `cellAttrs` срабатывает только для разметки, где инпут не перекрывает
  ячейки (escape hatch). Двойной обработки нет: в разметке кита клики получает инпут.
- Активная ячейка существует только при фокусе поля — иначе частично набранный код выглядит
  сфокусированным.
- Forced colors: кромка `CanvasText`, активная `Highlight`, ошибка пунктиром, disabled `GrayText`
  (уже есть).

## API

Слот `#field` получает весь `OtpCell` (`index`, `position`, `character`, `filled`, `active`,
`error`, `disabled`, `readonly`, `masked`, `maskCharacter`); слот `#mask` — то же. Добавляется
`hint` (символ плейсхолдера) — шаг 4 [index.md](index.md#план-работ). Ломающих изменений у ячейки
нет; `mask` — вопрос 2 семейства.

## План работ
