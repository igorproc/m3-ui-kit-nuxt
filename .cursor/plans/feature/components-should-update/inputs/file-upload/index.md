<implementation-status state="planned" updated="2026-10-07">Реализован в фазе 2: ровно один `MFileInput` как нативный picker, dropzone делегирует ему, общий `useFileSelection`/`createFilePolicy`, очередь с `upload`, `autoStart`, `concurrency`. Открыты: вложенное поле без имени, `autoStart` не запускает начальную модель (рендер), длинное имя налезает на действия, действия игнорируют disabled/readonly, причина отказа не показывается, статусы объявляются ненадёжно.</implementation-status>

## Вердикт

`авторский`. Архитектура прежнего плана остаётся:
- один picker;
- общая политика файлов;
- очередь как композабл;
- без второго скрытого `input`;
- без стора.

Дефекты:
- **`autoStart` не запускает файлы из начальной модели** — все остаются «queued» (рендер);
- вложенный `MFileInput` — видимое безымянное поле (FM-01, A11-02);
- длинное имя файла налезает на кнопки действий (CT-01, CT-04, рендер);
- кнопки элемента работают в disabled и readonly (ST-04, IN-09);
- причина отказа есть в данных (`reasons`), но не показывается и стоит в конце компонента
  (FM-03, LY-11);
- ошибка загрузки не различает сеть, 403, 413, 5xx и таймаут (DT-04);
- `role="alert"` монтируется вместе с текстом (DT-09);
- нажатое действие удаляет сфокусированную кнопку — фокус падает на `body` (A11-08);
- `MFileInput` получает модель без `@update:model-value`: его кнопка очистки рассинхронизирует
  очередь (EN-02);
- внешний сброс `v-model = []` не очищает очередь (CT-07, EN-05).

## Поведение и доступность

- Компонент — `role="group"` с именем (`label`), подсказкой ограничений и сообщениями (FM-07).
- Отказ показывается сразу под dropzone с причиной по каждому файлу (тип, размер, количество) и
  объявляется через постоянный регион (FM-03, LY-11, FM-05).
- Синхронизация с моделью в обе стороны: внешний сброс очищает очередь, очистка во вложенном
  поле — тоже (EN-02, EN-05, CT-07).
- Строки — пропы без английских дефолтов (CT-13).

`MFileInput` как picker. Не решено, должен ли он быть виден.

   очереди. Нет двух контролов для одного действия, но меняется вид, к которому привыкли.
2. Оставить видимым, дать ему лейбл и подсказку ограничений. Ничего не меняется визуально, но на
   экране два способа выбрать файл подряд.
