## Вердикт

`авторский` (инфраструктура). У M3 нет такого компонента. Из системы M3 он берёт scrim: роль
`scrim` на 32% — совпадает. Всё остальное — архитектура кита, и она сохраняется:
- один стек слоёв;
- Escape и клик снаружи закрывают только верхний слой;
- блокировка прокрутки со счётчиком ссылок;
- возврат фокуса;
- нативный top layer вместо z-index.

## Рендеры

Не применимо: у примитива нет собственной поверхности, кроме scrim. Вид модальных
поверхностей — в планах [dialog](dialog.md) и
[sheet](sheet.md).

## Оси дизайна

| Ось | Значения | Комментарий |
|---|---|---|
| `mode` | `modal \| popover` | Стратегия работы, слово `mode` по `axes.md` |
| `background` | `non-interactive \| interactive` | Модальный фон или «немодальный модальный» (side sheet рядом с контентом) |
| `overlayBehavior` | `auto \| persist` | Затемняет только верхний модальный слой или каждый |
| `closeOnSwipe` | `none \| up \| right \| down \| left` | Жест закрытия для листов |
| `displayDirective` | `if \| show` | Сохранять ли DOM закрытым |

Цветовой оси и оси размера нет и не будет: поверхность рисует потребитель.

## Поведение и доступность

- **A11-12, P1.** `showModal()` вызывается, пока панель ещё `v-show=false`, поэтому браузер
  переводит фокус на сам `<dialog>`. Чинится порядком: сначала показать панель, затем
  `showModal()` и перевод фокуса на первый фокусируемый элемент. Если его нет — на заголовок с
  `tabindex="-1"`.
- **A11-06, P1.** В popover-режиме активатор объявляет `aria-haspopup="menu"`, хотя внутри
  может быть не меню. `aria-haspopup` должен приходить от потребителя (`menu`, `listbox`,
  `dialog`), а `aria-controls` — ставиться всегда.
- **CT-10 / RS-10, P2.** Панель — контейнер на весь экран без прокрутки, а прокрутка страницы
  заблокирована. При высоте около 350px содержимое обрезается. Решение:
  `overflow-y: auto` и `overscroll-behavior: contain` на панели, `margin-block: auto` у
  содержимого вместо `align-items: center`, чтобы при переполнении верх не уезжал за экран.
- **EN-11.** Пропы `scrim`, `teleportTo`, `transition` удалены без деприкации. Нужны алиасы с
  предупреждением в dev на один minor:
  - `scrim: false` → `hideOverlay: true`;
  - `transition` → `contentTransition`;
  - `teleportTo` — только предупреждение, top layer его не требует.
- **Документация (DC-02…05).**
  - Анатомия: корень, scrim, панель, защитная полоса, баннер.
  - Фокус-трап и возврат фокуса.
  - Блокировка прокрутки.
  - `background: interactive`.
  - Переполнение.
  - Таблица пропов из `props.ts`: текущая docs-страница описывает несуществующие
    `click:outside`, `dismiss`, `after:enter`.

## API

Публичный API — `mOverlayProps` из `props.ts`, без изменений, кроме алиасов из EN-11. Программный
`$modals` — отдельный план [modals.md](modals.md), он монтирует те
же компоненты поверх этого примитива.

## План работ

1. **M — порядок открытия и фокус (A11-12).** `overlay/index.vue` и `useTopLayer.ts`: показ
   панели → `showModal()` → фокус. Спека проверяет, что `document.activeElement` — первый
   фокусируемый элемент, а не `<dialog>`.
2. **S — `aria-haspopup` от потребителя (A11-06).** Проп `activatorRole` или вывод из `mode` +
   `role` содержимого; `aria-controls` всегда.
3. **S — прокрутка панели (CT-10, RS-10).**
4. **S — алиасы удалённых пропов (EN-11).**
5. **S — токены.** `gesture-guard.width` через `spacing(16)`. Scrim под `prefers-contrast: more`.
6. **S — запись решения о reduced motion** в `decisions.md`.
7. **M — документация** (DC-02…05).
8. **S — пружины** после S4.

## Тесты

- Unit: порядок открытия и фокус; вложенные модалки — Escape закрывает только верхнюю;
  `persistent`; счётчик блокировки прокрутки; алиасы с предупреждением.
- e2e: фикстура с высоким содержимым на 360×350 — его можно докрутить до низа; axe в открытом
  состоянии; фокус возвращается к активатору.

## Готово, когда

- После открытия фокус стоит внутри содержимого, а не на `<dialog>`.
- Содержимое выше экрана прокручивается внутри панели.
- Старые имена пропов работают с предупреждением.
- Docs-страница совпадает с `props.ts`.

## Предложения по UX

Расширения сверх паритета с M3. Это предложения владельцу, а не шаги плана: в «План работ» попадают только после решения. Без Expressive-анимаций и без новых зависимостей.

| Предложение | Что получает пользователь | Заказчик | Цена | Рекомендация |
|---|---|---|---|---|
| Кнопка «назад» браузера закрывает верхний модальный слой (history state) | На телефоне системный жест «назад» закрывает диалог или лист, а не уводит со страницы | dialog, sheet, navigation-drawer на compact | M · `history.pushState` при открытии, снятие при закрытии, учёт вложенности стека | да, опцией `closeOnBack`, по умолчанию для fullscreen и листов |
| Защита от потери ввода: `beforeClose` (возвращает `Promise<boolean>`) перед dismiss по Escape, клику снаружи и свайпу | Форма в диалоге не закрывается случайно с потерей набранного | dialog с формой, form-renderer в листе | S · один хук в рантайме стека | да |
| Фон делается `inert` и в popover-режиме с `background: non-interactive` | Tab не уходит за пределы открытого слоя даже без фокус-трапа | menu, tooltip rich | S | обсудить: для меню APG допускает выход по Tab |

## Открытые вопросы

**1. Как активатор узнаёт роль всплывающего содержимого (`aria-haspopup`)?**
1. Явный проп `activatorRole` у `MOverlay`. Просто и прозрачно, но легко забыть.
2. Брать из потребителя: `MMenu` ставит `menu`, `MDialog` ставит `dialog`, у голого `MOverlay`
   — `dialog`. Правильно по умолчанию, но голый popover с listbox останется с неверной ролью.

Рекомендация: 2 и проп как запасной выход.
