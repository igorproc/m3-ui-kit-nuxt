## Вердикт

`авторский` (инфраструктура). Модель из прежнего плана остаётся:
- `MLazy` управляет моментом клиентской активации и монтирования, а не гидрацией;
- отдельный чанк гарантирует только настоящий `Lazy*`/async-компонент;
- по умолчанию нет ни спиннера, ни скелетона.

От M3 нужна только доступность состояний ожидания и ошибки и рецепт заглушки на loading
indicator. Ни того, ни другого сейчас нет.

## Рендеры

Не применимо: собственного вида нет, заглушку рисует потребитель. Рецепт заглушки на
`MLoading` показан в плане [loading](../feedback/loading.md).

## Анатомия

| # | Часть | В ките | Статус |
|---|---|---|---|
| 1 | Граница (корень) | `div` с `minWidth`/`minHeight` | есть; резерв места необязателен (DT-02) |
| 2 | Заглушка до активации | слот `placeholder` | есть; по умолчанию пустая (A11-07) |
| 3 | Ожидание (Suspense pending) | слот `fallback`, иначе снова `placeholder` | есть; без `aria-busy` (DT-09) |
| 4 | Содержимое | слот `default` | есть |
| 5 | Ошибка | слот `error` с `retry` | есть; без слота — пустой `div` (DT-04) |

## Оси дизайна

| Ось | Значения | Комментарий |
|---|---|---|
| `mode` | `eager \| on-idle \| on-view \| on-interaction` | Стратегия, слово `mode` по `axes.md`. `idle` как имя eager не используется: в Nuxt это отложенная гидрация |
| `once` | `true \| false` | Флаг допустим: второго значения не бывает |
| `interactions` | `pointerenter \| pointerdown \| click \| focus` | Только для `on-interaction` |

## Оси состояний

| Ось | Нужно | Есть | Не хватает |
|---|---|---|---|
| Данные | idle → pending → active / error | Машина состояний, событие на каждом переходе | `aria-busy` на pending; объявление ошибки (`role="alert"`) |
| Фокус | Фокус внутри не теряется | — | При `once=false` уход из окна размонтирует содержимое вместе с фокусом и введёнными данными (FM-12) |
| Клавиатура | `on-interaction` активируется с клавиатуры | Только если в заглушке есть фокусируемый элемент | Заглушка по умолчанию — фокусируемая кнопка-активатор или `tabindex="0"` (A11-07, A11-15) |
| Раскладка | Нет скачков | `minHeight` опционален; `out-in` даёт пустую паузу | Резерв по умолчанию и переход без схлопывания (DT-02, MO-04) |

## Поведение и доступность

- **DT-09, A11-06.** Пока идёт pending, корень несёт `aria-busy="true"`.
- **DT-04.** Без слота `error` — постоянный контейнер `role="alert"` с текстом из
  `shared/constants/messages.ts` и кнопкой повтора. Подход к английским строкам по умолчанию —
  общий вопрос Q13 (CT-13). До ответа — проп `errorText`, без дефолтной фразы.
- **FM-12.** При `once=false` фокус внутри содержимого блокирует размонтирование: деактивация
  откладывается, пока фокус внутри, и пока не размонтируется заполненная форма. Альтернатива —
  `v-show` вместо `v-if` для повторных циклов.
- **A11-07, A11-15.** Режим `on-interaction` без фокусируемой заглушки предупреждает в dev и
  делает корень фокусируемым.
- **EN-05.** Смена `rootMargin`/`threshold` пересоздаёт наблюдатель с новыми опциями.
- **EN-10.** Один общий `IntersectionObserver` на одинаковые опции. Это модульный реестр, на SSR
  не создаётся.
- **DT-11, P3.** Задержка показа `fallback` около 200 мс через `timeout` у `Suspense`, чтобы
  быстрые компоненты не мигали.

## План работ

1. **S — `aria-busy` и встроенный alert ошибки** (DT-09, DT-04, A11-06).
2. **M — сохранение фокуса при `once=false`** (FM-12). Спека: фокус в поле, прокрутка из окна —
   содержимое и значение на месте.
3. **S — клавиатурная активация** (A11-07, A11-15).
4. **S — резерв места и переход** (DT-02, MO-04).
5. **M — общий наблюдатель** (EN-05, EN-10).
6. **S — `fallbackDelay`** (DT-11).
7. **S — токены** (TK-02).
8. **M — документация** (DC-01…05).
   - Когда `MLazy`, а когда `loading="lazy"`, `content-visibility`, `defineAsyncComponent` или
     `hydrate-on-*`.
   - Анатомия.
   - Режимы.
   - Резерв места.
   - Доступность `on-interaction`.
9. **S — тесты** (TS-07). Ветка ошибки и `retry`, `on-view` через IO, событие `resolve`.

## Тесты

- Unit:
  - четыре режима;
  - `aria-busy` на pending;
  - встроенный alert;
  - фокус блокирует размонтирование;
  - общий наблюдатель — один на одинаковые опции;
  - `fallbackDelay`.
- e2e: Tab до заглушки в `on-interaction` и Enter активируют; axe в состояниях pending и
  error; CLS = 0 на фикстуре с `minHeight`.

## Готово, когда

- Ожидание и ошибка объявляются скринридеру.
- В `on-interaction` активация работает с клавиатуры.
- `once=false` не теряет фокус и введённые данные.
- На ленте из 100 `MLazy` работает один наблюдатель.

## Предложения по UX

Расширения сверх паритета с M3. Это предложения владельцу, а не шаги плана: в «План работ» попадают только после решения. Без Expressive-анимаций и без новых зависимостей.

| Предложение | Что получает пользователь | Заказчик | Цена | Рекомендация |
|---|---|---|---|---|
| Предзагрузка чанка по намерению: на `pointerenter` или `focus` начинать `import()`, монтировать по `click` | Тяжёлый виджет открывается почти мгновенно, хотя его код не грузился заранее | редакторы и карты в `on-interaction` | S · `import()` уже в руках `Lazy*`; новый режим или опция `prefetch` | да |
| Рецепт заглушки на `MLoading` и skeleton-фазе (`phases/skeletons`) в документации | Единый вид ожидания по всему продукту | все потребители | S · только документация | да |

## Открытые вопросы

**1. Что делать при `once=false`, если фокус внутри?**
1. Не размонтировать, пока фокус внутри. Деактивация откладывается до ухода фокуса. Просто, но
   память не освобождается, пока пользователь там.
2. Переключиться на `v-show`. Состояние сохраняется всегда, но смысл `once=false` (освобождать
   память) теряется.

Рекомендация: 1.
