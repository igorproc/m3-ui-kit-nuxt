## Вердикт

`авторский`, часть семейства списка. В M3 Expressive отдельного подзаголовка списка нет; визуально
кит уже совпадает с заголовком секции drawer — `title-small`, `on-surface-variant`, отступ 16. Эталон —
текущее видение: пассивный текст без состояния, без контекста и без поведения. Работа — системная:
z-index по правилу кита, `scroll-margin` для строк под липкой подписью, заливка sticky под фон списка,
точечные пути `g()` и правильный тег, когда список получит семантику.

## Анатомия

| # | Часть | Элемент кита | Статус |
|---|---|---|---|
| 1 | Контейнер подписи (min 48, отступы 8 / 16) | `.ui-list-subheader` (`div` / `li` / `p`) | есть |
| 2 | Текст (`title-small`, `on-surface-variant`) | проп `title` или слот по умолчанию | есть; заголовок из слота нормализуется (`:where(h1…h6, p)`) |
| 3 | Inset — отступ до колонки текста строк | `--inset`, `padding-inline-start` | есть; выведен из токенов строки, не литерал |
| 4 | Липкая заливка | `--sticky`: `position: sticky`, фон `surface`, `z-index: 1` | иначе: z-index вне изолированного корня; фон не совпадает с фоном списка на `surface-container-*` |

## Оси дизайна

| Ось | Аналог в M3 | Кит сейчас | Цель | Ломает API |
|---|---|---|---|---|
| `tag` | — | `'div' \| 'li' \| 'p'`, по умолчанию `div` | по умолчанию — из контекста списка (вопрос 1) | нет, если дефолт выводится |
| `inset` | заголовок drawer выровнен по тексту пунктов | булево: выравнивание по тексту строк с leading | без изменений (единственное значение — «по колонке текста»; второго физически нет) | нет |
| `sticky` | — | булево, чистый CSS | без изменений | нет |
| Типографика и цвет | `title-small`, `on-surface-variant` (drawer) | то же | совпадает | — |

`inset` и `sticky` остаются булевыми: у каждого второе значение невозможно (`principles.md`, В1 —
флаг честен, когда второго значения нет).

## Оси состояний

Подпись пассивна: hover, фокус, pressed, disabled, выбор и раскрытие неприменимы. Единственное
«состояние» — прилипание при прокрутке, оно целиком CSS.

## Токены: расхождения

Карта — `assets/stylesheet/components/list/subheader/_index.scss`. В `index.vue` все пути легаси через
дефис и `material-map()` без нужды (`'min-height'`, `'sticky-container-color'`, `index.vue:43-60`) —
перевести на точку целиком.

| Часть | Аналог | Кит сейчас (`файл` / путь `g()`) | Действие |
|---|---|---|---|
| Inset | текст строки начинается после leading 16 + иконка 24 + gap | `$inset-offset` = `padding.leading` + `leading.icon.size` + `padding.between` из карты строки (`_index.scss:12`) = 56 | без изменений; при gap 12 (вопрос 2 плана списка) станет 52 автоматически |
| Z-index | — | `sticky.z: 1` (`_index.scss:26`), корень списка не изолирован (LY-06, TK-04) | литерал 1 законен только внутри `isolation: isolate` (`craft.md` §12): `MList` получает `isolation: isolate`, ключ шкалы `z()` не нужен |
| Заливка sticky | — | `sticky.container.color: surface` (`_index.scss:25`) | вопрос 2 |
| Граница прокрутки | — | нет | не добавлять: волосяная линия внутри контрола — запах форм-тулкита (`craft.md` §1); подпись отделяется заливкой |
| Отступы | drawer: 16 по строке | `padding.block: 8rem`, `padding.inline` = `padding.leading` строки | через `spacing()` |

Совпадает: `title-small`, `on-surface-variant`, min 48.

## Поведение и доступность

- Утверждено и не меняется: подпись — видимый структурный текст, не фокусируется, роли кнопки или
  элемента списка не получает сама; уровень заголовка не угадывается — настоящий заголовок
  потребитель кладёт в слот (`<MListSubheader><h3>Архив</h3></MListSubheader>`), его отступы и шрифт
  нормализуются.
- Пустые `title` и слот — dev-предупреждение `[m-list-subheader] renders without a label` (есть).
- **LY-09.** Строки под липкой подписью уходят под неё при Tab-навигации. Список с липкими
  подписями задаёт строкам `scroll-margin-block-start` = min-height подписи (токен подписи), чистым
  CSS: `.ui-list:has(> .ui-list-subheader--sticky) .ui-list-item`.
- **Тег внутри семантического списка** — вопрос 1. Если `MList` станет `ul` (вопрос 3 плана списка),
  дочерний `div` сделает разметку невалидной.
- SSR: тег, текст и модификаторы — из пропов синхронно; ни слушателей, ни наблюдателей, ни таймеров.
  Липкость — нативный CSS без JS-обхода.
- RTL: только логические свойства (есть).

**Не цели** (утверждено): сворачивание, выбор, клик, автоматическая группировка строк, расчёт
отступа под app bar, вывод уровня заголовка. `MListGroup` не заводится — см. «Не вводить» в плане
списка.

## План работ

1. **S — системные правки без смены API.** Точечные пути и отказ от `material-map()`;
   `isolation: isolate` у `MList`, литерал z-index остаётся локальным (LY-06, TK-04);
   `scroll-margin-block-start` у строк под липкой подписью (LY-09); отступы через `spacing()`.
   Файлы: `list/subheader/index.vue`, `list/subheader/_index.scss`, `list/index.vue`.
2. **S — заливка sticky.** По вопросу 2. Файлы: `list/subheader/_index.scss`, при варианте 2 —
   `list/index.vue`, `list/context.ts`.
3. **S — тег внутри списка.** По вопросу 1, после шага 3 плана списка (семантика `MList`). Файлы:
   `list/subheader/index.vue`, `list/subheader/props.ts`.

## Тесты

- **Фикстуры** — в общих `playground/fixtures/list/{matrix,stress}.vue`: подписи обычные, `inset`
  со строками с иконкой и аватаром, `sticky` в прокручиваемой панели на `surface` и на
  `surface-container`; слот с `<h3>`; RTL.
- **e2e** (`list.e2e.ts`): axe на списке с подписями (валидная структура `ul`); Tab по строкам под
  липкой подписью — фокусированная строка видна целиком; inset совпадает с началом текста строки
  (измерение `getBoundingClientRect`).
- **Unit** (`list/subheader/index.spec.ts`, есть 6 случаев): приоритет слота над `title`, теги,
  пассивность, модификаторы; добавить тег по контексту и отсутствие роли.

## Готово, когда

- Липкая подпись не перекрывает фокусированную строку и не спорит со страницей по z-index.
- Заливка липкой подписи совпадает с фоном списка (по ответу на вопрос 2).
- Внутри семантического списка разметка валидна, axe чистый.
- Пути `g()` точечные, литералов отступов нет; линтеры зелёные.

## Предложения по UX

Сверх паритета; в план работ — только после решения владельца.

1. **Слот `#trailing`** — счётчик или действие справа («Недавние · 12», «Очистить»). Пользователь
   видит объём секции и управляет ей там, где читает её название. Заказчик: история, уведомления,
   загрузки. Цена: S, слот и flex-раскладка; подпись остаётся пассивной, кнопка в слоте — обычная
   цель Tab. Рекомендация: да.
2. **Алфавитный указатель** для длинных списков (рельс A–Я у края, переход к подписи по букве).
   Пользователь не листает 500 контактов. Заказчик: не назван. Цена: L, новый компонент и
   клавиатура. Рекомендация: нет, пока нет заказчика.

## Открытые вопросы

**1. Тег подписи внутри семантического списка** (после вопроса 3 плана списка).
1. По умолчанию из контекста: внутри `ul` — `li role="presentation"` (не считается элементом
   списка, текст читается), вне списка — `div`. Явный `tag` побеждает. Цена: флаг присутствия списка
   в контексте `m3:list` (он же нужен `MDivider`).
2. Оставить `div` по умолчанию, документировать `tag="li"` внутри списка. Цена: забытый `tag`
   ломает разметку и axe.
3. Группы: подпись — заголовок вложенного `ul` с `aria-labelledby`. Цена: возвращает `MListGroup`,
   от которого отказались при утверждении.

Рекомендация: 1.

**2. Заливка липкой подписи.**
1. Оставить `surface` и документировать: на других поверхностях потребитель переопределяет класс.
   Цена: в меню, листе и drawer (`surface-container-*`) полоса светлее фона.
2. `MList` объявляет роль своего фона (проп `surface`, значения из ролей контейнеров), липкая
   подпись читает её через контекст и получает статический класс (`@each` по ролям, без
   рантайм-переменных). Цена: новый проп ради одного случая.
3. Липкая подпись без фона, с размытием (`backdrop-filter`). Цена: чужой для M3 приём, текст строки
   просвечивает.

Рекомендация: 1, пока нет заказчика с липкими подписями на тонированной поверхности; 2 — когда
появится.
