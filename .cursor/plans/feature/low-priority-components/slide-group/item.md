## Вердикт

`нет в ките`, в M3 нет. При рекомендованном варианте родителя (примитив без выбора) отдельный
компонент элемента **не нужен**:
- привязка прокрутки — CSS на прямых детях вьюпорта;
- показ активного — `reveal(el)` у владельца;
- фокус прокручивает элемент сам.

Если владелец выберет полосу со своим выбором, действует контракт прежнего плана (ниже).

## Контракт прежнего плана (при варианте 2)

- Стабильный `value`, `disabled` и регистрация элемента. Индекс в DOM моделью приложения не
  является.
- Своей модели и публичного импорта нет. Состояние — только через слот.
- Тикет выбора — канонический (`useSelectionGroup`), без второго реестра. Прокрутку и слушателей
  считает родитель.
- Ролей элемент не придумывает: внутри могут быть чипы, вкладки или другие контролы, семантика
  остаётся у них.
- Выключенные элементы пропускаются упорядоченной навигацией. Порядок обхода — из данных или
  DOM, а не из порядка регистрации: это правило из `decisions.md` для дропдауна и шаг 2 плана
  chip-group.

## Поведение и доступность

- Фокус внутри элемента прокручивает полосу средствами браузера. Запас прокрутки родителя не даёт
  элементу встать под затухание.
- Своих `aria-*` нет.

## Готово, когда

При варианте 1 — нечего делать, кроме CSS родителя. При варианте 2 — регистрация снимается при
размонтировании, порядок обхода совпадает с DOM, выключенные пропускаются.
