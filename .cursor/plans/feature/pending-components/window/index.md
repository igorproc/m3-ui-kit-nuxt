## Вердикт

`нет в ките`. В M3 такого компонента нет: это поведенческая основа (`principles.md`, «Систем две»).
У неё нет поверхности и хрома. Она выбирает панель по стабильному значению, решает, какие панели
смонтированы, и анимирует смену. Нецели прежнего плана: `tablist`, пошаговый сценарий, валидация,
хром карусели, модель-индекс, глобальное состояние.

**Пересечение с тем, что уже есть.**

- `MTabs` уже переключает панели сам: `createSingle({ mandatory: true })` в `useTabs`, панель
  `MTabPanel` пересоздаётся через `v-if`.
- План [tabs](../../components-should-update/navigation/tabs.md) предлагает два расширения,
  которые и есть работа окна:
  - «Предложения по UX», 1-е: сохранять состояние панелей (`displayDirective: 'if' | 'show'`) —
    это политика `mount` окна;
  - «Предложения по UX», 5-е: свайп по контенту, «работа пейджера» — это `touch` окна.
- Чтобы не завести две реализации одного механизма, решаются вопросы 1 и 2. Этот план предложения
  tabs не дублирует, а даёт им общий фундамент.

**Чем окно не является.** Окно — не `MCarousel`: карусель — прокручиваемый ряд на нативном
`scroll-snap` (план
[carousel](../../low-priority-components/carousel/index.md)), а окно показывает одну панель за раз.

## Рендеры

**Не применимо.** Своей отрисовки у окна нет: ни поверхности, ни заголовков, ни стрелок. Видимый
результат — только движение при смене панели, а статичный WebP его не передаёт. Схема перехода
shared axis показана в кадре 6 концепта степпера
(`../../renders/stepper/concept.webp`); сами панели рисует потребитель (степпер, вкладки).

## Оси состояний

| Ось | Значения |
|---|---|
| Панель | активна · посещена и сохранена (`hidden` + `inert`) · не смонтирована |

| Движение | обычное · reduced motion |

## Поведение и доступность

**Слои.** Выбор — `createSingle` (тикеты, `mandatory`); контекст окна отдаёт активное значение,
порядок, направление, `mount`, `id` и `prev` / `next` / `select`. Элементы регистрируются один раз и
снимаются в `onScopeDispose`. Данные рисуются через `#item`; слот по умолчанию получает состояние
навигации (прежнее).

**Монтирование** (прежнее):

- `active` монтирует только выбранную панель;
- `visited` монтирует при первом выборе и сохраняет;
- `eager` монтирует все сразу.

Неактивные сохранённые панели `hidden` и `inert`. Удалённая панель теряет локальное состояние по
явной политике.

**Свайп** (прежнее). `useDrag`. `preventDefault` только после того, как подтверждена ось жеста, —
вертикальная прокрутка страницы не ломается. Граница с отключёнными элементами не пружинит в выбор.
RTL разворачивает горизонталь. Слушателей нет, пока `touch=false`.

**Доступность** (прежнее). По умолчанию окно семантически нейтрально; роли панелей и `id` задают
потребители (`tabpanel` у вкладок, панель шага у степпера). Неактивная сохранённая панель не
попадает в обход Tab. Reduced motion меняет только анимацию.

**SSR и жизненный цикл** (прежнее). Выбор и ветви монтирования синхронны; слушатели — через
композаблы со снятием; `visited` начинается с панели, активной на сервере, гидрация её не заменяет.

## API

Прежний одобренный контракт:

```ts
type MWindowDirection = 'horizontal' | 'vertical'
type MWindowTransition = 'slide' | 'fade' | 'none'
type MWindowMount = 'active' | 'visited' | 'eager'

interface MWindowProps<TItem, TValue> {
  items: readonly TItem[]
  itemValue: keyof TItem | ((item: TItem, index: number) => TValue)
  itemDisabled?: keyof TItem | ((item: TItem, index: number) => boolean)
  itemKey?: keyof TItem | ((item: TItem, index: number) => PropertyKey)
  direction?: MWindowDirection
  transition?: MWindowTransition
  touch?: boolean
  mandatory?: boolean | 'force'
  mount?: MWindowMount
}

const model = defineModel<TValue>()
```

Дефолты: `horizontal`, `slide`, `touch: false`, `mandatory: 'force'`, `mount: 'visited'`.

Слоты (прежнее):

- `#item` получает исходный элемент, индекс, значение, `active`, `visited`;
- слот по умолчанию получает `active`, `hasPrev`, `hasNext`, `prev`, `next`, `select`;
- `#empty` — когда нет включённых элементов.

Внутренние `id` тикетов в слоты не попадают. Словарь «направления» в ките уже тройной
(`orientation` у divider и slider, `direction` у chip-group, `layout` у toolbar и time-picker);
`direction` оставлен по прежнему решению, расчистка словаря — вне этого плана.

## План работ (после продвижения)

1. **M — контекст и регистрация.** `createSingle`, режимы `mandatory`, `prev` / `next` с пропуском
   отключённых, динамическое удаление. Файлы `components/ui/window/{index.vue,props.ts}`,
   `composables/window/useWindow.ts`.
2. **S — политика монтирования** чистой функцией, общей с вкладками (по вопросу 2). Приватный
   [WindowItem](item.md).
3. **M — переходы.** Shared axis, fade through, `none` на токенах; направление по порядку; RTL;
   reduced motion (по вопросу 3).
4. **M — свайп.** `useDrag`, подтверждение оси, границы, RTL.
5. **S — пустое состояние, dev-предупреждения** (дубликаты ключей), документация, записи в
   `decisions.md`.

Зависимости внешние — нет. Ждут этот план: [MStepper](../stepper/index.md) и, по вопросу 2,
[tabs](../../components-should-update/navigation/tabs.md).

## Тесты

- **Unit** (прежнее): типизированные значения, режимы `mandatory`, динамические элементы, все
  политики `mount`, `prev` / `next` с пропуском отключённых, снятие регистрации, ось жеста и RTL.
- **Фикстуры** `playground/fixtures/window/`: `matrix.vue` — `direction` × `transition` × `mount`;
  `stress.vue` — 50 панелей, вставка и удаление активной, панели разной высоты, RTL.
- **e2e**: `inert`-панели вне обхода Tab, reduced motion, свайп на тач-эмуляции не ломает
  вертикальную прокрутку, SSR и гидрация без замены активной панели; `lint` и `lint:style`.

## Готово, когда

- [ ] Панели переключаются по стабильному значению с управляемым монтированием и движением,
      независимо от семантики вкладок и степпера.
- [ ] Неактивные сохранённые панели не фокусируются и не читаются.
- [ ] Переходы — на токенах движения, reduced motion укорачивает их.
- [ ] Вопросы 1–2 закрыты так, что у кита одна реализация политики монтирования панелей.

## Открытые вопросы

**1. Одно слово для политики монтирования панелей.**
В ките уже есть `displayDirective: 'if' | 'show'` у модальных слоёв (`mModalLayerProps`), и план
tabs предлагает то же слово для панелей. Прежний план окна одобрил
`mount: 'active' | 'visited' | 'eager'`.
1. `mount` у окна, и предложение tabs берёт `mount` вместо `displayDirective`.
   `displayDirective` остаётся у оверлеев: там одна поверхность и два состояния. В `axes.md`
   записать: `mount` — когда монтируется содержимое панелей в переключателях. Цена: новое слово
   в словаре.
2. `displayDirective: 'if' | 'show'` везде, включая окно; `eager` убрать. Цена: противоречит
   прежнему решению, теряется `eager` — а его ждёт проверка всех шагов формы разом.
3. `displayDirective: 'if' | 'show' | 'eager'`. Цена: `eager` — не директива Vue, и оверлей
   должен будет отвергать третье значение.

Рекомендация: 1.

**2. Как вкладки получают политику монтирования и свайп.**
1. Чистая политика монтирования выносится в общую функцию (`usePanelMount(active, policy)`). Её
   используют `WindowItem` и `MTabPanel`; составной API вкладок не меняется. Цена: один маленький
   общий модуль.
2. `MTabs` с `items` рисует панели через `MWindow`, составной `MTabPanel` остаётся на `v-if`.
   Цена: два пути внутри одного компонента.
3. Вкладки делают своё, как в предложении плана tabs. Цена: две реализации одного механизма.

Рекомендация: 1. Свайп для вкладок (через окно) — только с заказчиком.

**3. Что значит `transition="slide"`.**
1. Shared axis M3: смещение 30 плюс затухание, `long-1`, `emphasized`. Это паттерн, который M3
   называет для пошаговых сценариев и соседних экранов одного уровня. Цена: «перелистывания» на всю ширину нет.
2. Сдвиг на всю ширину вьюпорта, как в Vuetify. Цена: это вид карусели (а у неё свой план, на
   нативной прокрутке), и на широком экране движение длинное и тяжёлое.

Рекомендация: 1.
