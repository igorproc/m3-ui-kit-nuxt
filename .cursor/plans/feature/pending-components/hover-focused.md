## Вердикт

`нет в ките` (и нет в M3 как компонента). Это поведенческий примитив без вида: он сообщает
состояние и никогда не выбирает цвет, непрозрачность, обводку, тень или движение потребителя.

Правило прежнего плана остаётся главным: **если задача решается чистым `:hover` /
`:focus-visible` и токенами компонента, JavaScript не используется.** Визуал в ките уже
системный (color-and-state.md):
- слой состояния — `state-opacity()` (8 / 10 / 12 %), `:hover` только внутри `can-hover`
  (`@media (hover: hover)`), чтобы тап на таче не «залипал»;
- фокус контролов — общий `@include focus-ring` (3, `secondary`, смещение 2);
- фокус полей — смена цвета, без кольца, утолщения и анимации.

Кандидаты ниже нужны только для реактивного состояния шаблона и бизнес-логики: показать
превью, запустить предзагрузку, поменять содержимое.

## Рендеры

Не применимо: примитивы не создают разметки и не имеют стилей. Визуальные состояния hover и
focus живут в картах токенов компонентов и видны на их рендерах (например,
[menu](../renders/menu/concept.webp), [chip](../renders/chip/concept.webp)).

## Анатомия

Слои по behavior.md: логика → control-композабл → презентация потребителя.

| # | Слой | Предлагаемая реализация |
|---|---|---|
| 1 | Помощник наведения | приватный `useHoverState`: события указателя, задержки, фильтр тача, очистка таймеров через `useTimer` |
| 2 | Помощник фокуса | приватный `useFocusState`: прямой фокус, focus-within, `:focus-visible` — или рецепт на VueUse (вопрос 2) |
| 3 | Renderless-компонент | `MHover` (и `MFocused` по вопросу 2): только слот, без DOM |
| 4 | Цель | элемент потребителя, получает бэг обработчиков через `v-bind` |

## Оси дизайна

Визуальных осей нет. Поведенческие:

| Ось | Кандидат | Комментарий |
|---|---|---|
| `openDelay`, `closeDelay` | мс, по умолчанию 0 | вопрос 3; задержка никогда не касается фокуса |
| `within` | у фокуса | прямой фокус или фокус внутри |
| `disabled` | флаг | сбрасывает состояние и отменяет таймеры |

## Оси состояний

Что примитив сообщает: `isHovering`; `isFocused`, `isFocusWithin`, `isFocusVisible`. Чего он
не делает: не рисует, не ставит `tabindex`, не создаёт глобального pub/sub.

## Токены

Не применимо: SCSS нет. Ограничения для потребителя, который рисует по этому состоянию, — те же,
что у любого компонента кита: слой через `state-opacity()`, `:hover` в `can-hover`, кольцо
`focus-ring` у контролов, смена цвета у полей, никаких анимаций фокуса.

## Поведение и доступность

**Наведение** (прежняя политика, без изменений):
- события указателя, а не мыши;
- тач не создаёт залипшего наведения: `pointerType === 'touch'` игнорируется — это JS-аналог
  `can-hover`;
- `disabled` сбрасывает состояние и отменяет таймеры;
- повторный вход отменяет ожидающий уход; уход отменяет ожидающий вход;
- размонтирование обязательно снимает таймеры и слушатели;
- никакого глобального pub/sub: наведение локально для цели;
- группа «активатор + плавающее содержимое» в первую версию не входит: это может принадлежать
  слою взаимодействия оверлея и тултипа.

**Фокус** (прежняя политика):
- фокус — отдельная способность, а не поле внутри примитива наведения;
- различать прямой фокус, focus-within и семантику `:focus-visible` браузера
  (`element.matches(':focus-visible')` в обработчике);
- фокус для клавиатуры не проходит через задержки наведения;
- примитив не добавляет `tabindex`: фокусируемость определяет настоящий интерактивный
  потребитель;
- для чистого оформления всегда предпочитать CSS `:focus-visible` / `:focus-within`.

**Почему свой помощник, а не VueUse `useElementHover`.** Он слушает `mouseenter` /
`mouseleave`: тап на таче порождает совместимый `mouseenter`, и состояние залипает — ровно то,
что запрещает `can-hover`. Таймер задержки при размонтировании не снимается. `useFocus`
(`focusVisible`) и `useFocusWithin` из VueUse политике фокуса соответствуют и могут быть
переиспользованы (вопрос 2).

**Один контроллер на паттерн** (behavior.md): в ките уже два обработчика наведения — `MTooltip`
(`mouseenter` + `useTimer`, грейс 100 мс по WCAG 1.4.13) и `MLazy` (`pointerenter`). Новый
помощник обязан стать их общим основанием (шаг 4), а не третьей копией.

**Контракт escape hatch:** бэг содержит только обработчики (`onPointerenter`,
`onPointerleave`, `onFocusin`, `onFocusout`) — ни классов, ни `data-*`. По словарю behavior.md
бэг зовётся `targetAttrs` (в прежнем плане — `props`).

**SSR:** серверный рендер отдаёт слот с `false` во всех состояниях; слушатели появляются только
на клиенте.

## API

Сохранены четыре варианта прежнего плана.

**A. Renderless `MHover` и `MFocused`.** Состояние сразу в шаблоне, не нужен ref, нет DOM,
цель выбирает разработчик. Минусы: renderless непривычен части пользователей, слот добавляет
вложенность, обязательный `v-bind` надо документировать, несколько целей — ручное
распределение.

```vue
<MHover v-slot="{ isHovering, targetAttrs }" :open-delay="200">
  <MCard v-bind="targetAttrs">
    <CardPreview v-if="isHovering" />
  </MCard>
</MHover>
```

```ts
interface MHoverProps { disabled?: boolean, openDelay?: number, closeDelay?: number }
interface MFocusedProps { disabled?: boolean, within?: boolean }

interface MHoverSlot {
  isHovering: boolean
  targetAttrs: { onPointerenter: (event: PointerEvent) => void, onPointerleave: (event: PointerEvent) => void }
}

interface MFocusedSlot {
  isFocused: boolean
  isFocusWithin: boolean
  isFocusVisible: boolean
  targetAttrs: { onFocusin: (event: FocusEvent) => void, onFocusout: (event: FocusEvent) => void }
}
```

**B. Директивы `v-hover` и `v-focused`** (колбэк или объект с `enter`, `leave`, задержками,
`within`). Привязаны к DOM цели, нет вложенности, хороши для побочных эффектов (аналитика,
предзагрузка). Минусы: не возвращают реактивное состояние в шаблон, присваивание в шаблоне
читается хуже, снаружи всё равно нужен ref, объектный биндинг сложно типизировать, для
рендеринга по состоянию почти не лучше явных `@pointerenter` / `@pointerleave`.

**C. Композаблы `useHover` и `useFocusWithin`.** Гибкость Composition API, реактивная цель,
переиспользование внутри кита. Минусы: нужен template ref, больше кода для простой задачи,
соблазн применить JS там, где хватает CSS.

**D. Публичные renderless-компоненты поверх приватных композаблов** — гибрид A и C: шаблонный
опыт снаружи, тестируемая логика внутри, композабл можно экспортировать позже при доказанном
спросе. Минусы: две внутренние сущности ради небольшой функции; приватный композабл не должен
стать параллельным незадокументированным API. Прежний план считал D самым сбалансированным.

## План работ (после продвижения)

0. **Ворота:** ответы на вопросы 1–4; назван заказчик.
1. **S — `useHoverState`** (`composables/hover/useHoverState.ts`): события указателя, фильтр
   тача, задержки через `useTimer`, `disabled`, бэг `targetAttrs`. Спека на анонимной разметке:
   в бэге нет `class` и `data-*`.
2. **S — фокус** по вопросу 2: приватный `useFocusState` или рецепт на `useFocus` /
   `useFocusWithin` VueUse.
3. **S — `MHover`** (`components/ui/hover/index.vue`) и `MFocused` по вопросу 2: только слот.
4. **M — общее основание**: `MTooltip` и `MLazy` становятся потребителями `useHoverState`
   (тултип сохраняет грейс 100 мс через `closeDelay`). Согласовать с планом
   [tooltip](../components-should-update/overlays/tooltip.md) и
   [lazy](../components-should-update/foundation/lazy.md).
5. **S — документация**: «сначала CSS», таблица «когда нужен JS», обязательный `v-bind`.

## Тесты

- Unit с фальшивыми таймерами: задержки входа и ухода; вход отменяет ожидающий уход и наоборот;
  `pointerType: 'touch'` не меняет состояние; `disabled` сбрасывает и отменяет таймеры;
  размонтирование снимает таймеры; фокус не ждёт задержки наведения; `isFocusVisible` только при
  клавиатурном фокусе.
- Escape hatch: бэги на анонимной разметке без `class` и `data-*`.
- SSR: слот рендерится со всеми состояниями `false`, без расхождения гидрации.
- e2e: эмуляция тача — наведение не залипает; клавиатура показывает содержимое без задержки;
  тултип после перевода проходит свои прежние e2e.

## Готово, когда

- [ ] В ките один обработчик наведения: тултип и `MLazy` на общем помощнике.
- [ ] Тап на таче не оставляет состояние наведения.
- [ ] Ни таймеров, ни слушателей после размонтирования.
- [ ] Примитивы не выводят DOM, классов и `data-*`.
- [ ] Документация начинается с правила «сначала CSS».

## Предложения по UX

Сверх базового объёма; решает владелец. Без новых зависимостей. «Прогрев» группы тултипов уже
предложен в плане [tooltip](../components-should-update/overlays/tooltip.md) и здесь не
повторяется.

| Предложение | Что получает пользователь | Заказчик | Цена | Рекомендация |
|---|---|---|---|---|
| Композиция «показать при наведении или фокусе» (`MReveal`: `isRevealed = isHovering \|\| isFocusWithin`) | Действия карточки, появляющиеся при наведении, доступны и с клавиатуры (WCAG 2.1.1) | карточки, строки таблиц, списки с действиями | S · поверх двух помощников, фокус остаётся отдельной способностью | да, это самый частый случай |
| Долгое нажатие как тач-аналог наведения (`touch: 'long-press'`) | Содержимое «по наведению» доступно на телефоне | превью, подсказки | M · согласовать с вопросом 3 плана tooltip | обсудить |
| Колбэк намерения `onIntent` (наведение дольше задержки или фокус) для предзагрузки | Переход или виджет открывается почти мгновенно | навигация, тяжёлые виджеты | S · пересекается с предложением предзагрузки в плане [lazy](../components-should-update/foundation/lazy.md) | да, вместе с `MLazy` |

## Открытые вопросы

**1. Основной публичный опыт.** (прежний пункт 1)
1. Renderless-компонент (A / D). Состояние в шаблоне без ref, но вложенность слота.
2. Директива (B). Без вложенности, но реактивного состояния в шаблоне нет.
3. Только композаблы (C). Гибко, но ref и boilerplate, и легко применить JS вместо CSS.

Рекомендация: 1 в форме D — публичный `MHover` поверх приватного помощника; директивы не
добавлять, пока не появится сценарий «только колбэк».

**2. Нужен ли публичный `MFocused`?** (прежний пункт 2)
1. Да, парный к `MHover`. Симметрия API, но ещё одна публичная сущность.
2. Нет: оформление — CSS `:focus-visible` / `:focus-within`, логика — рецепт на `useFocus`
   (`focusVisible`) и `useFocusWithin` VueUse, уже в зависимостях. Ноль нового API.
3. Приватный помощник без публичной обёртки, только для кита. Внутреннее переиспользование без
   обещаний наружу.

Рекомендация: 2 сейчас, 1 — когда появится заказчик шаблонного состояния фокуса.

**3. Задержки в первой версии `MHover`.** (прежний пункт 3)
1. Да: `openDelay` и `closeDelay`. Есть заказчик — тултип с грейсом 100 мс и намерением показа.
2. Нет: первая версия без задержек. Меньше кода, но тултип остаётся на своей реализации, и
   обработчиков наведения в ките будет три.

Рекомендация: 1.

**4. Экспортировать композаблы публично?** (прежний пункт 4)
1. Нет, это деталь реализации; экспорт — при доказанном спросе.
2. Да, `useHoverState` в публичном API сразу. Гибкость, но ещё одна поверхность для поддержки.

Рекомендация: 1.
