# ROADMAP.md

## Фаза 1 / Q3: Архитектура, оптимизация и стабилизация кита
*Ориентировочные затраты: ~9.5 – 11.5 недель*

- **причесывание всех компонентов, рефакторинг декларации значений в виде scss мапы**
  *(~2 недели)*: Полный уход от старых подходов к переменным, внедрение многомерных SCSS мап. Исключение deprecated-синтаксиса Sass, строгая изоляция токенов.
- **добавление адаптива**
  *(~1.5 недели)*: Внедрение резиновой методологии (1rem = 1px через viewport units) и полная интеграция M3 Window Size Classes на уровне базовых layout-компонентов.
- **решение проблем с auto-layout, регистрация компонентов, только внутри anchor компонентов.**
  *(~1 неделя)*: Настройка строгой иерархии и прямых импортов внутри Nuxt layer, чтобы сохранить возможность безболезненной смены префиксов в будущем.
- **добавление скелетонов на все ui-components**
  *(~1.5 недели)*: Интеграция состояний загрузки на базовом атомарном уровне для всех элементов кита.
- **добавление возможности изменения гидрации и подгрузки файлов. 3 режима:**
  *(~2 - 3 недели)*:
  1. *idle* (стандратная, подгрузка всех компонентов на странице)
  2. *on-view* (только когда он появился на экране, либо если компонент имеет client-side зависимости)
  3. *on-interactive* (только когда с ним пытаются взаимодействовать)
- **сбор информации по 0.vuetify, взаимстование некоторых идей**
  *(~0.5 недели)*: Анализ подходов к организации внутренних composables и a11y.
- **v-scroll как composable, рефакторинг и усиление базовой MTable**
  *(~1 - 2 недели)*: Разработка переиспользуемой виртуализации списков для плавной работы таблиц с большими объемами данных.

## Фаза 2 / Q4: Документация и подготовка к релизу
*Ориентировочные затраты: ~3 – 4 недели*

- **навписание wiireframes в доке**
  *(~1 неделя)*: Отрисовка и фиксация архитектурных слоев, контрактов и работы брейкпоинтов.
- **написание полу-аввтоген доки по киту, реализ в альфе (статика на s3, текст через сервер накста, токены через extract из scss мапы, use cases)**
  *(~2 - 3 недели)*: Создание пайплайна генерации документации, которая всегда актуальна коду, интеграция парсеров для выгрузки токенов напрямую из SCSS-мап.

## Фаза 3 / Q1: Мультиплатформенная архитектура (Compiler-First)
*Ориентировочные затраты: ~4 – 6 недель*

- **миграция на монорепозиторий (pnpm workspaces) и разделение на 3 пакета**
  *(~1 неделя)*: Выделение `@pt-ui/core` (ядро, токены), `@pt-ui/web` (Nuxt 3) и будущего `@pt-ui/xr`.
- **написание скриптов-экстракторов токенов в @pt-ui/core**
  *(~1 - 2 недели)*: Разработка Node.js компилятора (или внедрение Style Dictionary) для автоматического парсинга Sass мап и конвертации их в платформо-агностичный JSON (с резолвом CSS-переменных в HEX/RGB для WebGL).
- **внедрение паттерна "Thin Wrapper" (тонкие обертки)**
  *(~2 - 3 недели)*: Выделение чистой бизнес-логики компонентов (стейт, события) в независимые TS-файлы внутри `core`. Перевод компонентов в `@pt-ui/web` на использование этой логики через биндинг к плоскому DOM.

## Фаза 4 / Q2: Выход в Spatial Computing / XR
*Ориентировочные затраты: ~6 – 8+ недель (R&D)*

- **начало создания XR/3d версии кита, которая будет абстрагирована от движка и иметь адаптеры под Babylon.js/Three.js**
  *(~6 - 8 недель)*: Подключение `@pt-ui/xr` к ядру. Делегирование визуального рендеринга 3D-мешам и материалам, которые потребляют сгенерированные JSON-токены и "тонкую" логику из `@pt-ui/core`. Создание первого рендера-адаптера с учетом пространственной эргономики.
